# RNDLOG 고객 자료 업로드·파일 트리 통합 계획

- 작성 기준일: 2026-09-06
- 상태: 구현·검증·운영 배포 완료
- 대상: 연구소 관리의 고객사 상세 화면
- 목표: 관리자가 고객 자료를 중앙 정본에 안전하게 올리고, 자료와 산출물의 실제 폴더 구조를 한 화면에서 확인한다.

## 1. 사용자 결과

1. 고객사 상세의 `자료·산출물` 영역에서 `자료 올리기`를 누른다.
2. ZIP 파일 하나 또는 ZIP이 아닌 파일 여러 개를 선택한다.
3. 업로드가 끝나면 저장한 파일 수와 위치를 확인한다.
4. 같은 영역의 폴더 트리에서 자료와 산출물을 접고 펼쳐 확인한다.

ZIP과 개별 파일은 한 번의 선택에 섞지 않는다. ZIP은 한 개만 받고, 개별 파일은 여러 개를 한 번에 받는다.

## 2. 화면 배치와 동작

현재 고객사 상세의 `지금 할 일` 바로 아래에 있는 `자료·산출물 현황`을 확장한다.

- 상단: 기존 영역별 파일 수와 `자료 올리기` 행동
- 업로드 펼침 영역: 파일 선택, 저장 규칙, 제한, 실행 버튼, 진행·성공·실패 상태
- 하단: 고객사 작업공간의 접이식 폴더 트리
- 그 아래: 기존 `진행 업무`, `연구조직`, `주담당 변경 이력`

업로드 양식은 평소에는 접어 화면 밀도를 유지한다. 버튼을 누르면 같은 자리에서 펼쳐진다. 제출 중에는 버튼을 비활성화하고 처리 중임을 표시한다. 성공하면 새 업로드 폴더가 열린 트리를 보여주고, 실패하면 원인과 재시도 방법을 업로드 양식 안에 표시한다.

폴더 트리는 실제 경로를 다음 구조로 보여준다.

```text
<고객사 작업공간>
├── sources
│   ├── original       고객 원본
│   └── intake         수신 기록
├── research           조사 자료
└── deliverables
    ├── drafts         작업본
    └── final          최종 산출물
```

루트는 보이고 하위 폴더는 기본으로 접는다. 폴더마다 포함 파일 수를 표시한다. 파일에는 이름, 크기, 검토 상태를 표시하되 아직 지원하지 않는 다운로드 버튼은 만들지 않는다.

## 3. 저장 계약

파일 정본은 운영 웹서버가 아니라 메인서버의 기존 경로에 둔다.

```text
/home/chaconne/projects/rndlog/companies/<workspace_key>/
```

개별 파일 업로드:

```text
sources/original/업로드_<시각>_<무작위 식별자>/<원래 파일명>
```

ZIP 업로드:

```text
sources/original/업로드_<시각>_<무작위 식별자>/
├── <받은 ZIP 원본>
└── 압축해제/
    └── <ZIP 내부 폴더와 파일>
```

- 기존 파일과 폴더는 덮어쓰지 않는다.
- 받은 ZIP 자체를 보존하고 내용물을 별도 하위 폴더에 푼다.
- 개별 파일과 ZIP 내부 경로는 원래 이름과 폴더 구조를 유지한다.
- 새 파일 권한은 기존 고객 자료와 같은 소유자·그룹·쓰기 규칙을 사용한다.
- 운영 DB의 `FileAsset`에는 상대 경로, 원래 이름, 크기, SHA-256, MIME 형식, 업로더, 수신 시각, 미확인 상태와 원본 불변 표시를 기록한다.
- 파일 저장과 메타데이터 기록 중 하나가 실패하면 이번 업로드 묶음만 복구하고 기존 자료는 건드리지 않는다.

## 4. 중앙 저장 연결과 보안

운영 앱 컨테이너가 메인서버의 고객사 저장소에 직접 전체 SSH 권한을 갖지 않도록 제한한다.

1. 메인서버에 고객사 작업공간 업로드만 수행하는 Python 표준 라이브러리 게이트웨이를 둔다.
2. 운영 서버에는 이 게이트웨이만 실행할 수 있는 전용 SSH 키를 둔다.
3. 메인서버 `authorized_keys`에는 강제 명령과 `restrict`를 적용한다.
4. 운영 앱은 고정된 호스트 키를 검증하고 셸 문자열이 아닌 인자 목록으로 OpenSSH를 실행한다.
5. 앱의 기존 읽기 전용 자격증명 볼륨에 전용 개인 키와 `known_hosts`만 추가한다.
6. 운영 웹서버에는 Django의 요청 처리 중 필요한 임시 파일만 존재하며 성공·실패 뒤 남기지 않는다.

기존 50MB Nginx 요청 제한을 유지한다. 앱과 중앙 게이트웨이도 같은 업로드 총량을 검사한다. ZIP은 최대 2,000개 파일, 압축 해제 총량 500MB, 경로 깊이 10단계로 제한한다.

다음 ZIP은 전체 업로드를 저장 전에 거부한다.

- 절대 경로, `..`, 드라이브 문자 또는 제어문자가 있는 경로
- 심볼릭 링크와 일반 파일·폴더가 아닌 항목
- 암호화 파일
- 같은 경로가 두 번 들어 있는 ZIP
- 파일 수·압축 해제 크기·경로 깊이 제한 초과

## 5. 구현 범위

운영 저장소:

- `research_management/services.py`: 업로드 검증, SSH 전송, 메타데이터 기록, 폴더 트리 구성
- `research_management/views.py`, `urls.py`: 관리자 전용 업로드 처리
- `research_management/templates/research_management/workspace.html`: 기존 자료 영역 배치 변경
- 자료 영역 partial과 재귀 트리 partial: HTMX 응답과 중첩 폴더 표시
- `main/settings/base.py`, `.env.example`: 저장 연결 경로와 제한 설정
- `Dockerfile`: Python SSH 라이브러리를 새로 추가하지 않고 OpenSSH 클라이언트만 설치
- `research_management/test_views.py`와 관련 테스트: 권한, ZIP·다중 파일, 오류·복구, 트리 회귀

메인서버 중앙 조정실:

- `resources/tools/workspace_storage_gateway.py`: 제한된 업로드·압축 해제·복구 명령
- 게이트웨이 단위 테스트
- 전용 SSH 공개키의 강제 명령 등록

운영 런타임:

- 기존 자격증명 폴더에 전용 개인 키와 고정 호스트 키 추가
- 운영 환경 파일에 비밀값이 아닌 저장 연결 설정 이름 추가
- 기존 고객 파일, 운영 DB 데이터, 문자·예약·외부 연동은 변경하지 않음

## 6. 최종 실행 경로

```text
관리자 고객사 상세
→ ZIP 하나 또는 여러 개별 파일 선택
→ Django가 형식·개수·총량 검사
→ 전용 SSH 강제 명령으로 중앙 게이트웨이에 스트리밍
→ 중앙 게이트웨이가 경로·압축 안전성 검사
→ 고객사 sources/original의 새 업로드 묶음에 원자적으로 저장
→ 저장 결과 manifest 반환
→ FileAsset 메타데이터 일괄 기록
→ 같은 자료 영역을 성공 상태와 갱신된 폴더 트리로 교체
```

별도 수동 복사, 사후 압축 해제, 운영 웹서버 보관, 임시 동기화 경로는 만들지 않는다.

## 7. 검증과 배포

수정 전 기준선:

- `research_management` 테스트 19개 통과
- Django 검사 통과
- 운영 앱·Nginx 각각 `1/1`
- 비로그인 `/rndlog/admin/` 접근은 로그인으로 `302`

수정 후 검증:

1. 기존 19개 테스트와 새 업로드·트리 테스트를 함께 실행한다.
2. 중앙 게이트웨이를 임시 작업공간에서 실행해 개별 파일과 정상 ZIP을 확인한다.
3. 경로 탈출, 심볼릭 링크, 과다 압축, 중복 이름과 제한 초과가 저장 없이 실패하는지 확인한다.
4. 운영 컨테이너에서 전용 키가 게이트웨이 명령만 실행하고 일반 셸은 열지 못하는지 확인한다.
5. Tailwind 빌드, `collectstatic`, Django 검사와 관련 테스트를 실행한다.
6. 격리된 테스트 DB와 임시 중앙 작업공간으로 실제 브라우저에서 390px, 480px, 1024px 이상을 확인한다.
7. 클릭 전·제출 중·성공·실패·빈 트리·깊은 트리와 키보드 포커스를 확인한다.
8. 코드 리뷰에서 확인된 결함을 수정하고 같은 범위를 다시 검증한다.
9. 운영 저장소가 승인 범위의 변경만 가진 상태에서 커밋·배포한다.
10. 배포 후 서비스 `1/1`, 운영 URL, 관리자 전용 권한과 중앙 연결 상태를 다시 확인한다.

운영 고객사에 시험 파일을 올리지는 않는다. 파일 쓰기 검증은 격리된 임시 작업공간에서만 한다.

## 8. 일괄 승인 범위

이 계획 승인에는 다음이 포함된다.

- 운영 Django 코드·템플릿·테스트·Dockerfile·설정 예시 변경
- 메인서버 중앙 저장 게이트웨이와 테스트 추가
- 기능 전용 제한 SSH 키·고정 호스트 키·운영 환경 설정
- 검증된 변경의 코드 리뷰·문서화·Git 커밋·운영 배포
- 배포 후 읽기 전용 운영 확인

다음은 승인에 포함되지 않는다.

- 기존 고객 파일의 이동·삭제·이름 변경
- 파일 다운로드, 보고서 생성, 승인·전달·발송 기능
- 운영 고객사에 시험 파일 업로드
- 관리자 외 역할의 업로드 권한
- 현재 50MB 요청 한도 확대
