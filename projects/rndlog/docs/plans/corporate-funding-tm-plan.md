## 1. 목적과 배경

- CRETOP 추출 완료 데이터(`ceo_loan.cretop`, 회사 193 · 원문 스냅샷 213 사업자번호 · 재무 구조화 189)를 기반으로 TM을 진행한다.
- TM 표준 흐름: 재무 기반 "대출 가능 금액 X~Y억" → 관심 확인 → 전문가 통화 동의 → 방문 일정.
- 목적: 컨택 유지와 다음 액션 연결. 최고 성과 = 방문상담 약속.
- MMS(업체 보고서) 발송이 선행 접점이나, **발송·이미지 생성은 추후 단계**.

## 2. 확정 결정 (2026-07-16 그릴)

| # | 결정 | 내용 |
|---|---|---|
| 1 | 저장 DB | TM 기록은 **ceo_loan DB**, TM 전용 네임스페이스. cretop 스키마는 읽기 전용 (ADR 0001) |
| 2 | 기준 엔티티 | **대표이사 중심** — 통화 상대는 사람. 이름+전화번호(정규화 유니크), `public.leads`에서 승격 생성, 회사는 대표이사에 1:N (ADR 0002) |

| 4 | 금액 산정 | 참조자료 확정 산식(스크립트): 제조 1/2 · 도소매 1/6 · 기타 1/4, −1억 상한, −1억 하한, 최소 1억, 억원 내림. LLM은 검토의견·최종결과 문구만 |
| 5 | 발송물 | MMS 업체 보고서(이미지+문구, 자본총계 추가). 발송·이미지 모두 추후 |
| 6 | 오디오 매칭 | 갤럭시 기본 통화녹음(파일명에 상대 번호 포함) → 전화번호 정규화 자동 매칭, 미일치만 수동 지정 |
| 7 | 리스트 기준 | 추출 완료 대표이사 **전체 + 자격(eligibility) 배지**, 기본 필터 = 자격 통과 |
| 8 | 처리·보관 | 백그라운드 스레드+DB 큐(exdigm 패턴) · 원본 오디오 10GB 상한 FIFO 삭제(전사·요약 영구) |
| 9 | TM 운영 (2026-07-16 갱신 — 결정 8의 "담당자 없이 시작"을 대체) | 담당자(Agent)·할당(Assignment) 도입: eligible만 **전자동 배분**(sync 직후, 미완료 잔량 최소 담당자), 미정·미달은 풀 대기 · 담당자 = rndnote 스태프 계정 · **담당자는 자기 할당만 보고 관리자(superuser)는 전체** · 대표이사당 할당 1건(OneToOne)으로 중복 방지 · 통화기록 생성 시 대기→진행중, 반응도 1(거부)은 자동 제외 · 담당자 비활성화 시 미완료 재배분 |

## 3. 데이터

- **원천(읽기 전용)**: `cretop.companies`(193) + 구조화 테이블(재무·신용·프로필·인증·IP). `public.leads`(14,084)의 `person_name`/`phone_digits`가 대표이사 원천. 사업자번호 조인은 digits 정규화 필수(193개사↔196리드 확인).
- **TM 네임스페이스(신규, ceo_loan)**: 대표이사 · 통화기록(유형: 수동/오디오, 통화 결과, 반응도, 넥스트액션+예정일, 메모/전사/요약) · 오디오 파일 메타(용량·큐 상태·매칭 상태).
- **엑셀**: 경영진단.xlsx 33셀 계약(참조자료 §9~12)이 `cretop_report_pipeline.py export-report`에 통합 예정. 웹 정보 패널은 같은 원천 테이블을 직접 읽고, 엑셀은 다운로드로 제공.
- **연결**: rndnote Django에 ceo_loan을 두 번째 DATABASES로 등록, TM 모델만 마이그레이션 허용하는 라우터. cretop·public은 unmanaged 읽기 전용.

## 4. 화면 — 3분할 (마케팅 하위 「기업 자금」 메뉴)

```
┌────────────┬──────────────────┬────────────────┐
│ ① 대표이사   │ ② 회사 정보        │ ③ TM 패널       │
│ 이름·회사명  │ 경영진단 웹 재배치   │ 통화 타임라인     │
│ 자격 배지    │ 재무 하이라이트     │ 수동 기록 입력    │
│ 반응도·예정일│ 차입금·신용        │ 오디오 업로드     │
│ 검색·필터   │ 대출가능 X~Y억+근거 │ 반응도·넥스트액션  │
│            │ [엑셀 다운로드]     │ (MMS 이력 자리)  │
└────────────┴──────────────────┴────────────────┘
```

- **①**: 대표이사 행(이름·대표 회사명·자격 배지·최근 반응도·넥스트액션 예정일). 검색(이름·회사·사업자번호·전화), 필터(자격, 반응도, 예정일 도래, 통화 이력 유무), 기본 필터=자격 통과. 행 클릭 → ②③ HTMX 부분 전환.
- **②**: 자격 결과와 근거 / 대출 가능 범위 + 산식 근거(업종군·기준 매출) + 변동 안내 문구 / 재무 3개년(매출·순이익·차입금) / 신용등급·신용사건 / 인증·IP. 대표이사의 회사가 복수면 회사 탭 전환.
- **③**: 통화 타임라인(최신순, 요약·반응도·넥스트액션) + 입력 폼(통화 결과, 반응도, 메모, 넥스트액션+예정일) + 단건 오디오 업로드. MMS 발송 이력 영역은 자리만.
- 레이아웃·파샬 규칙은 디자인 스킬 `template-structure.md`·`foundations.md` 준수 (파일명 접두 `funding_`).

## 5. 오디오 파이프라인

1. **수집**: ③ 단건 업로드 + **일괄 업로드 페이지** — PC에 QR 표시 → 핸드폰 브라우저(같은 와이파이)로 접속 → 다중 선택 업로드. USB 방식 없음.
2. **큐**: 파일 수신 즉시 저장+큐 등록(대기) → 백그라운드 스레드가 순차 처리(처리중→완료/실패).
3. **매칭**: 파일명에서 전화번호 추출(갤럭시 형식) → 대표이사 자동 매칭. 실패 시 "미매칭" 목록에서 사람이 지정. 스크립트는 감지만, 확정은 사람.
4. **전사·요약**: exdigm `transcriber`(Gemini) + `meeting_analyzer`(전사→LLM 요약 제안) 패턴 이식 → 통화기록 **초안** 생성 → 사람이 반응도·넥스트액션 확정.
5. **보관**: 원본 총량 10GB(설정값) 초과 시 FIFO 삭제. 전사·요약은 영구.

## 6. 단계별 구현

| Phase | 내용 | 상태 |
|---|---|---|
| 1 | 메뉴+3분할, 대표이사 승격·리스트, 정보 패널(자격+금액 산식 포함), 수동 통화기록 | ✅ 완료 (28f7dcb, 2026-07-16) |
| 2 | 단건 오디오 업로드→큐→전사→요약→기록 초안, 보관 정책 | ✅ 완료 (32a5438, 2026-07-16) |
| 3 | QR 일괄 업로드 + 미매칭 지정 UI | ✅ 완료 (410e9f3, 2026-07-16) |
| 4 | 경영진단.xlsx 다운로드 연동 (파이프라인 export-report 완성 후) | 예정 |
| 후속 | MMS 보고서 이미지·발송 연동, 숙박업 담보대출 메뉴 | 예정 |

Phase 2 구현 계약: 업로드 50MB(nginx 상한 일치) → 원자적 큐 클레임(멀티프로세스 안전, 30분 좀비 재큐, 폴링 자가치유) → Gemini 전사(18MB 초과는 Files API, 전사 원문 무보정 영구 보관) → LLM JSON 요약 계약(주입 경계·1회 재시도) → 사람 확정으로만 CallRecord 생성. 녹음 시각 미상은 `happened_at_estimated`로 표시.

Phase 3 구현 계약: 배치 페이지가 15분 서명 토큰 QR 발급(`/funding/m/<token>/`, 무로그인) → 폰에서 다중 파일 순차 업로드(토큰 창당 300건 쿼터) → 파일명 전화번호 **숫자 경계 가드 정확 일치**만 자동 매칭, 미일치는 미매칭 목록(50건 표시)에서 사람이 datalist로 지정(전화번호 정확 일치 해석, 유사 매칭 금지) → Phase 2 워커 공용. FAILED 원본은 유일 사본이라 FIFO 삭제 제외. 수용 한계: 발급된 토큰은 재발급해도 15분 만료 전까지 유효(무상태 서명 — 필요 시 서버측 무효화 추가).

## 7. 잔여 미결 (파이프라인 소관 — 참조자료 §13)
