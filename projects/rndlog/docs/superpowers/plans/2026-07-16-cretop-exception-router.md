# CRETOP 예외처리기 통합 계획

## 목표

정상 수집 경로의 기대 마커 확인이 실패하면 정상 함수 안에서 임의 복구하지 않고, 한 곳의 예외처리기로 넘긴다. 예외처리기는 실제 화면 범주를 판정하고 검증된 스마트 검색 상태로 복귀하거나, 안전하게 배치를 중단한다.

## 변경 계약

1. 정상 검색·상세 진입·브리핑·8개 화면 수집 순서와 좌표는 변경하지 않는다.
2. 배치 시작과 회사 처리 중 기대 마커 실패는 화면 캡처와 본문을 보존한 뒤 같은 예외처리기로 전달한다.
3. 예외처리기는 화면 겹침을 피하기 위해 다음 우선순위로 판정한다.
   - 페이지 만료
   - 유료 서비스·서비스 신청 필요
   - 기업·재무정보 비공개
   - 로그인·시간연장·동시접속·KODATA 팝업
   - 검색 결과
   - 상세 화면
   - 스마트 검색·랜딩 화면
   - 판정 불가
4. `유료 서비스입니다`와 `기업 서비스를 신청해주세요`가 함께 확인되면 중앙 확인을 클릭하거나 복구하지 않고 무조건 배치를 실패 처리한다.
5. 기업·재무정보 비공개는 기존 검증 경로인 캡처 → 중앙 확인 → 상세 확인 → 스마트 검색 초기화로 처리하고 다음 회사로 진행한다.
6. 로그인·시간연장·동시접속·KODATA 팝업은 기존 프리플라이트로 복구한 뒤 랜딩과 스마트 검색을 확인하고 같은 회사를 검색부터 다시 시작한다.
7. 페이지 만료는 기존 하드 새로고침 1회 → 30초 대기 → 상태 판정 → 스마트 검색 복귀 경로를 유지한다.
8. 검색 결과나 상세 화면에서 일반 마커 실패가 발생하면 중앙 확인을 클릭하지 않고 상위 스마트 검색으로 초기화한 뒤 해당 회사를 오류로 기록하고 다음 회사로 진행한다.
9. 스마트 검색 화면이 이미 확인되면 마커를 다시 확인한 뒤 해당 회사를 오류로 기록하고 다음 회사로 진행한다.
10. 판정 불가, 화면 복사 실패, 복구 완료 마커 실패는 캡처를 결과에 남기고 배치를 중단한다.
11. 예외 처리 결과는 `같은 회사 재시작`, `오류 기록 후 다음 회사`, `배치 중단` 세 가지로만 배치에 반환한다.

## SSP 병합 위치

- 현재 경로: `collect_batch_fast()`의 배치 시작·페이지 만료·일반 예외 분기
- 병합 위치: 세 분기가 호출하는 단일 예외처리 경계
- 대체 대상: 모든 일반 오류에서 중앙 확인 → 상세 확인을 가정하는 `_recover_company_failure_to_smart_search()` 직접 호출
- 재사용 대상: 기존 만료 복구, 프리플라이트, 비공개 확인, 스마트 검색 초기화 함수
- 유지 대상: 정상 회사 수집과 성공 냉각
