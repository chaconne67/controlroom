# CRETOP 품질 미달 항목 다음 배치 재처리 설계

## 목표

원격 수집 결과 중 한 기업의 상세 섹션 품질검사가 실패해도 전체 DB 저장을 중단하지 않는다. 해당 기업은 DB에 기록하지 않아 미처리 상태로 남기고, 다음 CRETOP 배치가 같은 사업자번호를 다시 선택하게 한다.

## 동작

1. `remote-batch-fetch`는 `present` 항목의 기존 품질검사를 실행한다.
2. 품질검사가 통과하면 기존 DB 저장 경로를 그대로 사용한다.
3. 품질검사가 실패하면 해당 항목의 `save_result()`를 호출하지 않는다.
4. 실패 항목은 회수 요약의 `deferred_items`에 실행 ID, 리드, 품질 실패 사유를 기록한다.
5. 다음 항목의 품질검사와 DB 저장을 계속한다.
6. 모든 저장 가능한 항목을 처리한 뒤 원격 작업을 정리한다.
7. DB에 `requery_required=false` 기록이 없는 품질 미달 기업은 다음 `batch-script-only-collect`의 미처리 목록에 포함된다.

## 불변조건

- 품질 미달 원문은 상세 스냅샷과 구조화 테이블에 저장하지 않는다.
- 품질 미달 기업의 `lead_lookup_status`를 완료 상태로 만들지 않는다.
- 원격에서 명시적으로 회사 오류로 끝난 기존 항목의 저장 규칙은 바꾸지 않는다.
- 이미 저장된 항목의 중복 방지 규칙은 바꾸지 않는다.
- 실패한 섹션만 이전 수집 결과에 합치지 않는다.

## 오류 경계

품질검사 실패만 항목별 보류로 처리한다. DB 오류, 파일 손상, 원격 결과 계약 위반과 같은 다른 예외는 기존처럼 전체 회수를 중단한다.

## 검증

- 단위 테스트에서 첫 항목의 품질검사가 실패하고 두 번째 항목은 DB에 저장되는지 확인한다.
- 실패 항목이 DB 저장 함수에 전달되지 않는지 확인한다.
- 회수 요약에 `deferred_items`가 남는지 확인한다.
- 기존 `20260726_cretop_additional1000`을 다시 회수한다.
- DB에서 999건 완료와 품질 미달 1건 미처리를 확인한다.
- 추가 1,000건 배치를 시작하고 미처리 기업이 대상에 포함됐는지 확인한다.
