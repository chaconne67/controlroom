# 자동게시 에이전트 — 잡코리아 단일 경로 구현 계획 (2026-09-16)

## 현재 승인된 구현 계획

사용자는 자동게시를 고정 스크립트에 예외 처리를 덧붙이는 방식이 아니라, 절차는 프로그램이 강제하고 그 안에서 AI가 판단하는 에이전트로 만들도록 지시했다. “사이트별 절차는 당연히 달라야한다”, “계획을 만들고 구현 진행해”, “최소코드, SSP 준수”가 이번 구현의 기준이다. 아래 과거 기록은 당시 결과로 보존하며 최신 범위와 재개 판단에는 이 절을 우선한다.

### 목표와 범위

- 첫 구현 대상은 기존 승인 범위인 잡코리아다. 기존 로그인 → 등록 화면 준비 → 사이트별 입력 단계 → 최종 확인 → 모드별 처리 순서를 보존한다. 다른 사이트의 순서나 업무 규칙을 잡코리아와 같게 만들지 않는다.
- 핵심역량·근무지처럼 현재 화면의 의미 판단이 필요한 단계는 하나의 관찰/판단/도구 실행/결과 검증 루프를 사용한다. 나머지 검증된 입력 도구를 불필요하게 LLM 호출로 바꾸지 않는다.
- 별도 에이전트 서버, 범용 워크플로 프레임워크, 복구 봇, 임시 실행기, 새 의존성, DB 모델을 만들지 않는다. 기존 공식 autoposting 경로 밖의 성공을 완료 증거로 쓰지 않는다.
- 기존 원본 payload·다른 작업 파일·다른 사이트·로그인/브라우저 수명·공개/담당자/급여 정책을 보존한다. 운영 DB 쓰기, 저장/게시/수정/마감 및 운영 배포는 하지 않는다.

### 책임과 강제 절차

| 책임 | 프로그램/도구 | AI |
|---|---|---|
| 사이트 업무 절차 | Jobkorea.run/_fill이 단계 순서와 다음 단계 진입을 강제 | 순서를 임의로 바꾸지 않음 |
| 관찰과 실행 | common의 현재 화면 관찰·현재 참조 검증·입력·변화 대기 | 관찰 근거에서 허용 도구와 인수 선택 |
| 사이트 특화 | 선택창·주소 입력·실제 확정값 확인 도구, 해당 단계 지침 | 지역 의미·역량 우선순위·추가 요구 해석 |
| 완료와 실패 | 실제 필수 결과·창 종료·예산·권한 검사, 실패 증거 보존 | 원본과 실제 결과의 의미 비교, 부족한 사실 설명 |

각 적응 단계는 `준비 마커 확인 → 현재 상태 관찰 → 검증된 결정 재사용 또는 AI 판단 → 현재 도구 계약 검사 → 실행 → 화면 변화 확인 → 재관찰 → 완료 검증`을 강제한다. 판단과 실행 사이 화면이 바뀌면 실행하지 않는다. 여러 행동을 한 번에 계획해도 행동마다 다시 관찰하고 실행 대상을 확인한다. AI의 완료 선언만으로 다음 단계로 진행하지 않는다.

사용자의 후속 경계 확인을 적용한다. 자동게시는 구조화된 절차이며 AI의 과도한 선택 자유를 목표로 하지 않는다. 화면을 여는 순서·필수 입력·단계 완료·저장/게시 권한은 프로그램이 결정한다. AI에는 현재 단계의 실제 선택지와 허용 도구만 제공한다. AI가 필수 입력을 선택 사항으로 바꾸거나 다음 업무 단계로 건너뛸 수 없다.

단계별 판단 입력에는 목표, 원본 사실과 참고 선택값의 구분, 실제 선택지/안내, 허용 도구, 완료 조건, 최근 실패를 넣는다. 공통 프롬프트는 공통 안전·출력 계약만 담당하며 사이트별 의미 지침을 별도 사이트 실행 경로에서 전달한다. 로딩 대기·기계적 검증·확정된 계획의 실행에는 매번 LLM을 부르지 않는다.

### 현재 근거와 최소 변경

- 이전 실제 dry `20260916170337`은 핵심역량 단계에서 실패했다. 같은 모달의 일반 역량과 중요 역량이 같은 DOM ID/라벨/값을 사용한다. 계획 재연결 키가 두 항목을 같은 대상으로 취급해 계획 실행 없이 판단을 반복했고 최종 응답 계약 오류로 중단됐다. 내부 ID를 전역 고유값으로 가정하지 않고 현재 관찰의 실제 위치와 컨트롤 계약을 함께 확인한다.
- common의 observe_form/validate_form_action/act_on_form, Jobkorea의 _fill/_resolve_form_goal/_known_workplace_action/_set_address, workflow의 _posting_form_decision을 실제로 확인했다.
- 최소 구현 게이트: **2단계에서 멈춤**. 기존 도구·루프·제품 LLM·공식 명령을 재사용한다. 새 실행 계층 없이 _fill의 반복 호출/검사 코드를 하나의 사이트 단계 목록으로 정리하고, 프롬프트의 중복 규칙과 관찰의 불필요한 반복을 줄인다. 필요한 준비 대기와 도구 계약 검사는 그 경로에 통합한다.
- 변경 파일은 기존 자동게시 5파일 안으로 제한한다. 새 런타임 파일은 만들지 않는다. 테스트는 기존 신규 workplace 테스트 파일을 확장한다. 프로그램 증가분은 필수 준비/실행/검증 계약으로 설명하고 같은 변경의 중복 제거와 함께 검토한다.

## 구현 경로와 책임

기존 payload builder → AutoPosting.main → Jobkorea.run/_fill → 근무지 목표 실행 → 실제 입력 확인 → 기존 후속 단계로 연결한다. 신규 서비스·러너·DB 모델·의존성은 없다.

- workflow: 원문 근무지와 사이트 선택값을 분리한다. 정적 지역 코드표 일치를 게시 전 필수 조건으로 요구하지 않는다. 실행 중 의미 판단·행동 선택·최종 의미 검토는 기존 제품 LLM 호출부를 재사용한다.
- common: 현재 근무지 영역의 보이는 컨트롤과 상태를 관찰하고, 이번 관찰에서 발급한 참조만 조작한다. 임의 코드·셀렉터 실행이나 영역 밖 클릭을 허용하지 않는다.
- Jobkorea: 주소·지역의 목표, 허용 조작 영역, 실제 주소·선택 지역 검증을 제공한다. 기존 주소 도구를 재사용하고 코드값으로 상위 지역을 추론하는 특수 분기를 제거한다.
- 알 수 없는 선택지는 재관찰/판단 대상이다. 실제 필수 사실 부족, 안전하지 않은 조작, 예산 소진, 결과 검증 불가는 명시적으로 중단한다. 내용 생략이나 임의 주소로 성공시키지 않는다.
- LLM 호출 수·시간·토큰과 행동/실제 결과를 근무지 증거로 남긴다. 새 정보 없이 같은 행동을 반복하지 않는다.

최소 구현 게이트: 2단계에서 멈춤. 기존 common.llm, AutoPostingCommon.page_session, Jobkorea._set_address, 공식 명령과 테스트를 재사용한다. 검색 근거: _select_region, _select_projected_modal_options, _jobkorea_region_options, _jobkorea_projection_defects, posting_form_snapshot, call_llm_result, gemini_generate_content.

### 구현한 비용·안전 경계

- 기존 선택 힌트가 현재 화면과 맞으면 기계적 입력을 재사용한다. 힌트는 현재 원문의 의미가 맞다는 증거가 아니므로 마지막 의미 검증 1회는 생략하지 않는다.
- 낯선 상태에서는 LLM이 현재 선택지로 목표 주소·추가 지역을 정하고, 스크립트가 이후 동작을 실행한다. 시험의 명확한 사례는 목표 판단 1회 + 독립 검증 1회였다. 모든 변칙이 2회에 끝난다는 보장은 아니다.
- 닫힌 창에서 사라진 안내문도 의미 판단에 유지한다. 행동 참조는 현재 화면 것만 사용한다.
- 최종 검증은 원래 원문과 실제 반영값을 사용하며, 실행 모델의 성공 주장이나 클릭 성공을 근거로 삼지 않는다. 근무지 확정은 다른 입력 뒤, 전체 확인 직전에 실행한다.
- 기본 근무지 예산은 180초와 제한된 판단·행동 횟수(설정 기본 16회)다. 같은 관찰에서 실패한 같은 행동을 반복하지 않으며 응답 형식 보정은 1회다. 시간·토큰을 기록하고 초과·필수 정보 부족은 실패로 남긴다.
- 주소 조회가 실패하면 기존 주소를 덮어쓰지 않는다. 관찰 밖 참조, 제출 버튼, 이동 링크, 임의 셀렉터·코드 실행은 막는다.
- 이미 검증한 주소 입력 도구는 재사용한다. 새로운 사이트 전체 탐색기, 임의 팝업/iframe 처리, 자가 코드 수정·자가 배포·성공 전략의 영구 학습 저장소는 만들지 않았다.

### 후속 보완 승인 — 2026-09-16

1. 선택 단계의 완료 조건을 클릭/창 안 체크가 아니라 실제 확정값과 선택창 종료로 고친다. 현재 화면의 추가 선택 요구를 원래 단계의 책임으로 처리한다.
2. 비정상 상태에서 관찰 범위를 클릭을 막는 창·화면·실패 이유까지 넓힌다. LLM에는 해당 단계의 목적과 원래 사실도 함께 전달한다. 관찰 범위 확대가 임의 클릭·저장·게시 권한 확대로 이어져서는 안 된다.
3. 정상 동작은 스크립트로 수행하고, 의미 선택이나 낯선 요구에만 LLM을 사용한다. 예를 들어 중요한 핵심역량 선택은 실제 선택지와 원문에 근거해 판단하며 코드가 임의의 앞 2개를 고르지 않는다.
