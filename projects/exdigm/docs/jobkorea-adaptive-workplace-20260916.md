기존 payload builder → AutoPosting.main → Jobkorea.run/_fill → 근무지 목표 실행 → 실제 입력 확인 → 기존 후속 단계로 연결한다. 신규 서비스·러너·DB 모델·의존성은 없다.

- workflow: 원문 근무지와 사이트 선택값을 분리한다. 정적 지역 코드표 일치를 게시 전 필수 조건으로 요구하지 않는다. 실행 중 의미 판단·행동 선택·최종 의미 검토는 기존 제품 LLM 호출부를 재사용한다.
- common: 현재 근무지 영역의 보이는 컨트롤과 상태를 관찰하고, 이번 관찰에서 발급한 참조만 조작한다. 임의 코드·셀렉터 실행이나 영역 밖 클릭을 허용하지 않는다.
- Jobkorea: 주소·지역의 목표, 허용 조작 영역, 실제 주소·선택 지역 검증을 제공한다. 기존 주소 도구를 재사용하고 코드값으로 상위 지역을 추론하는 특수 분기를 제거한다.
- 알 수 없는 선택지는 재관찰/판단 대상이다. 실제 필수 사실 부족, 안전하지 않은 조작, 예산 소진, 결과 검증 불가는 명시적으로 중단한다. 내용 생략이나 임의 주소로 성공시키지 않는다.

### 후속 보완 제안 — 범위 확정 전

1. 선택 단계의 완료 조건을 클릭/창 안 체크가 아니라 실제 확정값과 선택창 종료로 고친다. 현재 화면의 추가 선택 요구를 원래 단계의 책임으로 처리한다.
2. 비정상 상태에서 관찰 범위를 클릭을 막는 창·화면·실패 이유까지 넓힌다. LLM에는 해당 단계의 목적과 원래 사실도 함께 전달한다. 관찰 범위 확대가 임의 클릭·저장·게시 권한 확대로 이어져서는 안 된다.
3. 정상 동작은 스크립트로 수행하고, 의미 선택이나 낯선 요구에만 LLM을 사용한다. 예를 들어 중요한 핵심역량 선택은 실제 선택지와 원문에 근거해 판단하며 코드가 임의의 앞 2개를 고르지 않는다.
4. 열린 창을 강제로 닫거나 필수 입력을 버리는 소비자 우회 대신, 미완료 단계를 완성한 뒤 같은 공식 흐름으로 복귀한다. 원래 실패·기존 성공·다른 지역을 다시 비게시 검증한다.

이번 승인은 실제 비게시 검증이며 이 후속 구현은 아직 하지 않았다. 기존 첫 적용 범위인 근무지에서 선행 단계의 완료 확인·방해 창 복구까지 넓히는 계획을 확정한 뒤 변경한다. 실제 사이트 인증/입력 검증에 대한 기존 승인은 다시 요청할 필요가 없다.
