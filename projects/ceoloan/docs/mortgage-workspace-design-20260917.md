작성일: 2026-09-17. 상태: **검토용 시안 / 운영 메뉴·업무 모델 미변경**.

- 사용자 요청: 현재 메뉴는 기업자금으로 묶고, 기업자금·모기지 두 아코디언 아래 각각 회사 목록·문자·TM·영업을 운영한다. 기본 업무 순서는 같고 모기지는 부동산 정보를 추가한다.
- 클릭 시안: [기업자금·모기지 업무 화면](previews/mortgage-workspace-20260917/index.html). 가상의 회사·금액·자료 상태이며 실제 발송·예약·DB 저장이 없다.
- 데이터 설계 정본: [IROS 저장 모델 4·13·14절](iros-real-estate-model-20260917.md). 실제 운영 판독 8개는 검토 대기, 분석 확정은 0개다. 시안의 확인 완료는 미래 상태를 보여주는 합성 자료다.

## 1. 사용자 결과와 범위

사용자는 업무 메뉴를 선택한 뒤 그 업무의 회사에서 문자·통화·영업을 이어가며, 모기지에서는 회사와 연결된 부동산의 소유·거래·권리·원문을 확인할 수 있어야 한다.

이번 변경은 이 문서, 시안 HTML/CSS/JS, 문서 색인뿐이다. 운영 코드·DB·문자 발송·배정·배포는 변경하지 않는다. 운영 정본의 시작 상태는 main `efc8f2ddff789084543a6ea7d47f089de8b0ab1d`, 작업 트리 clean이다. 조정실 controlroom 시작은 `7b6f782` clean. 현행 성공 동작은 문자 발송 후 TM 대상 노출, 대표이사 단위 기업자금 통화, 역할별 메뉴, 영업 인계, 회사 권한을 검사하는 등기 원본 다운로드다.

최소 구현 게이트: 2단계. 실제 `nav_sidebar.html`, `funding/_layout.html`, `admin_list.html`, `workspace.html`, `_tm_panel.html`, `handoff_inbox.html`, `funding/urls.py`, `funding/models.py`, `mortgage/models.py`, `CONTEXT.md`와 ADR0002를 확인했다. 기존 메뉴/상태/색·폰트·컴포넌트 표현을 재사용한 독립 문서 시안이다. 별도 앱 프레임워크·새 운영 의존성·DB 복제는 없다. 검토 HTML에 필요한 CSS/JS만 문서 폴더에 둔다.

## 2. 메뉴 구성

| 순서 | 기업자금 | 모기지 | 목적 |
|---|---|---|---|
| 1 | 오늘 할 일 | 오늘 할 일 | 해당 업무의 예정 통화·자료 요청·방문 |
| 2 | 대상 회사 | 대상 회사 | 검색·대상 선택·회사 상세 진입 |

| 4 | TM 상담 | TM 상담 | 대상 선택·통화·후속 행동 기록 |
| 5 | 통화 녹음 | 통화 녹음 | 해당 업무의 녹음 업로드·미매칭·요약 검토 |
| 6 | TM 진행 내역 | TM 진행 내역 | 상담 비교·영업 전달 |

하단에는 공통 관리(담당자 관리·가입 승인·발신 설정)를 둔다. 기존 슈퍼유저 설정 링크와 로그아웃은 그대로 둔다. 시안에서는 바뀌는 메뉴/업무 공간만 만들며 로그아웃·슈퍼유저 화면을 복제하지 않았다. 담당자 배정은 관리 안에서 기업자금/모기지를 선택하고 기존 배정 확인 절차를 따른다. 기능별 권한이 없는 메뉴는 숨기되 서버 검사도 적용한다.

현재 기업자금에는 독립 ‘대상 회사’ 메뉴가 없으므로 그 진입점을 추가하는 것은 시안 제안이다. 기존 회사 목록을 재사용하고 기업자금의 대표이사 단위 상담을 회사 단위로 강제 변경하지 않는다. 기존 ‘통화 녹음 올리기’는 메뉴에서 ‘통화 녹음’으로 짧게 표기하되 업로드·미매칭·재시도 기능을 보존한다.

### 아코디언과 화면 수명

- 상위 업무명 클릭은 펼침/접힘만 한다. 하위 메뉴 클릭이 화면을 바꾼다. 시안은 한 그룹만 펼치는 방식이다.
- 실제 현재 업무는 본문의 경로·제목과 선택 하위 메뉴에 표시한다. 메뉴를 펼쳤다는 이유로 현재 업무가 바뀌었다고 표시하지 않는다.
- 초기 진입은 URL의 업무 그룹을 펼친다. 별도 경로가 없는 기존 URL은 기업자금으로 유지한다.
- 업무별 마지막 화면·검색 조건·선택 회사·상담 초안을 분리해 유지한다. 다른 업무의 선택 대상을 가져와 문자 예약할 수 없다.
- 서버 구현은 기존 HTMX `#main-content outerHTML` 경로를 유지하고 URL, 포커스, 스크롤, 사이드바 선택·배지를 동기화한다. 배지 조회가 브라우저 주소를 덮어쓰지 않도록 기존 `hx-push-url=false` 계약을 보존한다.
- 모바일은 메뉴 버튼과 같은 아코디언을 사용한다. 이동 후 닫고 본문 제목으로 포커스를 보낸다.

## 3. 회사 목록과 상세

### 목록은 회사 한 줄

모기지 열: 선택 / 회사·지역·업종 / 연결 물건 수와 종류 / 회사와 물건의 관계 / 등기 자료 상태·열람일 / TM 담당자·진행. 거래금액·담보 금액을 회사별 한 수치로 임의 합산하지 않는다. 검색은 회사·대표·지역, 필터는 자료 상태를 시안에 구현했다. 실제 업무에는 기존 담당자·지역·업종·진행 필터를 단계적으로 재사용한다.

- ‘연결 물건 2개’는 토지·건물의 등기 객체 수다. 회사 수·원문 파일 수·첨부 목록 수와 구분한다.
- ‘회사 보유 부동산’은 회사 소유를 검토한 경우에만 사용한다. 주소 검색 결과, 대표자 소유, 제3자 소유, 위탁자, 임차 관계는 별도 표기한다.
- 원문이 없으면 ‘미수집/연결 확인 전’이다. 물건 수 0개나 부채 없음으로 표시하지 않는다.
- 신용·재무는 공통 회사 정본을 표시하고 수집/결산/평가 기준일을 함께 둔다. 미수집 값을 0으로 대신하지 않는다.

회사 상세는 회사 정보 / 부동산 / 활동 이력으로 나눈다. 모기지 기본 탭은 부동산, 기업자금은 회사 정보다. 활동 이력은 현재 업무의 문자·통화·영업 이력이며 공통 회사 사실과 섞지 않는다.

### 물건 상세는 한 물건에 집중

왼쪽 토지·건물·호실 목록에서 하나를 고르고 오른쪽에 해당 물건 내용을 표시한다. 실제 고유번호, 주소, 유형, 열람일, 자료 상태를 머리에 둔다. 시안은 실제 등기번호 대신 A-01 등의 합성 코드를 사용한다.

| 탭 | 표시할 정보 | 주의할 구분 |
|---|---|---|
| 요약 | 등기명의자·지분, 회사 관계, 용도·면적, 최근 소유권 변동, 거래금액과 범위, 담보 상태 | 등기명의자·소유자·위탁자·채무자는 서로 다른 역할 |
| 권리·담보 | 권리 종류·순위번호, 권리자·채무자, 채권최고액, 담보 범위, 설정 원인일·접수일, 변경·말소, 공동담보 묶음 | 최고액≠잔액. 말소를 잔액 0원으로 변환하지 않음 |
| 신탁(해당 시) | 위탁자·수탁자·수익자, 공동 순위·기관별 한도, 신탁 기간·연장, 비용·처분 조건 | 우선수익 한도≠근저당 최고액, 신탁 기간≠대출 만기 |
| 변동 이력 | 취득·설정·변경·말소·이기·분할 사건을 원인일/접수일과 함께 표시 | 현재 기록에 없으면 전체 생애 이력을 확보한 것으로 표시하지 않음 |
| 원문 | 본문·매매목록·공동담보목록·신탁원부, 열람일·쪽수·판독 버전·미수령 참조 | 물건/문서/파일/판독을 구분하고 이전 버전 보존 |

거래금액은 ‘본관+대지 전체 계약 48억원’처럼 대상 범위를 붙인다. 필지별 배분이 없으면 개별 물건 가격을 만들지 않는다. 지분은 원문 분수와 지분 취득 원인/시기를 보존한다. 여러 차례 지분 취득을 합산해 현재 지분을 표시할 때에는 검증한 계산 근거가 있어야 한다.

공동담보는 검토된 동일성 연결이 있을 때만 묶는다. 시안의 본관과 대지는 같은 36억원 담보를 공유하며 둘을 더하지 않는다. 미열람 담보 물건이 있으면 ‘확인된 2개 / 참조된 나머지 미확보’처럼 범위를 표시한다. 같은 은행·날짜·금액은 동일 채무의 충분한 근거가 아니다.

호실은 전유면적과 대지권을 따로 표시한다. 건물만 담보라는 부기를 본문 근처에서 보여주고 대지권까지 담보로 자동 확장하지 않는다. 이기·분할·승계로 새 순위번호가 생겨도 새 대출로 집계하지 않는다.

### 근거와 불확실성

핵심 금액·명의자·지분·날짜 옆 ‘원문’은 현재 표시 중인 판독이 참조한 문서의 해당 쪽을 연다. 근거 좌표가 페이지 수준이면 해당 페이지를 열고 필드 단위 강조를 검증한 것처럼 만들지 않는다. 새 원문과 옛 판독이 섞이지 않도록 문서/판독 식별자를 결합한다. 원문 파일은 기존 마운트와 인증 다운로드 경로를 사용한다.

자료 상태는 최소 미수집 / 검토 대기 / 확인 완료를 구분한다. 최신 원문의 판독이 검토 중이면 마지막 확인본의 날짜와 새 검토 대기를 함께 표시하고, 오래된 확인본을 최신 현재 상태로 단정하지 않는다. 확인 완료라도 권리 상태는 ‘열람일 현재’이며 실시간 법적 상태라는 표현을 쓰지 않는다.

검토 대기에서는 소유·금액 요약을 보류하고 원문·확인할 항목·누락된 부속 문서를 보여준다. 현재 운영의 8개 판독은 여기에 해당한다. 실제 잔액·금리·만기는 별도 증빙이 없으면 ‘확인 자료 없음’이다. 대출 가능액·여유 한도·LTV 산출은 이번 범위에 없다.

## 4. 문자 → TM → 영업

1. 해당 업무의 회사 목록에서 대상을 고른다.
2. 문자 화면에서 확인된 수신 연락처·대상 수·문구·일정을 확인하고 예약한다. 실제 발송 결과가 나와야 TM 상담 대상이 된다.
3. TM은 회사 정보와 필요한 부동산 자료를 보며 통화 결과·반응·메모·다음 행동·일시를 기록한다. 기존 녹음 요약 초안의 확인 절차를 재사용한다.
4. TM 진행 내역에서 영업 담당자를 선택하고 상담 요약·대상 물건·참조 자료 상태를 전달한다.
5. 영업자는 자신에게 전달된 해당 업무 건을 수신→진행중→성사/무산으로 관리한다. 상태·일정·성과 집계는 업무별이다.

### 연락처와 중복 연락

현재 MortgageTarget의 영업 준비는 회사 전화가 확인됐다는 뜻이다. 문자 수신 가능·담당자 휴대전화·수신 적격성을 확인했다는 뜻이 아니다. 회사 일반전화로 funding.Ceo를 만들거나 대표 휴대전화로 바꾸지 않는다.

시안 제안은 TM의 ‘연락처 확인’ 탭이다. 회사 전화만 있는 대상은 문자 전에 이 분기에서 수신 담당자와 연락처를 확인한다. 이는 기본 문자→TM 순서의 예외이므로 실제 구현 전에 채택 여부를 확정한다. 시안에서는 연락처를 자동 생성하거나 확인 완료로 바꾸지 않는다.

업무 기록 분리와 수신자의 연락 의사 보호를 함께 지킨다. 전사적 수신거부를 다른 업무로 우회하지 않는다. 기존 수신거부 데이터의 실제 범위는 구현 전 확인해 마이그레이션 기준을 정한다. 타 업무 최근 발송은 권한 안에서 날짜·업무 등 최소 정보만 보여주고, 다른 팀의 상담 내용까지 자동 공개하지 않는다. 시안의 중복 연락 안내는 합성 사례다.

## 5. 역할과 데이터 경계

| 역할 | 업무 화면 | 부동산·원문 |
|---|---|---|
| 관리자 | 두 업무의 회사·문자·TM·영업·배정 | 권한 있는 회사 자료와 원문 |
| TM | 배정된 업무 대상에 문자·상담·녹음·전달, 기존 범위의 영업 진행 조회 | 배정 회사의 부동산. 원문은 기존 배정 검사 유지 |
| 영업 | 본인에게 전달된 업무의 영업 관리 | 전달된 회사·물건의 요약은 제안 범위. 현재 원문 다운로드 권한에는 영업 역할이 없으므로 권한 확대는 별도 결정 |
| 슈퍼유저 | 기존 가입 승인·설정 경로 | 슈퍼유저라는 이유만으로 업무 역할 검사를 생략하지 않음 |

기술적으로 메뉴만 나누면 업무가 분리되지 않는다. target, assignment, SMS campaign/send, call/audio, followup, handoff 각각의 조회·쓰기·작업 큐·중복키·권한 조건에 업무 범위가 있어야 한다. 어느 저장 책임을 공통화할지는 구현 단계에서 현행 funding 계약과 함께 결정한다. 같은 책임의 문자 발송 엔진·녹음 처리기를 복사하지 않고 입력 대상 연결과 업무 저장 책임을 분리한다.

- 회사/연락처/재무 정본: company 읽기.
- 토지·건물·호실·소유/권리 관측·원문: real_estate 읽기.
- 모기지 대상·배정·상담·문자·영업 기록: ceoloan 쓰기.
- 현재 funding.Ceo 중심 통화/문자 FK와 MortgageTarget의 회사 중심 식별을 동일한 키로 취급하지 않는다. 기존 기업자금 데이터를 자동 이관/복제하지 않는다.

## 6. 화면 상태·접근성·시안 범위

- 모바일 390/480px: 목록을 세로 행으로 재배치하고 같은 정보를 유지한다. 부동산 선택은 상세 위쪽이다. 긴 자료는 해당 영역 안에서 스크롤한다.
- 키보드: 버튼·입력·대화상자 이름, 보이는 포커스, Escape로 닫기, 작업 결과 알림을 제공한다. 탭과 메뉴를 색으로만 구분하지 않는다.
- 불러오는 중 / 목록 오류·재시도 / 검색 결과 없음 / 미수집 / 검토 대기 / 확인 완료를 제공한다.
- 시안은 가상 관리자 관점이다. 역할별 실제 로그인이나 운영 DB 권한을 구현한 결과가 아니다.
- 시안의 문자 완료·상담 저장·영업 전달은 메모리 내 상태만 바꾼다. 새로고침 또는 초기화 시 사라진다. 실서비스 적용 및 배포 승인이 아니다.

## 7. 구현 단계와 완료 조건

1. 메뉴 재구성: 기업자금 현재 동작/URL/역할 유지, 아코디언과 모바일 메뉴. 메뉴 열기와 업무 전환을 구분.
2. 모기지 대상과 부동산 조회: 회사/물건/문서/판독 경계, 실제 검토 대기 8개, 원문 권한 연결. 누락/공유/신탁/이기 사례 표시.
3. 모기지 업무: 업무별 담당자·문자·TM·녹음·후속 행동·영업 저장, 연락처 확인 예외 결정, 수신거부 및 교차 업무 중복 연락 정책.
4. 통합 검증: 한 회사가 두 업무에 존재하는 경우의 데이터/권한/재시도 분리, 부분 화면 이동과 입력 보존, 모바일, 오류 복구. 운영 배포는 명시 승인 후.

실제 구현 완료는 시안 외형 일치뿐 아니라 기존 기업자금 성공 경로 보존, 모기지 실제 대상 분리, 예약/외부 효과 중복 방지, DB 권한 및 원문 바이트 검증으로 판정한다.
