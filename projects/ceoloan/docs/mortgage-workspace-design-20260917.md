# 기업자금·모기지 메뉴와 회사 모달 기획

작성: 2026-09-17. 수정: 2026-09-18. 상태: **사용자 정정 반영 시안 / 운영 코드 미변경**.

## 1. 확정한 사용자 요구

기존 UI·UX를 유지한다. 기업자금/모기지로 메뉴만 묶고 모기지는 기존 화면을 재사용하며 부동산 정보를 추가한다. 회사 목록의 행을 누르면 기존처럼 모달이 열린다. 별도 회사 상세 페이지, 새 목록 디자인, 새 문자·TM·영업 과정은 만들지 않는다.

모기지 회사 모달의 정보 순서는 기존 회사 기본정보 → 재무정보 → 부동산 정보다. **처음 열 때 재무정보는 접혀 있고 부동산 정보는 펼쳐져 있다.** 각 영역은 독립적으로 열고 닫을 수 있다. 모달을 닫았다 다시 열거나 다른 회사를 열면 이 기본 상태로 시작한다.

모달의 높이는 화면을 넘지 않으며 긴 내용은 모달 안에서 세로 스크롤한다. 제목과 닫기 버튼은 내용 스크롤 영역 밖에 둔다. 넓은 표는 표 안에서 가로로 스크롤한다.

- [클릭 시안](previews/mortgage-workspace-20260917/index.html): 가상 회사·금액. 실제 발송·예약·DB 호출 없음.
- [부동산 데이터 모델](iros-real-estate-model-20260917.md): 원문/판독/권리·담보 데이터의 정본.
- 기존 시안의 회사→독립 상세 페이지와 새 업무 화면은 철회했다. 9월 17일 화면·검증 파일은 당시 기록이며 현재 승인안이 아니다.

## 2. 기준선과 변경 범위

원격 코드 정본은 현재 AGENTS.md의 main 서버 chaconne@49.247.192.127, /home/chaconne/projects/ceoloan이다. 작업 중 운영 경로 정리 지침이 갱신되어 마지막에 새 경로에서 같은 HEAD와 clean 상태를 재확인했다. 2026-09-18 확인 HEAD efc8f2ddff789084543a6ea7d47f089de8b0ab1d, 작업 트리 clean. 조정실 문서 시작 HEAD 45e64d7, clean.

변경은 이 문서, 시안 index.html/app.js/style.css, 이 작업의 검증 자료와 README 링크 설명에 한정한다. 실제 앱 코드·DB·권한·문자·배정·운영 배포는 변경하지 않는다.

수정 전 시안을 실제 Chrome에서 확인했다. 목록 클릭 후 #mortgage/detail/hotel/summary로 이동하고 열린 회사 모달이 0개였다. 이것이 사용자 정정과 맞지 않는 직접 관측이다. 메뉴의 두 업무 구분, 합성 부동산 표본, 원문/미확정 값 표시의 의미는 보존한다.

최소 구현 게이트: 2단계에서 멈춤. 실제 funding/templates/funding/_admin_rows.html, _admin_items.html, _progress_modal.html, _company_panel.html, admin_list.html, funding/_layout.html, templates/common/nav_sidebar.html, static/css/input.css, tailwind.config.js를 확인했다.

기존 .darkhead-table, .btn, .input, .select와 4xl/85vh 모달 틀을 재사용한다. 시안은 운영 공개 CSS를 직접 참조하며 조회 시 SHA-256은 원격 static/css/output.css와 일치했다: 863c15d8312ed191afa3af6760b08115769d03cf35b19c6dbe9855523ea72b5d. 새 UI 프레임워크·의존성·화면별 제품 CSS를 추가하지 않는다. style.css는 문서 배치와 변경하는 두 정보 영역/모달의 시안용 표현만 소유한다.

## 3. 메뉴

기업자금 / 모기지 아코디언 아래 기존 이름과 순서로 둔다.

1. 오늘 할 일
2. 문자 발송
3. TM 상담
4. 통화 녹음 올리기
5. TM 진행 내역
6. 영업 현황 (영업자에게는 기존 영업 관리 명칭)

관리·설정·로그아웃은 기존 위치와 권한을 유지한다. 독립 ‘대상 회사’ 메뉴 추가, ‘통화 녹음’으로 이름 변경, 선행 ‘연락처 확인 TM’ 분기 제안은 철회한다. 대상 회사 목록은 각 업무의 기존 목록을 사용하고 모기지 대상/업무 범위만 분리한다.

상위 제목은 메뉴를 접고 펼친다. 세부 메뉴가 해당 업무 화면을 연다. 기존 기업자금 URL·HTMX 부분 교체·작성 상태·역할별 메뉴 계약을 유지한다. 시안은 기존 문자 발송 목록의 합성 표현을 제공하고 변경하지 않는 다른 업무 화면은 안내 자리로 표시한다. 전체 앱 기능을 새로 모사하지 않는다.

## 4. 기존 회사 모달에 추가할 영역

실제 현재 경로:
- 문자 발송 목록 _admin_items → progress_modal → _progress_modal → _company_panel.
- TM 진행 내역은 기존 ceo_detail 상담 판을 열며 회사 정보와 통화·액션 기록을 함께 본다.
- TM 상담도 같은 _company_panel을 재사용한다.

기존 대표/연락처 제목, 회사명·사업자번호·주소, 경영진단 버튼, 회사 프로필은 기존 표시를 유지한다. 기업자금은 기존 그대로 표시한다. 모기지에서만 회사 정보 안에 다음 두 접기 영역을 사용한다.

| 영역 | 초기 상태 | 내용 |
|---|---|---|
| 재무정보 | 접힘 | 기존 재무 3개년 표, 신용등급·기준일, 부채비율 및 기존 회사 재무 표시 |
| 부동산 정보 | 펼침 | 물건 선택, 소유·관계·면적·취득·거래·권리·담보·신탁·이력·원문 |

재무가 없는 회사도 모달과 부동산을 열 수 있다. ‘재무 데이터가 없습니다’로 표시하고 미확인 값은 0으로 채우지 않는다. 회사 전화만으로 대표 휴대전화나 문자 발송 가능 여부를 추정하지 않는다.

모기지 데이터가 없으면 ‘수집된 부동산 정보가 없습니다’로 표시한다. 이를 부동산을 보유하지 않았다는 뜻으로 표시하지 않는다.

모달 내부의 상담 기록·할 일·영업 전달 기능은 기존 위치와 동작을 유지한다. 이번 수정은 그 기능을 재설계하거나 새 접촉 절차를 추가하지 않는다.

## 5. 목록과 부동산 모달에 표시할 내용

2026-09-18 실제 DB·원문 대조를 반영했다. 근거와 현재 조회 가능 범위는 9절에 기록한다.

### 회사 목록

기존 회사명·대표·매출·등급·담당 TM·최근 통화·반응도·통화 수·상태와 행 클릭 동작을 유지한다. **모기지 목록에만 ‘부동산 자료’ 열 하나를 추가**한다.

- 첫 줄: ‘연결 2개’처럼 회사에 연결된 고유 물건 수. 회사 소유 물건 수라는 뜻이 아니다.
- 둘째 줄: 검토 대기 / 일부 검토 완료 1/2 / 검토 완료 / 미수집 중 실제 상태. 일부 물건만 검토되어도 회사 전체를 완료로 바꾸지 않는다.
- 매출·등급은 기존 재무 정본을 그대로 읽는다. 자료가 없으면 ‘—’. 재무 유무를 부동산 자료 열에 섞지 않는다.
- 거래금액·채권최고액·부동산 평가액·대출 잔액·LTV를 회사 단위로 합산한 열은 만들지 않는다. 공동담보와 여러 물건의 계약 전체 금액이 중복될 수 있다.
- 문자·TM·영업의 상태, 담당자, 연락처와 발송 조건은 기존 업무 기능이 계속 책임진다.

### 모달의 부동산 정보

물건이 여러 개면 기존 부동산 영역의 선택 상자에서 토지·건물·호실을 선택한다. 별도 상세 페이지는 만들지 않는다. 선택 뒤에는 이 순서로 표시한다.

| 영역 | 보여줄 내용 | 표시·집계 규칙 |
|---|---|---|
| 물건과 자료 상태 | 부동산 고유번호·종류·주소·동호수, 열람일, 판독 상태, 회사 연결 근거 | 주소 조회/공동담보목록 연결/소유·위탁자 대조를 구분한다. 검토 상태와 회사 관계 확인 상태는 별개다. |
| 표시·면적 | 토지 지목·면적, 건물 용도·구조와 층별 면적, 집합건물 전유면적·대지권 비율 | 토지/전유/층별/전체 면적을 섞지 않는다. 원문에 전체 면적이 없으면 합계로 만들지 않는다. 분모·분자와 원문 비율을 보존한다. |
| 소유·취득 표 | 등기명의자별 현재 지분, 회사 관계, 취득 원인, 원인일·접수일, 근거 쪽 | 공유자는 전원 별도 행. 일부 지분 취득·현재 남은 지분을 구분한다. 소유권 이기·신탁·상속 등을 매매로 바꾸지 않는다. |
| 거래금액·범위 표 | 매수인·매도인, 계약/원인일·접수일, 거래금액·통화, 매매목록과 적용 물건·지분 범위 | 전체 계약금액과 본 물건 배분금액을 구분한다. 미기재 배분금액은 빈 값. 같은 거래의 반복 기재를 거래 여러 건으로 세지 않는다. |
| 현재 권리·담보 표 | 갑/을구 원문 순위·부기번호, 권리 종류, 권리자·채무자, 금액 종류·통화, 담보 범위, 원인일·접수일, 근거 쪽 | 근저당 채권최고액, 저당 채권액, 전세금, 가압류 청구금액을 같은 금액으로 취급하지 않는다. 변경 후 현재 금액·당사자를 표시하고 말소된 권리는 현재 표에서 제외한다. |
| 신탁 관계·우선수익권 | 위탁자·수탁자·수익자, 기관별 순위·한도·담보 채권 범위, 기간·연장 조건, 근거 쪽 | 공동 1순위를 임의 1·2·3순위로 바꾸지 않는다. 같은 채권의 중복 여부가 확인되지 않으면 한도 합계를 만들지 않는다. 신탁 기간은 대출 만기가 아니다. |
| 변경·말소 이력 | 대상 등기·권리, 변경 종류, 원인일·접수/주기일, 변경 전후 값·당사자·범위, 말소 여부, 근거 쪽 | 말소를 잔액 0원으로 바꾸지 않는다. 이기된 문서의 일부 이력을 전체 이력으로 표현하지 않는다. 원인일을 접수일로 복사하지 않는다. |
| 원문·연결 목록 | 문서 종류·열람일·페이지 수·검토 상태, 공동담보목록/매매목록/신탁원부, 수령 여부, 근거 쪽과 원문 버튼 | 수령하지 않은 문서는 미수령으로 표시. 파일은 마운트 디스크에 두고 기존 인증 다운로드로 조회한다. 페이지 근거만 있으면 글자 위치를 강조한 것처럼 표시하지 않는다. |

‘현재’는 **해당 문서 열람일 기준**이다. 최신 시점의 권리 상태를 보장하는 표현으로 쓰지 않는다. 공동담보는 확인된 동일 담보 관계만 묶고, 목록 번호만 같다고 같은 채무로 묶지 않는다. 물건·공동담보·채권의 수를 구분한다.

실제 대출 잔액·금리·만기는 별도 자료가 없으면 비운다. 회사 재무의 단기·장기차입금은 회사 전체 회계 수치이므로 해당 부동산의 대출 잔액에 연결하지 않는다.

**판독 검토 대기:** 물건/문서의 수집 정보, 회사 연결 근거, 원문, 검토·미수령 상태를 표시하고 미확정 소유자·지분·금액·현재 권리를 확정 표로 공개하지 않는다. 지금 적재된 판독 8개가 여기에 해당한다. 시안의 ‘검토 완료 예시’는 향후 표시 구성 검토를 위한 가상 자료다.

**빈 값 구분:** 미수집, 검토 대기, 원문 미기재, 자료 없음, 해당 없음, 원문으로 확인된 권리 없음은 다른 상태다. 현재 권리 조회 결과 0행만 보고 ‘권리 없음’으로 출력하지 않는다. 공개된 판독·문서 범위와 검토 완료 여부를 함께 확인해야 한다.

### 재무정보 재사용

현재 financial_series()의 계정·단위·연도 순서를 그대로 따른다. 매출/영업이익/당기순이익은 백만원, 자산/부채/자본/납입자본금/단기차입금/장기차입금은 천원이다. 최근 최대 3개년을 과거→최근 순서로 표시하고 없는 계정은 생략, 없는 연도별 값은 ‘—’로 둔다. 모든 계정을 백만원으로 통일하거나 없는 값을 0으로 만들지 않는다. 이번 시안의 가상 재무 데이터도 이 계약으로 맞췄다.

## 6. 데이터·권한 보호

회사 사실과 재무는 company, 등기 사실·원문은 real_estate, 문자·TM·영업 업무는 ceoloan의 기존 경계를 따른다. 기업자금/모기지에서 같은 회사가 보여도 선택·초안·배정·발송·상담·영업 기록은 해당 업무에 속한다. 수신거부나 기존 접촉 제한은 업무 전환으로 우회하지 않는다.

### 원문과 추출 결과 대조

기존 검증 기록 전체를 읽고, A02/A03/U06의 로컬 원본 3개를 보관 manifest의 SHA-256과 대조했다. 해당 사례의 주요 페이지를 직접 시각 확인했다. 개인명·식별번호·실제 주소와 원문 이미지는 이 문서/Git/공용 지식에 복제하지 않는다. 아래는 구조 판단만 남긴다.

- **A02:** 현재 소유자 3명과 지분 3/10·5/10·2/10이 존재하지만 이전 판독은 일부만 추출했다. 매매목록은 여러 물건의 계약 전체 가격이며, 당사자·지분별 반복 기재를 물건별 가격이나 별도 거래로 세면 중복된다. 말소된 이전 근저당도 남아 있어 현재 권리와 이력 분리가 필요하다.
- **A03:** 소유권 변동이 신탁이며 이기 이전 전체 이력은 현재 문서만으로 끝나지 않는다. 신탁원부에는 위탁자·수탁자·수익자와 공동 1순위 기관들, 기간·연장 조항이 있다. 표지 몇 항목 추출 성공만으로 전체 원부 검토 완료를 표시할 수 없다.
- **U06:** 집합건물 전유면적과 대지권 비율이 따로 있으며, 근저당에는 나중에 ‘건물만’에 관한 등기라는 주기가 있다. 주기일을 신규 대출일이나 만기로 사용하면 틀린 설명이 된다.
- **기존 감사 기록의 추가 결함:** N01은 여러 근저당·면적·공동담보목록을 누락했고 N02는 최신 일부 권리만 추출했다. L01에서 말소를 0원으로 생성하던 문제가 있었고 L02는 은행명 대조 불일치가 있었다. 구문/구조 검사 성공은 사실 검토 완료와 다르다.
