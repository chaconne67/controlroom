화면 기획 · 실제 화면에는 표시하지 않음

회사는 공통으로 읽고, 업무는 두 갈래로 이어갑니다.

기업자금과 모기지는 각각 대상 회사 → 문자 발송 → TM 상담 → 영업으로 이어집니다. 회사가 양쪽 대상이어도 담당자·선택 목록·예약·통화·녹음·할 일·영업 건은 서로 섞이지 않습니다. 같은 회사의 재무·연락처·부동산 원문은 공통 정본을 참조합니다.

1. 메뉴 구성

상단의 기업자금 / 모기지 버튼은 하위 메뉴만 펼칩니다. 메뉴를 펼치는 것만으로 현재 화면을 바꾸지 않습니다. 하위 메뉴 선택 시 업무가 바뀌며, 마지막 화면·검색 조건·작성 중 기록은 업무별로 기억합니다.

두 메뉴 모두 오늘 할 일, 대상 회사, 문자 발송, TM 상담, 통화 녹음, TM 진행 내역, 영업 현황을 둡니다. 계정·가입 승인·발신 설정은 하단 공통 관리에 둡니다. 담당자 배정은 관리 화면 안에서 업무를 선택합니다.

2. 부동산 탐색

목록은 회사 한 줄, 상세는 물건 한 개를 기준으로 봅니다. 회사 상세의 부동산 탭에서 토지·건물·호실을 고르고 요약, 권리·담보, 변동 이력, 원문을 봅니다. 신탁이 있는 물건에만 신탁 탭을 추가합니다.

등기 자료 보유와 회사 소유 확인을 별개로 표시합니다. 주소로 연결된 부동산을 곧바로 보유 부동산으로 부르지 않습니다. 말소·공유지분·건물만 담보·미수령 목록을 내용 가까이 표시합니다.

3. 금액을 읽는 기준

매매금액은 어느 물건 묶음의 가격인지, 채권최고액은 어느 담보 묶음의 금액인지 함께 보여줍니다. 공동담보 36억원이 두 등기에 반복돼도 72억원으로 더하지 않습니다. 신탁 우선수익 한도는 근저당 최고액과 별도로 표시합니다.

대출 잔액·금리·만기는 은행 자료 등 별도 근거가 있을 때만 표시합니다. 등기만 있는 상태는 ‘확인 자료 없음’입니다. 대출 가능액·LTV·상환일을 임의로 계산하지 않습니다.

4. 자료 상태와 영업 상태

등기 미수집, 검토 대기, 확인 완료는 자료 상태입니다. 미접촉, 상담 중, 영업 전달, 진행·성사·무산은 업무 상태입니다. 검토 대기 자료는 원문을 볼 수 있지만 숫자 요약과 분석 집계에는 포함하지 않습니다.

현재 운영의 판독 8개는 모두 검토 대기입니다. 이 시안의 ‘확인 완료’는 향후 원문 검토를 통과했을 때의 합성 상태입니다. 회사 전화만 있는 경우의 연락처 확인 TM, 영업자의 원문 접근 권한은 아래 결정 사항을 따릅니다.

모바일에서의 사용

390·480px에서는 상단 메뉴 버튼으로 동일한 아코디언을 엽니다. 회사 표는 같은 정보를 담은 세로 행으로, 부동산 선택은 상세 위쪽 목록으로 바뀝니다. 긴 원문은 별도 대화상자에서 스크롤하며, 통화 입력과 저장 버튼을 숨기지 않습니다. 위 ‘모바일 폭 보기’에서 변경된 화면을 바로 확인할 수 있습니다.

구현 메모

시안용 CSS는 운영의 paper / ink / accent / line 및 WDS 색 값을 사용합니다. 구현 때에는 기존 .btn / .input / .select / .darkhead-table과 nav_sidebar, funding/_layout, HTMX의 #main-content 교체를 재사용합니다. 시안은 독립 HTML이며 운영 코드의 새 CSS 체계가 아닙니다. 주 행동에는 기존 TM 화면처럼 ink 배경을 사용하고, 녹색은 선택 표시로 사용합니다.

결정한 방향과 남은 선택

요청으로 확정: 기업자금·모기지 아코디언, 별도 대상·문자·TM·영업, 같은 업무 순서, 모기지 부동산 상세. 시안 제안: 양쪽 ‘대상 회사’ 진입점, 공통 관리 안 업무별 배정, 모기지의 ‘연락처 확인’ TM 분기. 이 분기는 문자 → TM 순서의 예외이므로 구현 전 확정할 항목입니다. 영업자의 등기 원문 권한 확대는 이 시안으로 허용하지 않으며, 필요하면 전달된 회사·물건 범위로 별도 설계합니다.

구현 단계

  1. 현 기업자금 메뉴를 아코디언으로 묶고 기존 URL·상태·권한을 보존합니다.
  2. 모기지 대상 회사와 회사·부동산 조회를 연결합니다. 판독 미확정 상태부터 실제 자료로 검증합니다.
  3. 문자·TM·녹음·할 일·영업을 업무별로 분리하고, 중복 연락·권한·진행 상태를 확인합니다.
  4. 모바일·키보드·부분 화면 이동·오류/재시도와 실제 업무 분리를 검증한 뒤 배포 여부를 결정합니다.
