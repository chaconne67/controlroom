# 실행

## 사전 준비

- 아래 `companies/<회사>`의 `<회사>`는 `V<YYMMDD>-<한글회사명>` 형식의 회사 폴더명이다. 사용자가 한글회사명만 말하면 `companies/`에서 `V*-<한글회사명>` 폴더를 찾아 쓰고, 날짜가 다른 폴더가 둘 이상이면 임의로 고르지 말고 어느 것을 쓸지 사용자에게 확인한다.
- 회사 작업공간: `companies/<회사>`
- 입력 파일 존재 여부를 확인한다.
  - `companies/<회사>/README.md`
  - `companies/<회사>/distillation.md`
  - `companies/<회사>/values.md`
  - `companies/<회사>/texts/problem_background.md`
  - `companies/<회사>/texts/solution.md`
  - `companies/<회사>/texts/tech_progress.md`
  - `companies/<회사>/texts/tech_plan.md`
- 출력 폴더가 없으면 생성한다.
  - `companies/<회사>/texts/`
- Markdown 파일 읽기와 쓰기는 항상 UTF-8을 명시한다.
- PowerShell에서 한글 파일을 확인할 때는 먼저 `[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)`를 실행한 뒤 `Get-Content -LiteralPath <path> -Encoding UTF8`로 읽는다.

## 입력 내용

- `README.md`
  - 회사명
  - 홈페이지 URL
  - 작성 방향
  - 현재 진행 상태
- `distillation.md`
  - 시장환경
  - 경쟁·대체재 환경
  - 기술동향
  - 고객·마케팅 동향
  - 회사 기술의 위치
  - 차별성 작성 포인트
  - 확인 필요
- `values.md`
  - 기본 정보
  - 주요 제품·서비스
  - 제품·서비스 차별성 후보
  - 재무·협업·자금 후보
- 문제해결 본문:
  - `texts/problem_background.md`
  - `texts/solution.md`
  - `texts/tech_progress.md`
  - `texts/tech_plan.md`

## 작업 내용

- 메인 에이전트는 작성 sub-agent를 호출하기 전에 `시장`, `경쟁`, `진입경과`, `확대계획` 키포인트를 먼저 정리한다.
- 키포인트는 별도 파일로 저장하지 않고 작성 sub-agent 프롬프트에 공통 제공한다.
- 4개 작성 sub-agent를 병렬로 호출해 각 항목 초안을 작성한다.
- 각 작성 sub-agent는 자기 항목의 본문 초안만 반환하고 파일을 수정하지 않는다.
- 검사 sub-agent는 4개 초안을 함께 검토해 시장 → 경쟁 → 진입경과 → 확대계획 흐름, 중복, 모순, 심각한 사실 오류, 명백한 창작, 작성자 방어식 표현을 점검한다.
- 메인 에이전트는 검사 결과를 확인한 뒤 최종 문구를 4개 Markdown 파일로 저장한다.

## 작문 규칙 로드

작문 규칙 정본은 아래 한 파일이다. 규칙을 이 파일에 복제하지 않는다.

```
skills/venture/references/writing-rules.md
```

- 작성·검사 sub-agent를 호출하기 전에 프로젝트 루트 기준 위 경로를 Read로 읽는다. 이미 읽었다고 판단해 건너뛰지 않는다.
- 파일 첫 절인 `## 역할과 입장`을 먼저 적용한다. 다른 모든 규칙보다 우선하며, sub-agent 프롬프트에 반드시 함께 포함한다.
- 읽지 않은 상태로 sub-agent를 호출하지 않는다.
- sub-agent 프롬프트에는 해당 절 전문을 그대로 포함한다. 요약하거나 경로만 알려주지 않는다.
- 규칙 파일의 `phase별 적용 범위` 표에서 이 phase에 해당하는 행을 확인하고 그대로 적용한다.

## 작성 sub-agent 공통 제공 내용

- 작성 규칙: 작문 규칙 파일의 `## 작문 공통 규칙` 전문
- 공통 키포인트:
  - 시장: 메인 에이전트가 입력 자료에서 정리한 목표시장과 고객군
  - 경쟁: 메인 에이전트가 입력 자료에서 정리한 경쟁사·대체재와 회사의 차별성
  - 진입경과: 메인 에이전트가 입력 자료에서 정리한 현재까지의 시장진입 준비와 사업화 단서
  - 확대계획: 메인 에이전트가 입력 자료에서 정리한 향후 3년 시장진입·확대 방향
- 입력 자료:
  - `README.md`의 작성 방향
  - `distillation.md`의 시장환경, 경쟁·대체재 환경, 기술동향, 고객·마케팅 동향, 회사 기술의 위치, 차별성 작성 포인트, 확인 필요
  - `values.md`의 주요 제품·서비스, 제품·서비스 차별성 후보, 재무·협업·자금 후보
  - `texts/problem_background.md`, `texts/solution.md`, `texts/tech_progress.md`, `texts/tech_plan.md`
- 시장 규모, 성장률, 매출, 계약, 협업, 투자 계획은 `distillation.md`와 `values.md`의 상태에 맞춰 확정 실적, 목표, 추정, 추진 계획이 구분되도록 작성한다.
- 수치가 추정 또는 목표인 경우 고객군, 적용처, 구매 동기, 진입 가능한 사업모델, 실행 방향과 함께 사업계획 표현으로 작성한다.

## phase6 작성 방식

- 4개 항목(목표시장·고객 정의 → 경쟁사 분석 → 시장진입 추진경과 → 향후 시장확대 계획)이 하나의 논리로 이어지게 작성한다: 정의한 목표시장·고객을 두고 경쟁 구도를 비교하고, 현재까지의 진입경과와 향후 확대 계획으로 연결한다.
- 시장 관련 본문은 `distillation.md`의 웹조사 기반 시장환경·기술동향·고객 동향·경쟁/대체재 환경을 주요 근거로 활용한다.
- TAM/SAM/SOM 구분과 고객군 라벨, 연도·연차별 실행 단위, 수치 표기와 실적/목표 구분 등 세부는 아래 항목별 작성요령과 작문 규칙 파일의 `## 작문 공통 규칙`을 따른다.

## 항목별 작성 sub-agent 제공 내용

### target_market

- 출력 항목: 목표시장 및 고객 정의
- 반환 내용: 목표시장 및 고객 정의 본문 초안
- 항목 작성요령:
  - 목표시장 및 고객을 정의한다.
  - 회사 기술·제품·서비스의 전체시장, 유효시장, 목표시장을 구분한다.
  - 현재 진입 가능하거나 3년 내 확보 가능한 시장과 고객을 중심으로 작성한다.
  - 객관적 시장 규모 자료가 있으면 출처와 함께 반영한다.
  - 객관적 시장 규모 수치가 제한적인 경우에도 고객군, 적용 공간, 구매 동기, 사업모델에 근거해 전체·유효·목표시장 규모와 연차별 예상 매출·고객 수를 합리적 추정 수치로 명시한다(`약`, `예상`, `목표`, `진입 가능` 등 목표·추정 표기 병기).

### competition

- 출력 항목: 경쟁사 분석
- 반환 내용: 경쟁사 분석 본문 초안
- 항목 작성요령:
  - 목표시장 내에서 비슷한 가치를 제공하는 경쟁기업 또는 대체재를 분석한다.
  - 경쟁사가 명확하면 최대 3개사의 특징, 한계, 회사의 우위 가능성을 작성한다.
  - 경쟁사가 명확하지 않으면 고객이 기존에 문제를 해결하던 방식과 그 한계를 작성한다.
  - 회사의 경쟁우위는 기술, 서비스 구성, 특허·인증, 시공·운영 방식의 차이로 설명한다.
  - 각 경쟁사·경쟁군·대체재는 `특징 → 한계 → 당사 우위 → (가능하면) 우위 확보 전략` 순의 정형 구조로 정리해 비교가 한눈에 보이게 한다.
  - 당사 우위는 막연한 우월 표현이 아니라 특허·데이터·레퍼런스·운영 방식 등 구체 근거와 1:1로 연결한다.

### market_progress

- 출력 항목: 시장진입 및 확대 전략 추진경과
- 반환 내용: 시장진입 및 확대 전략 추진경과 본문 초안
- 항목 작성요령:
  - 목표시장에 대한 현재 시점의 진입 준비와 목표달성 수준을 작성한다.
  - 최근 3년 매출액, 계약, 납품, 협업 자료가 있으면 확인된 범위에서 반영한다.
  - 매출·계약 수치가 제한적인 경우 시장조사, 제품·서비스 정비, 기술 확보, 인증, 브랜드·채널 준비 등 추진경과 중심으로 작성한다.
  - 목표시장 진입을 위한 마케팅, 가격, 브랜드, 생산·시공, 상품화 준비 과정을 구체적으로 제시한다.

### market_plan

- 출력 항목: 시장진입 및 확대 전략 향후 3년 계획
- 반환 내용: 향후 3년 시장진입 및 확대 계획 본문 초안
- 항목 작성요령:
  - 목표시장 진입과 확대를 위한 향후 3년 계획을 작성한다.
  - 1차년, 2차년, 3차년 흐름으로 단계별 실행 방향을 제시한다.
  - 주요 채널, 제품·서비스 적용처, 고객군 확대, 브랜드·마케팅, 시공·공급 역량 고도화 계획을 작성한다.
  - 각 연차에는 실행 방향과 함께 정량 이정표(예상 매출, 계약·레퍼런스 건수, 고객 수, 점유율 목표 등)를 `약`·`목표`·`예상` 표기로 배치한다.
  - 매출 목표나 계약 계획 수치가 제한적이어도 정량 이정표를 비우지 않으며, 자료 유무에 따른 처리는 작문 규칙 파일의 `## 작문 공통 규칙`의 `### 수치·근거`를 따른다.

## 검사 sub-agent 제공 내용

- 검사 규칙: 작문 규칙 파일의 `## 작문 검사 규칙` 전문
- 메인 에이전트가 정리한 공통 키포인트
- 작성 sub-agent가 반환한 4개 초안
- 초안 확인에 필요한 `distillation.md` 내용
- 초안 확인에 필요한 `values.md` 내용
- 초안 확인에 필요한 문제해결 본문 4개

## 검사 sub-agent 작업

- 4개 초안이 시장 → 경쟁 → 진입경과 → 확대계획 흐름으로 연결되는지 점검한다.
- 항목 사이에 같은 문장이나 같은 논리가 과도하게 반복되는지 점검한다.
- 항목 사이에 시장 범위, 경쟁사, 실적, 계획이 서로 모순되는지 점검한다.
- 심각한 사실 오류, 명백한 창작, 벤처인증 제출문에 어울리지 않는 작성자 방어식 표현을 점검한다.
- 최종 권장 문구 4개를 반환한다.

## 출력 내용

- 출력 파일:
  - `companies/<회사>/texts/target_market.md`
  - `companies/<회사>/texts/competition.md`
  - `companies/<회사>/texts/market_progress.md`
  - `companies/<회사>/texts/market_plan.md`
- 각 파일의 `char_count`는 프론트매터와 제목을 제외한 본문 글자수만 기록한다.
- 각 파일의 `source`에는 실제 사용한 근거 파일을 기록한다.
- 각 출력 파일은 아래 형식을 따른다.

```markdown
---
field_id: <field_id>
status: ready
char_count: 000
source:
  - distillation.md
  - values.md
notes:
  - 필요 시 작성 기준 또는 확인 필요 사항
---

# <항목 제목>

본문
```
