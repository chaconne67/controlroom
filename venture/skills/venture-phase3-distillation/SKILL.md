# 실행

## 사전 준비

- 아래 `companies/<회사>`의 `<회사>`는 `V<YYMMDD>-<한글회사명>` 형식의 회사 폴더명이다. 사용자가 한글회사명만 말하면 `companies/`에서 `V*-<한글회사명>` 폴더를 찾아 쓰고, 날짜가 다른 폴더가 둘 이상이면 임의로 고르지 말고 어느 것을 쓸지 사용자에게 확인한다.
- `companies/<회사>/README.md`에서 회사명, 홈페이지 URL, 작성 방향, 추출 문서 목록, 자료 위치를 확인한다.
- Markdown 파일 읽기와 쓰기는 항상 UTF-8을 명시한다.
- PowerShell에서 한글 파일을 확인할 때는 먼저 `[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)`를 실행한 뒤 `Get-Content -LiteralPath <path> -Encoding UTF8`로 읽는다.
- phase3 산출물 범위는 `distillation.md` 작성과 `README.md` 갱신이다.
- 홈페이지 렌더링: `homepage_url`이 있으면 `node scripts/scrape_site.js --url <homepage_url> --out companies/<회사>/src/homepage_rendered.md`를 실행해 JS로 주입되는 메인·하위 페이지(heritage, 사업, 제품, 기술 등) 본문을 확보한다. 정적 추출(`src/homepage.md`)만으로 본문이 부실하거나 하위 페이지 링크가 `#none`으로 숨겨진 홈페이지를 보강하는 단계다. 스크립트 실패 시 정적 `src/homepage.md`로 진행한다.
- 회사가 제공한 특허, 인증, 자격, 상표, 디자인권, 기술자료는 신청서 작성 근거로 신뢰한다.
- 명백한 사실 오류가 아닌 회사 제공자료와 정제 정보는 긍정적인 사업계획서 작성 관점에서 활용한다.

## 작문 규칙 로드

이 phase는 시장 규모·성장률·목표 수치를 만들어 후속 phase가 그대로 쓰는 단계다.
작업을 시작하기 전에 프로젝트 루트 기준 아래 경로를 Read로 읽고 `## 역할과 입장`을 적용한다.

```
skills/venture/references/writing-rules.md
```

- 읽지 않은 상태로 정제·수치 산출을 시작하지 않는다. 이미 읽었다고 판단해 건너뛰지 않는다.
- sub-agent를 호출할 때는 `## 역할과 입장` 전문을 프롬프트에 그대로 포함한다.
- 수치는 선택 가능한 범위에서 가장 큰 값을 취하고, 근거가 부족해도 비우지 말고 산출 로직과 함께 적극적 추정치를 제시한다.

## 입력 내용

- 입력 파일: `companies/<회사>/README.md`
- 원본자료: `README.md`의 `추출 문서` 표에 기록된 `src/*.md`
- 렌더링 홈페이지: `companies/<회사>/src/homepage_rendered.md`(있으면 사용)
- 웹조사 대상: 회사 홈페이지, 공개 웹 자료, 경쟁시장, 대체재, 기술동향, 정책·보도자료, 고객·마케팅 동향
- 원본자료 정제 sub-agent 제공 내용:
  - `companies/<회사>/README.md`
  - `README.md`의 `추출 문서` 표에 기록된 `src/*.md`
  - `companies/<회사>/src/homepage_rendered.md`(있으면 홈페이지 본문 정제에 우선 사용)
  - README의 작성 방향
  - 정제 관점: 회사 개요, 주요 제품·서비스, 핵심 기술, 특허·인증, 기술이 해결하는 문제, 사업화 단서, 후속 작성에 필요한 키워드·단문·비교 포인트
- 웹조사 sub-agent 제공 내용:
  - 회사명
  - 홈페이지 URL
  - README의 작성 방향
  - 원본자료 정제 sub-agent가 반환한 주요 제품·서비스명과 핵심 기술 키워드
  - 조사 관점: 회사 홈페이지와 공개 외부 언급, 경쟁시장과 대체재, 관련 기술동향, 정책·보도자료, 고객·마케팅 동향
  - 조사 관점(후속 작성 전 항목에 활용): 웹조사 결과는 경쟁사 분석뿐 아니라 개발 배경과 필요성, 솔루션·경쟁력 확보, 기술개발 추진경과, 향후 기술개발 계획, 목표시장·고객 정의, 시장진입, 시장확대 등 phase5·6 전 항목에 활용되므로, 다음을 폭넓게 조사한다.
    - 문제·배경 근거(개발 배경과 필요성용): 사회·시장 문제의 빈도·규모·비용 통계, 규제·정책 변화, 업계 페인포인트.
    - 기술·표준 동향(솔루션·기술개발 추진경과·향후 기술개발 계획용): 관련 기술 트렌드, 표준·인증 동향, 경쟁·대체 기술의 성능·한계.
    - 시장 규모·성장(목표시장·시장확대용): 전체시장(TAM) 규모, 유효시장(SAM) 규모, 목표시장(SOM) 산출 근거, 성장률(CAGR), 인접·상위 시장 규모(직접 통계가 없을 때 추론 근거).
    - 경쟁 구도(경쟁사 분석·솔루션용): 주요 경쟁사명, 규모·점유율, 강·약점, 가격대, 대체재.
    - 시장진입·확대 근거(시장진입·시장확대용): 채널·가격·조달·정책 동향, 해외시장·수출 동향, 목표매출 산출 변수(평균 단가·객단가, 고객 수, 구매·교체 주기, 연간 발주 규모).
    - 고객 수요·반응(전 항목 공통): 검색량·수요 증가율·선호 가치, 업계 전망, 산업 동향.

## 작업 내용

- 원본자료 정제 sub-agent는 `src/homepage.md`, `src/homepage_rendered.md`, `src/SRC-*.md`에서 회사가 보유한 제품·서비스, 기술, 특허, 인증, 사업 단서를 정제한다. 렌더링 홈페이지가 있으면 본문이 더 풍부하므로 우선 활용한다.
- 원본자료 정제 sub-agent는 긴 원문을 그대로 옮기기보다 후속 작성에 바로 쓸 수 있는 키워드, 단문, 근거 단위로 정리한다.
- 원본자료 정제 sub-agent는 정보량을 줄이는 요약이 아니라, 흩어진 정보를 작성에 쓰기 좋은 형태로 정제한다.
- 원본자료 정제 sub-agent는 핵심 맥락, 기술 디테일, 시장 단서, 경쟁 비교 포인트가 사라질 정도로 뭉뚱그려 요약하지 않는다.
- 원본자료 정제 sub-agent는 정제한 내용마다 `SRC-001`, `homepage.md` 같은 확인 가능한 출처를 남긴다.
- 웹조사 sub-agent는 회사가 속한 시장, 경쟁·대체재, 기술동향, 정책·보도자료, 고객·마케팅 동향을 조사한다.
- 웹조사 sub-agent는 경쟁사와 대체재를 같은 고객 문제를 해결하는 업체·제품·대체 수단(공법·서비스 방식 등)까지 포함해 조사한다.
- 웹조사 sub-agent는 고객·마케팅 동향을 구매 동기, 사용 맥락, 선호 가치 중심으로 정리한다.
- 웹조사 sub-agent는 전체시장(TAM)·유효시장(SAM)·목표시장(SOM) 산출에 필요한 시장 규모·세그먼트 규모·성장률·정책 예산·통계·경쟁사 규모·점유·목표매출 변수(단가·고객 수·구매 주기)를 수치·출처와 함께, 후속 작성이 바로 쓸 수 있는 단위로 정리해 반환한다.
- 웹조사 sub-agent는 시장규모·경쟁사·성장률 같은 통계가 회사 내부 자료에 거의 없는 것이 일반적이므로, 회사 자료 분량과 무관하게 모든 회사에 대해 시장·경쟁·수요·정책 수치 근거를 적극적으로 폭넓게 수집한다(내부에 있으면 우선 활용하고, 없으면 웹으로 채운다). 어떤 회사도 시장 항목을 수치 없이 비워두지 않는다.
- 웹조사 sub-agent는 핵심 수치를 가능하면 복수 출처로 교차 확인하고 최신 연도를 우선하며, 직접 통계가 없으면 인접·상위 시장 통계에서 산출 로직과 함께 추정치를 마련해 반환한다.
- 웹조사 sub-agent는 조사 결과를 `출처 URL`, `출처명`, `발표 연도`, `핵심 사실(수치 포함)`, `작성 활용 포인트` 형식으로 반환한다. 정량 데이터는 수치, 출처 URL, 출처명, 연도를 함께 적는다.
- 웹조사 sub-agent는 회사가 직접 보유한 사실과 시장·업계 환경 사실을 구분해 반환한다.
- 각 sub-agent는 파일을 수정하지 않고 결과만 반환한다.
- 메인 에이전트는 두 sub-agent 결과를 통합해 회사 기술의 위치, 차별성, 경쟁력, 사업계획 작성 포인트를 도출한다.
- 메인 에이전트는 웹조사 결과를 `시장환경`에만 몰지 않고 후속 작성 전 항목이 외부 근거를 쓸 수 있게 배분한다: 문제·통계·규제는 개발 배경 근거로, 기술·표준 동향은 솔루션·기술개발 경과·향후 기술계획 근거로, 경쟁사·대체재는 경쟁사 분석·솔루션 근거로, 시장 규모·성장·채널·정책은 목표시장·시장진입·시장확대 근거로 정리한다.
- 메인 에이전트는 `후속 phase 활용 포인트`에 위 배분을 따라 각 외부 근거가 어느 작성 항목(개발 배경, 솔루션, 기술개발 경과·계획, 경쟁사, 목표시장, 시장진입·확대)에 쓰이는지 매핑해 정리한다.
- 메인 에이전트는 외부조사를 회사의 실적처럼 쓰지 않고, 시장환경 또는 경쟁환경 근거로 사용한다.
- 메인 에이전트는 명백한 오류가 아닌 내부자료와 외부조사 단서를 긍정적인 작성 활용 포인트로 정리한다.
- 메인 에이전트는 시장규모, 성장률을 `시장환경`에 정량 수치로 수록하고, 각 수치에 출처 URL·출처명·연도를 병기한다.
- 메인 에이전트는 `시장환경`에 전체·유효·목표 시장 규모 후보와 각 산출 로직(인접·상위 시장에서 좁혀온 근거 포함), CAGR, 경쟁 구도(주요 경쟁사·점유·가격), 목표매출 산출 변수(단가·고객 수·구매 주기)를 phase6의 TAM/SAM/SOM과 연차별 매출 추정에 바로 대입할 수 있는 형태로 정리한다.
- 수치 산출 규칙: ① 출처 통계를 우선 사용한다. ② 직접 통계가 없으면 인접·상위 시장 통계에서 산출 근거(로직)를 명기해 추론한다. ③ 시장규모·성장률·고객 반응은 사업계획서 관점에서 긍정적·우호적으로 산출한다. ④ 매출·계약·납품 등 회사 실적성 수치는 창작하지 않는다.
- 메인 에이전트는 맥락과 디테일이 축소되지 않았는지 확인하고 부족하면 필요한 범위에서 sub-agent 결과를 보강한다.
- 메인 에이전트는 회사 제공자료 자체의 권리관계를 제3자 시각으로 의심해 확인 필요로 분류하지 않는다.
- 메인 에이전트는 시장규모를 공란으로 `확인 필요`에 남기지 않고, 추론치와 산출 근거를 `시장환경`에 제시한다. 회사 실적관계, 성능수치처럼 산출이 불가능하고 추가 자료가 반드시 필요한 내용만 `확인 필요`에 모은다.
- 메인 에이전트는 `shared/` 디렉터리의 벤처 유형 가이드 파일을 읽고, 각 가이드에 명시된 판단 기준과 정제된 내부자료를 대조해 벤처 유형을 판단한다. 판단 결과는 `## 벤처 유형 판단` 섹션에 유형명·근거 항목별 대조·최종 확정 유형을 기록한다. 판단 결과는 phase4에서 `values.md`의 `application_type`에 반영되므로 이 단계에서 확정한다.

## 출력 내용

- 출력 파일: `companies/<회사>/distillation.md`
- README 갱신 위치: `companies/<회사>/README.md`
- `distillation.md` 구조:

```markdown
# <회사> 정제 자료

## 회사 개요

## 작성 방향

## 주요 제품·서비스

## 핵심 기술

## 특허·인증

## 외부 조사 요약

## 시장환경

## 경쟁·대체재 환경

## 기술동향

## 고객·마케팅 동향

## 회사 기술의 위치

## 차별성 작성 포인트

## 후속 phase 활용 포인트

## 벤처 유형 판단

## 출처 인덱스

## 확인 필요
```

## 사후 처리

- `README.md`의 자료 위치에 `distillation: distillation.md`를 추가한다.
- `README.md`의 진행 상태를 `venture-phase4-values`로 바꾼다.
- 핵심 정제 항목에 내부자료 출처 또는 웹 URL이 남아 있는지 확인한다.
- `시장환경`에 시장규모·성장률 정량 수치와 출처·연도가 수록되어 있는지 확인한다.
- 후속 작성에 필요한 키워드, 단문, 비교 포인트, 근거 맥락이 사라지지 않았는지 확인한다.
- 내부자료 사실과 외부 시장·업계 환경 사실이 섞여 쓰이지 않았는지 확인한다.
- 회사 제공 특허·인증·자격 자료가 불필요한 권리관계 확인 항목으로 남지 않았는지 확인한다.
