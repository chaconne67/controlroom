# 실행

## 사전 준비

- 아래 `companies/<회사>`의 `<회사>`는 `V<YYMMDD>-<한글회사명>` 형식의 회사 폴더명이다. 사용자가 한글회사명만 말하면 `companies/`에서 `V*-<한글회사명>` 폴더를 찾아 쓰고, 날짜가 다른 폴더가 둘 이상이면 임의로 고르지 말고 어느 것을 쓸지 사용자에게 확인한다.
- 회사 작업공간: `companies/<회사>`
- 입력 파일 존재 여부를 확인한다.
  - `companies/<회사>/README.md`
  - `companies/<회사>/distillation.md`
  - `companies/<회사>/values.md`
  - `companies/<회사>/texts/problem_background.md`
  - `companies/<회사>/texts/solution.md`
  - `companies/<회사>/texts/tech_progress.md`
  - `companies/<회사>/texts/tech_plan.md`
  - `companies/<회사>/texts/target_market.md`
  - `companies/<회사>/texts/competition.md`
  - `companies/<회사>/texts/market_progress.md`
  - `companies/<회사>/texts/market_plan.md`
- 출력 폴더가 없으면 생성한다.
  - `companies/<회사>/texts/`
- Markdown 파일 읽기와 쓰기는 항상 UTF-8을 명시한다.
- PowerShell에서 한글 파일을 확인할 때는 먼저 `[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)`를 실행한 뒤 `Get-Content -LiteralPath <path> -Encoding UTF8`로 읽는다.

## 작업 내용

- 메인 에이전트는 작성 sub-agent를 호출하기 전에 `자금운용`, `기업가 정신` 키포인트를 먼저 정리한다.
- 키포인트는 별도 파일로 저장하지 않고 작성 sub-agent 프롬프트에 공통 제공한다.
- 2개 작성 sub-agent를 병렬로 호출해 각 항목 초안을 작성한다.
- 각 작성 sub-agent는 자기 항목의 본문 초안만 반환하고 파일을 수정하지 않는다.
- 검사 sub-agent는 2개 초안을 함께 검토해 자금운용 계획과 기업가 정신의 연결성, 중복, 모순, 심각한 사실 오류, 명백한 창작, 작성자 방어식 표현을 점검한다.
- 메인 에이전트는 검사 결과를 확인한 뒤 최종 문구를 2개 Markdown 파일로 저장한다.

## 작문 규칙 로드

작문 규칙 정본은 아래 한 파일이다. 규칙을 이 파일에 복제하지 않는다.

```
skills/venture/references/writing-rules.md
```

- 작성·검사 sub-agent를 호출하기 전에 프로젝트 루트 기준 위 경로를 Read로 읽는다. 이미 읽었다고 판단해 건너뛰지 않는다.
- 파일 첫 절인 `## 역할과 입장`을 먼저 적용한다. 다른 모든 규칙보다 우선하며, sub-agent 프롬프트에 반드시 함께 포함한다.
- 읽지 않은 상태로 sub-agent를 호출하지 않는다.
- sub-agent 프롬프트에는 해당 절 전문을 그대로 포함한다. 요약하거나 경로만 알려주지 않는다.
- 규칙 파일의 `phase별 적용 범위` 표에서 이 phase에 해당하는 행을 확인하고 그대로 적용한다.

## 작성 sub-agent 공통 제공 내용

- 작성 규칙: 작문 규칙 파일의 `## 작문 공통 규칙` 전문
- 공통 키포인트:
  - 자금운용: 메인 에이전트가 입력 자료에서 정리한 기술개발·시장확대 실행에 필요한 자금 운용 방향
  - 기업가 정신: 메인 에이전트가 입력 자료에서 정리한 대표자 또는 회사의 사업 기회 포착, 실행, 기술사업화 의지
- 입력 자료:
  - `README.md`의 작성 방향
  - `distillation.md`의 회사 개요, 주요 제품·서비스, 핵심 기술, 특허·인증, 시장환경, 사업화 단서, 확인 필요
  - `values.md`의 기본 정보, 신청 유형, 재무·협업·자금 후보, 기술·인증·사업화 값
  - 문제해결 본문 4개
  - 시장 본문 4개
- 자금 규모·매출·투자·대출·계약·대표자 이력 수치는 작문 규칙 파일의 `## 작문 공통 규칙`의 `### 수치·근거`에 따라 확정 실적과 목표·추정을 구분해 작성하고, 추정·목표 수치는 기술개발·시장진입 실행 방향과 함께 사업계획 표현으로 제시한다.

## 항목별 작성 sub-agent 제공 내용

### funding_plan

- 출력 항목: 자금운용 계획
- 반환 내용: 자금운용 계획 본문 초안
- 항목 작성요령:
  - 문체: 작문 규칙 파일의 `## 작문 공통 규칙`의 개조식 명사형 종결을 따른다(기업가 정신 항목과 달리 서술형으로 풀지 않는다). 근거: 샘플 자금운용 계획이 개조식 명사형 + 콜론·대시 라벨 스타일임.
  - 맨 앞에 `자금 조달 수단`을 표기하고 해당하는 항목을 고른다(영업이익 / 자본금 / 투자(엔젤·VC·금융권·기타) / 정부지원(창업지원·R&D) / 대출(정책보증·시중은행)).
  - 자금조달 계획은 조달원별 또는 연차별(1~3년차) 구조로 작성하고, 각 항목에 조달 규모·조달 방법·자금 활용 계획을 함께 제시한다. 조달원별 구성 예: (1) 자금 조달 현황과 총 소요 예산(용도별 배분), (2) 정책자금·융자 조달, (3) 정부 국책 R&D 보조금, (4) 내부 유보금·매출 재투자.
  - 총 소요자금과 용도별 배분(R&D·성능인증, 시설·장비, 초기 원자재·운영자금 등), 조달원별 목표 금액을 추정·계획 수치로 명시한다.
  - 소요·조달 규모는 3년 성장 목표(`texts/target_market.md`의 연차별 예상매출)와 사업 비전에 걸맞게 적극적으로 제시한다. 현재 매출이 작아도 매출에 비례해 보수적으로 축소하지 않고, 사업 확장에 필요한 규모를 비전에 맞춰 제시한다.
  - 다만 허황돼 보이지 않도록 정합 구조는 지킨다: 용도별 배분(R&D·인증/시설·장비/운영·마케팅) 합과 조달원별 조달 합이 총 소요자금과 맞아떨어지게 구성하고, 합리성을 벗어난 터무니없는 규모만 피한다.
  - 정책자금은 기술보증기금, 중소벤처기업진흥공단, 중기부 R&D 등 회사 상황과 `distillation.md` 정책 근거에 맞는 제도를 골라 사업명과 자금 용도를 구체화한다. 회사 상황에 맞지 않으면 무리해서 특정 사업명을 넣지 않는다.
  - 자금 용도는 사업계획서 앞단의 기술개발 계획(성능 시험·인증, 부재 표준화)과 시장확대 계획(시공·공급 역량, 판로)과 연결한다.
  - 회사 설립 후 소요된 자금, 최근 3년 재무자료, 매출, 투자, 대출, 보조금 자료가 있으면 확인된 범위에서 실적으로 반영하고, 계획·추정과 구분한다.
  - `values.md`의 자금조달 방법 후보와 성장단계 후보가 있으면 본문 방향과 일관되게 반영한다.

### entrepreneurship

- 출력 항목: 기업가 정신
- 반환 내용: 기업가 정신 본문 초안
- 항목 작성요령:
  - 대표자가 새로운 사업 기회를 포착하고 사업화를 추진한 실행력을 작성한다.
  - 화자·주어(중요): 기업가 정신은 대표자가 발휘한 경험이므로, 사업 기회 포착·결단·생산요소 재조합·리스크 감수·실행의 주체를 대표자로 일관 서술한다(예: `대표 ○○○은 ~하였다`). 집단(개발진·임직원), 사물(기술력·제품), 회사명을 주어로 흩뜨리지 않으며, 회사가 보유한 실적·자산도 대표자의 실행 결과로 연결한다. 동일 주어가 이어지면 둘째 문장부터 주어를 생략해 단조로움을 피한다. 근거: 샘플 기업가 정신이 대표자(`대표자 본인은`·`저는`·`대표자는`)를 화자로 일관함.
  - 문체(중요): 이 항목은 "기업가 정신을 발휘했던 경험"을 서술하는 항목이므로, 작문 규칙 파일의 `## 작문 공통 규칙`의 개조식 명사형 종결을 적용하지 않고 완결 서술형 문장(`~하였다`, `~다`)으로 작성한다. 다른 phase 항목과 달리 이 항목에서는 서술형이 우선한다.
  - 흐름: `사업 기회 포착·과제 정의 → 생산요소(기술·인력·자본·네트워크) 재조합 → 리스크 감수와 위기 극복·실행 성과 → 사회적 가치와 성장 비전` 순으로 구성한다.
  - 구조: 개조식 압축이나 `1)2)3)` 하위 분해 대신, 위 흐름을 `1. 사업 기회 포착` 같은 번호 소제목으로 배치하고, 각 단계를 `소제목: 완결 문장 3~5개`의 스토리텔링형으로 풀어 쓴다.
  - 구체성: 각 단계에 회사의 구체 실적·수치·고유명사(매출, 특허 건수, 계약·거래처, 출시 이력, 흑자전환·재투자 규모 등)를 이야기 흐름에 녹여 서술한다.
  - 마무리: 마지막 단계 끝에 일련의 경험((1) 기회 포착, (2) 생산 요소 재조합, (3) 리스크 감수·위기 극복, (4) 지속 성장·확장)을 종합해 기업가 정신을 실질적으로 입증하고 향후 도약 의지를 밝히는 종합 문장을 둔다(괄호형 숫자 사용, 동그라미 숫자 금지).
  - 문제정의, 해결방안, 기술개발 경과, 시장진입 전략을 포괄해 기업가 정신 관점으로 연결한다.
  - 회사 고유의 강점(보유 기술, 전통·도메인 자산, 데이터·실적 등)과 시장 기회를 결합하려는 사업 방향, 기술 확보, 시장진입 준비, 품질·운영 의지를 회사 특성에 맞게 설명한다(특정 업종·사례에 한정된 표현을 쓰지 않는다).
  - 특허·연구소 설립·핵심 계약·수상 등 확보된 실행 근거를 기업가적 결단과 실행력의 증거로 연결한다.
  - 대표자 개인 이력 수치가 제한적인 경우 회사가 보유한 기술자료, 특허·인증, 사업방향을 바탕으로 기업가 정신과 사업화 의지를 작성한다.

## 검사 sub-agent 제공 내용

- 검사 규칙: 작문 규칙 파일의 `## 작문 검사 규칙` 전문
- 메인 에이전트가 정리한 공통 키포인트
- 작성 sub-agent가 반환한 2개 초안
- 초안 확인에 필요한 `distillation.md` 내용
- 초안 확인에 필요한 `values.md` 내용
- 초안 확인에 필요한 문제해결 본문과 시장 본문

## 검사 sub-agent 작업

- 자금운용 계획이 기술개발 계획과 시장확대 계획을 실행하는 방향으로 연결되는지 점검한다.
- 기업가 정신 본문이 앞선 문제해결·시장전략 본문을 포괄하는지 점검한다.
- 기업가 정신 본문이 완결 서술형 문장(`~하였다`/`~다`)으로 작성되어 있고, 4단계 흐름과 종합 입증 마무리 문장을 갖추었는지 점검한다(이 항목은 개조식 명사형 종결을 적용하지 않는다).
- 기업가 정신 본문의 화자·주어가 대표자로 일관되는지(집단·사물·회사명으로 분산되지 않는지) 점검한다.
- 항목 사이에 같은 문장이나 같은 논리가 과도하게 반복되는지 점검한다.
- 항목 사이에 자금, 실적, 계획, 대표자 정보가 서로 모순되는지 점검한다.
- 심각한 사실 오류, 명백한 창작, 벤처인증 제출문에 어울리지 않는 작성자 방어식 표현을 점검한다.
- 최종 권장 문구 2개를 반환한다.

## 출력 내용

- 출력 파일:
  - `companies/<회사>/texts/funding_plan.md`
  - `companies/<회사>/texts/entrepreneurship.md`
- 각 파일의 `char_count`는 프론트매터와 제목을 제외한 본문 글자수만 기록한다.
- 각 파일의 `source`에는 실제 사용한 근거 파일을 기록한다.
- 각 출력 파일은 아래 형식을 따른다.

```markdown
---
field_id: <field_id>
status: ready
char_count: 000
source:
  - distillation.md
  - values.md
notes:
  - 필요 시 작성 기준 또는 확인 필요 사항
---

# <항목 제목>

본문
```
