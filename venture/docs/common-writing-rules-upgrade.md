# 공통작성규칙 업그레이드 방안

## 목적

벤처인증 사업계획서 문구 작성 품질을 높이기 위해 작성 규칙과 검사 규칙을 분리한다.

현재 공통작성규칙은 금지 조항이 강하게 작동하여 작성 에이전트가 제출문보다 방어적 설명문을 작성하는 문제가 있다. 앞으로는 작성 에이전트가 심사용 제출문을 자연스럽고 설득력 있게 작성하도록 하고, 별도 검사 에이전트가 심각한 오류와 제출문에 맞지 않는 표현만 걸러낸다.

## 기본 원칙

작성 규칙은 긍정형 지침 중심으로 작성한다.

검사 규칙은 심각한 할루시네이션, 명백한 사실 오류, 제출문답지 않은 방어적 표현만 걸러내는 역할로 제한한다.

작성 에이전트에게 모든 위험을 동시에 막게 하지 않는다. 작성 에이전트는 좋은 문구를 쓰고, 검사 에이전트는 큰 오류를 잡는다.

## 작성 에이전트 지침

작성 에이전트는 벤처인증 심사자가 신청기업의 문제의식, 기술 차별성, 시장성, 실행 가능성을 빠르게 이해할 수 있도록 작성한다.

화자는 신청기업인 `당사`다.

본문은 심사 제출용 사업계획서 문장으로 작성한다.

기술은 단순 나열하지 않고 고객 문제, 기존 방식의 한계, 당사의 해결 방식과 연결해 설명한다.

차별성은 기존 방식이 무엇에 머무르고, 당사가 어떤 방식으로 해결하는지를 구체적으로 보여준다.

경쟁사가 명확하지 않으면 특정 기업명을 만들지 않고, 업계 유형이나 기존 대체 방식과 비교한다.

시장, 고객, 경쟁, 사업화 방향은 정제된 정보와 회사의 기술·서비스 범위 안에서 합리적으로 해석해 작성한다.

출처 설명, 자료 부족 설명, 작성 근거 해명, 제출 전 보완 필요 문장은 본문에 넣지 않는다.

## 작성 에이전트 프롬프트 예시

```text
벤처인증 심사자가 신청기업의 문제의식, 기술 차별성, 시장성, 실행 가능성을 빠르게 이해할 수 있도록 작성한다.
화자는 신청기업인 당사다.
본문은 제출용 사업계획서 문장으로 작성한다.
기술은 고객 문제, 기존 방식의 한계, 당사의 해결 방식과 연결해 설명한다.
경쟁사가 명확하지 않으면 업계 유형과 기존 대체 방식 중심으로 비교한다.
차별성은 기존 방식이 무엇에 머무르고, 당사가 어떤 방식으로 해결하는지 구체적으로 설명한다.
출처 설명, 자료 부족 해명, 작성 근거 변명은 본문에 넣지 않는다.
```

## 검사 에이전트 지침

검사 에이전트는 문장을 과도하게 보수적으로 죽이지 않는다.

검사 에이전트는 심각한 사실 오류와 명백한 창작만 수정 또는 확인 필요로 표시한다.

다음 내용은 수정 또는 확인 필요로 표시한다.

- 근거 없는 고유 경쟁사명
- 근거 없는 고객명, 계약, 협약, 투자, 매출, 시장규모, 성장률
- 보유하지 않은 인증, 특허, 수상, 인허가
- 기술자료와 충돌하는 성능 주장
- 회사 사업 범위를 벗어난 완전히 새로운 사업 내용
- `자료에 근거하여`, `확인되지 않아`, `제출 전 보완`, `홈페이지에서`, `자료에서`처럼 작성자가 스스로 방어하거나 출처를 설명하는 문장

다음 내용은 허용한다.

- 일반 업계 범주화
- 고객군 추정
- 기존 해결 방식 분석
- 경쟁 방식 비교
- 사업화 방향의 합리적 서술
- 확인된 특허·인증·서비스 범위에 기반한 차별성 표현

## 검사 에이전트 프롬프트 예시

```text
작성문이 벤처인증 제출문으로 자연스러운지 검사한다.
문장을 과도하게 보수적으로 죽이지 말고, 심각한 사실 오류와 명백한 창작만 걸러낸다.
없는 경쟁사명, 없는 고객명, 없는 매출, 없는 인증, 없는 계약, 없는 투자, 없는 시장규모·성장률은 수정 또는 확인 필요로 표시한다.
본문 안에 자료에 근거하여, 확인되지 않아, 제출 전 보완, 홈페이지에서, 자료에서처럼 방어적이거나 출처 설명형 표현이 있으면 제출문답게 수정한다.
일반 업계 범주화, 고객군 추정, 기존 해결 방식 비교, 기술 범위 안의 차별성 설명은 허용한다.
```

## 적용 흐름

1. 작성 에이전트가 정제된 정보와 항목 작성요령을 읽고 본문 초안을 작성한다.
2. 검사 에이전트가 본문 초안을 검토한다.
3. 검사 에이전트는 심각한 오류와 제출문답지 않은 표현만 지적한다.
4. 메인 에이전트가 최종 문구를 확정한다.

## 기대 효과

작성 문구가 방어적 설명문이 아니라 심사 제출문에 가까워진다.

근거 해명 문장이 줄어든다.

작성 에이전트가 좋은 문장을 쓰는 데 집중할 수 있다.

검사 에이전트가 큰 오류만 잡으므로 문장이 과도하게 위축되지 않는다.
