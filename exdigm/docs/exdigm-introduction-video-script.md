# 엑스다임 업무 플랫폼 소개 영상 기획·스크립트

> 작성 기준일: 2026-08-13<br>
> 권장 본편 길이: 약 5분 30초<br>
> 핵심 문장: **헤드헌터의 판단은 사람이, 반복 업무와 정보 연결은 엑스다임이.**

## 1. 영상이 전달해야 할 결론

엑스다임은 후보자 정보를 보관하는 일반적인 채용 관리 프로그램에 머물지 않는다.

이력서가 들어오는 순간부터 후보자 데이터화, 검색, 프로젝트별 추천, 진행 관리, 추천 서류 준비, 채용공고 게시, 후속 행동까지 헤드헌팅 업무의 맥락을 하나로 연결하는 **헤드헌팅 업무 운영 플랫폼**이다.

AI는 사람 대신 채용을 결정하지 않는다. 자료를 읽고, 정리하고, 후보를 좁히고, 문서를 만들고, 다음 행동을 제안한다. 후보자 선택, 고객사 추천, 발송, 탈락, 채용 결정은 담당 컨설턴트와 고객사가 맡는다.

### 한 줄 포지셔닝

> 엑스다임은 흩어진 헤드헌팅 업무를 하나의 흐름과 조직의 데이터 자산으로 바꾸는, 현장 중심의 AI 업무 플랫폼입니다.

### 추천 슬로건

1. **헤드헌팅의 모든 맥락을, 하나의 흐름으로.**
2. **데이터는 쌓이고, 판단은 빨라집니다.**
3. **AI가 준비하고, 헤드헌터가 결정합니다.**

## 2. 왜 엑스다임이 필요한가

헤드헌팅 업무의 어려움은 단순히 후보자가 부족해서 생기지 않는다. 중요한 정보와 판단의 맥락이 여러 장소에 흩어져 있기 때문에 생긴다.

### 현장의 문제

- 이력서는 이메일, 폴더, 드라이브, 채용 사이트에 흩어진다.
- 후보자의 최신 경력과 과거 접촉 기록을 다시 확인해야 한다.
- 새 프로젝트가 시작될 때마다 기존 후보자 풀을 충분히 활용하지 못하고 처음부터 검색한다.
- 고객사 JD를 해석하고 각 사이트 양식에 맞춰 공고를 다시 입력한다.
- 후보자 정보를 고객사 양식에 맞춰 추천 서류로 반복 작성한다.
- 진행 상황과 다음 행동이 개인 메모, 메신저, 기억에 남는다.
- 담당자가 바뀌면 후보자와 프로젝트의 맥락도 함께 끊길 수 있다.
- 자동화가 사람의 판단까지 대신하면 잘못된 추천이나 발송으로 이어질 수 있다.

### 엑스다임이 바꾸는 것

| 기존 업무 | 엑스다임이 만드는 변화 |
|---|---|
| 파일로 쌓이는 이력서 | 검색하고 재활용할 수 있는 후보자 데이터 |
| 키워드와 개인 기억에 의존한 검색 | 자연어 검색과 프로젝트 조건 기반 후보 추천 |
| 후보자별 진행 상황이 여러 도구에 분산 | 프로젝트 안에서 연락부터 입사 결정까지 관리 |
| 고객사별 추천 서류 반복 작성 | 후보자 데이터와 정해진 양식을 조합해 문서 준비 |
| 사이트마다 채용공고 반복 입력 | 국내 주요 사이트별 게시 자료 생성과 게시 결과 관리 |
| 개인에게 남는 업무 지식 | 회사가 함께 사용하는 후보자 풀과 업무 기록 |
| AI의 불투명한 자동 결정 | AI가 준비하고 사람이 검토·선택·실행하는 구조 |

## 3. 엑스다임의 핵심 장점

### 3.1 이력서를 조직의 데이터 자산으로 바꾼다

- 수동 업로드, 회사 이메일, Google Drive 등에서 들어온 이력서를 같은 흐름으로 관리한다.
- 이력서 원문에서 경력, 학력, 기술, 연락처 등 후보자 정보를 구조화한다.
- 이메일과 전화번호를 기준으로 동일 후보자를 안전하게 확인한다.
- 여러 이력서가 있는 후보자는 현재 대표 이력서와 최신 프로필을 관리한다.
- 사람이 직접 입력한 정보는 자동 추출값보다 우선한다.
- 후보자 데이터는 특정 프로젝트가 끝나도 회사의 공유 자산으로 남는다.

**업무 가치:** 이미 만난 후보자와 과거에 확보한 이력서가 다음 프로젝트의 출발점이 된다.

### 3.2 헤드헌터의 말로 후보자를 찾는다

- 텍스트와 음성으로 자연스럽게 검색할 수 있다.
- 헤드헌팅 용어를 실제 후보자 필드의 검색 조건으로 바꾼다.
- 사용자가 말한 필수조건은 결과가 적더라도 몰래 제거하지 않는다.
- 시스템이 추측한 숫자가 아니라 실제 데이터베이스 조회 인원수를 보여준다.

**업무 가치:** 복잡한 검색 문법을 배우지 않고도 컨설턴트가 찾고 싶은 인재상을 그대로 표현할 수 있다.

### 3.3 일반 검색과 프로젝트 적합 후보 추천을 구분한다

- 일반 후보자 검색은 컨설턴트가 원하는 조건으로 회사의 후보자 풀을 직접 탐색하는 기능이다.
- 프로젝트 추천은 JD와 프로젝트 메모를 읽고 조건을 다음 네 종류로 나눈다.
  - 절대 필수조건
  - 핵심 적합조건
  - 추가 적합조건
  - 우대조건
- 절대 필수조건을 충족하지 못한 후보만 제외한다.
- 핵심·추가·우대조건은 후보를 함부로 탈락시키지 않고 우선순위를 정하는 데 사용한다.
- AI는 조건과 이력서의 직접 증거를 확인한다.
- 최종 추천 여부와 실제 진행 후보 선택은 컨설턴트가 결정한다.

**업무 가치:** AI가 그럴듯한 후보를 단정하는 대신, 사람이 판단할 수 있는 좁고 설명 가능한 후보군을 준비한다.

### 3.4 프로젝트 안에서 후보자 한 명의 전체 흐름을 본다

- 고객사의 구인 의뢰 하나를 프로젝트로 관리한다.
- 사장은 프로젝트를 등록·할당·종료한다.
- 컨설턴트는 자신에게 할당된 프로젝트를 수행한다.
- 회사의 후보자 풀은 컨설턴트가 함께 검색한다.
- 후보자 진행은 다음 다섯 업무 지점으로 관리한다.
  - 연락
  - 사전 미팅
  - 이력서
  - 면접
  - Closing
- 실제 업무에 맞게 단계를 건너뛰거나 되돌릴 수 있다.
- 중단된 후보자 진행은 후보자를 삭제하지 않고 같은 기록에서 다시 살릴 수 있다.
- 면접 일정과 결과, 자유 메모, 할 일과 리마인더가 같은 흐름에 연결된다.

**업무 가치:** 후보자를 몇 단계에 넣었는지만 보는 것이 아니라, 지금까지 무엇을 했고 다음에 무엇을 해야 하는지 알 수 있다.

### 3.5 추천 서류 준비를 반복 작업에서 품질 관리로 바꾼다

- 후보자의 원본 이력서와 구조화된 정보를 이용해 제출용·추천 이력서를 만든다.
- 표준 양식과 고객사별 양식을 사용할 수 있다.
- 문서 생성, 저장, 업로드, 다운로드 알림이 이어진다.
- 생성된 문서는 컨설턴트가 검토한 뒤 사용한다.

**업무 가치:** 매번 내용을 옮겨 적는 시간은 줄이고, 후보자를 어떻게 소개할지 검토하는 데 집중할 수 있다.

### 3.6 국내 채용 사이트의 실제 입력 방식까지 연결한다

- 프로젝트 JD에서 외부 공개용 공고문과 사이트별 게시 자료를 준비한다.
- BusinessPeople, 엑스다임, 인크루트, 잡코리아, PeopleNJob, 사람인용 게시 경로를 갖고 있다.
- 사이트별 직무, 산업, 지역, 담당자, 공개 범위 차이를 각각 처리한다.
- 사이트별 게시, 결과 확인, 마감 상태를 프로젝트에서 관리한다.
- 사용 가능한 사이트는 운영 설정으로 켜고 끌 수 있다.

**업무 가치:** 단순히 공고문을 복사하는 것이 아니라, 국내 채용 사이트마다 다른 실제 등록 업무를 프로젝트와 연결한다.

### 3.7 직원마다 자기 업무를 이해하는 Telegram 에이전트를 둔다

- 직원 한 명과 일대일로 연결되는 별도 Telegram 업무 에이전트를 운영한다.
- 에이전트는 해당 직원의 엑스다임 계정 권한을 그대로 적용받는다.
- 필요한 데이터만 조회하고, 기존 엑스다임 화면과 같은 업무 기능을 실행한다.
- 후보자 검색, 프로젝트 조회, 문서 생성 같은 업무를 대화로 요청할 수 있다.
- 별도의 우회 업무 로직을 만들지 않고 사람이 쓰는 엑스다임 기능을 함께 사용한다.

**업무 가치:** 직원은 이동 중에도 익숙한 대화 방식으로 자기 권한 안의 업무를 이어갈 수 있다.

### 3.8 AI의 역할과 사람의 책임을 분명히 한다

엑스다임의 자동화 원칙은 다음과 같다.

| AI와 시스템이 하는 일 | 사람이 하는 일 |
|---|---|
| 읽기·추출·정리 | 원문과 결과 검토 |
| 검색 조건 해석 | 검색 의도 결정 |
| 후보 추천 준비 | 실제 진행 후보 선택 |
| 추천 서류·이메일 초안 준비 | 수정·승인·발송 |
| 미팅 전사·분석 | 반영할 내용 선택 |
| 다음 행동 제안·알림 | 적용·중단·복원·종료 결정 |

**업무 가치:** 속도를 얻으면서도 채용과 관계의 책임을 자동화에 넘기지 않는다.

## 4. 다른 헤드헌팅 업무 프로그램과의 차별점

### 비교의 전제

Bullhorn, Loxo, Recruit CRM, Access Vincere 같은 대표 제품도 ATS·CRM, 이력서 파싱, 후보자 매칭, 자동화, 공고 게시, AI 기능을 제공한다. 따라서 엑스다임의 차별점을 단순한 기능 보유 여부로 설명하면 설득력이 약하다.

엑스다임의 차별점은 **한국의 실제 헤드헌팅 조직이 자기 업무를 수행하기 위해 만든 운영 방식**에 있다.

| 비교 항목 | 대표 글로벌 ATS·Recruiting CRM | 엑스다임 |
|---|---|---|
| 제품 출발점 | 여러 국가·규모의 채용 회사를 위한 범용 플랫폼 | 엑스다임의 실제 Executive Search 업무를 위한 내부 운영 체계 |
| 핵심 강점 | 광범위한 표준 기능, 확장성, 외부 데이터와 연동 생태계 | 한국 현장에 맞춘 세부 흐름과 회사의 후보자 데이터 활용 |
| 후보자 데이터 | ATS·CRM 안에 후보자와 활동 기록을 통합 | 이메일·Drive·업로드·브라우저 수집을 현재 후보자 프로필과 연결 |
| 검색과 추천 | AI 검색·매칭·점수화 기능을 폭넓게 제공 | 일반 자연어 검색과 JD 기반 추천을 분리하고, 필수조건과 우선순위 조건의 역할을 명시 |
| 사람의 판단 | 제품별 자동화 정책과 설정에 따라 다름 | 선택·발송·적용·탈락·채용 결정은 사람에게 남기는 원칙을 도메인에 내장 |
| 프로젝트 진행 | 설정 가능한 ATS 파이프라인 중심 | 연락·사전 미팅·이력서·면접·Closing이라는 헤드헌팅 업무 지점과 되돌리기·중단·복원을 함께 관리 |
| 추천 서류 | 후보자 프로필·리포트·PDF 기능 제공 | 내부 후보자 데이터에서 표준·고객사 양식의 제출용 문서를 준비하는 업무에 집중 |
| 채용공고 | 넓은 글로벌 job board 네트워크와 연동 | 국내 주요 사이트의 실제 입력값·담당자·공개 규칙·결과 확인을 사이트별로 처리 |
| 업무 에이전트 | 내장 AI 도우미, AI agent, 모바일 앱 등을 제공 | 직원별 Telegram 에이전트가 같은 회사 계정 권한과 기존 엑스다임 업무 기능을 사용 |
| 데이터와 제품 변화 | 공급사가 정한 제품 로드맵과 표준에 의존 | 실제 컨설턴트 업무에서 발견된 문제를 같은 운영 경로에 직접 반영 |

### 정직하게 말해야 할 차이

- 엑스다임은 글로벌 제품보다 연동 범위나 표준 기능 수가 많다고 주장하지 않는다.
- 글로벌 제품도 AI 매칭, 이력서 파싱, 다중 공고 게시, AI 에이전트를 제공한다.
- 엑스다임이 내세울 강점은 **우리 회사의 업무 방식에 맞는 깊이**, **국내 채용 채널의 세부 처리**, **직원별 권한을 지키는 대화형 업무**, **사람의 판단을 보존하는 설계**다.

## 5. 기능이 만들어진 이야기

> 아래 내용은 회사의 공개 이력, 현재 업무 원칙, 실제 Git 개발 순서를 바탕으로 재구성한 영상용 서사다. 창업자나 개발 책임자의 개인적인 계기와 발언을 인용한 것은 아니므로, 공개본에서는 인터뷰로 핵심 문장 한두 개를 확인하는 것이 좋다.

### 배경: 20여 년의 헤드헌팅 경험

엑스다임은 2004년 설립 이후 외국계 기업과 국내 주요 기업의 고급 인재 채용을 수행해 왔다. 업무 플랫폼은 채용 시장을 밖에서 관찰한 개발사가 만든 범용 도구가 아니라, 실제 헤드헌팅 업무에서 반복되는 불편과 데이터 손실을 줄이기 위해 발전했다.

### 1막: 이력서 파일을 다시 쓸 수 있는 데이터로

2026년 3월 말, 후보자 모델과 이력서 텍스트 추출, Google Drive 동기화, 구조화 추출, 검수 화면이 먼저 만들어졌다.

이 순서는 제품의 첫 질문을 보여준다.

> “이미 회사 안에 있는 수많은 이력서를 다음 프로젝트에서 어떻게 다시 쓸 수 있을까?”

파일을 보관하는 데서 멈추지 않고, 후보자를 찾고 비교할 수 있는 데이터로 바꾸는 것이 출발점이었다.

### 2막: 후보자 데이터에서 헤드헌팅 업무 전체로

2026년 4월, 고객사와 프로젝트, JD 분석, 후보자 발굴, 추천, 면접, 채용 결정까지 기능이 확장됐다.

이 과정에서 중요한 원칙이 생겼다.

- 프로젝트는 고객사의 구인 의뢰다.
- 후보자 진행은 프로젝트 안에서 한 사람에게 이어지는 별도 흐름이다.
- 컨설턴트는 추천하고 고객사가 결정한다.
- 후보자는 한 프로젝트가 끝나도 회사의 공유 자산으로 남는다.

즉, 단순한 ATS 화면을 만드는 것이 아니라 실제 헤드헌팅 업무의 책임과 관계를 시스템에 옮기는 단계였다.

### 3막: 도구 사이의 반복 업무를 연결

이후 회사 이메일의 이력서 수집, 브라우저 확장 후보자 수집, 미팅 녹음 분석, 뉴스 큐레이션, 추천 이력서 생성, 채용공고 자동 게시가 연결됐다.

기능을 늘리는 것이 목적이 아니었다. 같은 내용을 이메일, 문서, 채용 사이트에 반복 입력하는 시간을 줄이고, 모든 결과가 다시 후보자와 프로젝트의 맥락으로 돌아오게 하는 것이 목적이었다.

### 4막: AI를 판단자가 아니라 동료로

2026년 7월 말에는 프로젝트 적합 후보 추천이 사람 검토 중심으로 다듬어졌다.

모든 JD 조건을 무조건 탈락 기준으로 쓰는 대신, 절대 필수조건과 적합·우대조건을 나눴다. AI는 이력서의 직접 증거를 확인하고, 코드는 정해진 기준으로 후보를 좁힌다. 최종 선택은 컨설턴트가 한다.

이 변화는 엑스다임이 AI를 사용하는 태도를 보여준다.

> “자동으로 결정하는 AI”보다 “사람이 더 좋은 결정을 내리도록 준비하는 AI”를 만든다.

### 5막: 모든 직원에게 자기 업무 에이전트를

2026년 7~8월에는 직원별 Telegram 에이전트가 엑스다임의 기존 권한과 업무 기능에 연결됐다.

새로운 별도 시스템이 업무를 흉내 내는 방식이 아니다. 웹에서 사람이 사용하는 후보자 검색과 프로젝트 업무를 같은 권한과 규칙으로 대화에서 실행한다.

엑스다임은 이제 기록 시스템을 넘어, 각 직원이 회사의 데이터와 업무 방식을 안전하게 활용하도록 돕는 운영 파트너로 발전하고 있다.

### 0:00–0:25 — 오프닝: 헤드헌팅 업무의 현실

**화면**

- 이메일 첨부 이력서, 여러 폴더, 스프레드시트, 채용 사이트 탭, 메신저 알림이 빠르게 겹친다.
- 한 컨설턴트가 같은 정보를 여러 화면에 반복 입력한다.
- 화면이 멈추고 질문이 나타난다.

**화면 문구**

> 좋은 후보자를 찾는 일보다, 흩어진 정보를 다시 찾는 일이 더 많아지고 있지 않습니까?

**내레이션**

> 헤드헌팅의 핵심은 사람을 이해하고, 기업과 인재의 가능성을 연결하는 일입니다. 하지만 실제 하루는 이력서를 찾고, 정보를 옮기고, 진행 상황을 확인하고, 같은 내용을 다시 입력하는 일로 쉽게 흩어집니다.

### 0:25–0:55 — 문제 정의: 정보가 아닌 맥락의 단절

**화면**

- 선으로 이어지려다 끊기는 애니메이션.

**화면 문구**

- 이력서는 파일로
- 진행 상황은 개인 메모로
- 후보자 경험은 담당자의 기억으로

**내레이션**

> 문제는 정보가 없는 것이 아닙니다. 정보가 서로 연결되지 않는 것입니다. 이력서는 파일로 남고, 후보자와 나눈 대화는 개인에게 남고, 프로젝트가 끝나면 그 경험을 다음 업무에서 다시 쓰기 어렵습니다.

**화면**

**내레이션**

**화면 문구**

**내레이션**

**화면 문구**

**내레이션**

**내레이션**

## 8. 영상 제작 시 표현 지침

### 반드시 강조할 표현

- “AI가 준비하고 사람이 결정한다.”
- “후보자 데이터가 프로젝트를 넘어 회사의 자산으로 남는다.”
- “헤드헌팅 현장에서 나온 업무 흐름이다.”
- “일반 검색과 프로젝트 적합 추천이 구분된다.”
- “직원별 에이전트가 같은 권한과 기존 업무 기능을 사용한다.”

### 피해야 할 표현

- “AI가 최적의 후보를 자동으로 결정합니다.”
- “채용 전 과정을 완전 자동화합니다.”
- “한 번의 클릭으로 고객사 발송까지 모두 끝납니다.”
- “다른 채용 프로그램에는 AI나 자동 게시 기능이 없습니다.”
- “모든 국내 채용 사이트에 항상 자동 게시됩니다.”
- 확인되지 않은 시간 절감률, 정확도, 매출 증가율, 고객 성공 수치

### 추천 화면 캡처 순서

1. 후보자 이력서 업로드와 구조화된 상세 화면
2. 자연어·음성 후보자 검색
3. 프로젝트 적합 후보 추천과 사람의 선택
4. 후보자 진행 카드와 다섯 업무 지점
5. 추천 이력서 생성·다운로드
6. 사이트별 채용공고 게시 상태
7. 직원별 Telegram 에이전트 대화
