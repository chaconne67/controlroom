# FundKeeper 수동계좌 잔고 반영

수동계좌 자료에서 전체 잔고를 추출하고 현재 운영 DB와 비교한 뒤, 사용자가 승인한 값만 원자적으로 반영한다. FundKeeper 실행 환경과 공통 안전 경계는 `fundkeeper` 스킬을 함께 따른다.

## 최종 경로

1. 입력 자료와 대상 고객을 확정한다.
2. 전체 보유 종목·현금·계좌 평가액을 추출하고 합계를 검증한다.
3. 운영 DB를 읽기 전용으로 조회해 현재값과 승인 후보를 비교한다.
4. 변경·신규·삭제 항목을 사용자에게 제시하고 명시적 승인을 기다린다.
5. 승인된 전체 잔고를 하나의 `transaction.atomic()` 안에서 동기화한다.
6. DB를 다시 조회해 승인값과 일치하는지 검증하고 결과를 보고한다.

승인 전에는 DB를 변경하지 않는다. 승인 뒤 입력값이나 대상 계좌가 달라지면 비교표부터 다시 만들고 새 승인을 받는다.

## 입력 완전성 확인

다음 자료가 한 시점의 전체 잔고를 구성하는지 먼저 확인한다.

- 요약: 총 적립금 또는 최종 적립금
- 현금성 자산: 원리금보장형 등 현금으로 반영할 금액
- 보유 종목 전체: 종목명, 적립금, 수익률, 좌수, 기준가

표시된 총 종목 수, 페이지 수 또는 다른 완결성 단서로 전체 자료임을 확인한다. 일부 페이지만 제공됐거나 누락 여부를 판단할 수 없으면 기존 종목을 삭제하거나 DB를 갱신하지 않는다.

고객명으로 `ClientAccount.objects.filter(fkuser__name=...)`를 조회하되 결과가 없거나 둘 이상이면 계좌 PK·계좌번호·회사·용도 등으로 대상을 확정한다. 계좌를 추정하지 않는다.

대상 계좌에 `ClientCash`가 둘 이상 있거나 같은 `Asset`의 `ClientTicker`가 중복돼 있으면 잔고 반영을 중단하고 현재 상태를 보고한다. 이 스킬에서 중복 행을 임의로 합치거나 삭제하지 않는다.

## 추출과 계산

- `qty`: 화면의 좌수
- 종목 평가액: 화면의 적립금
- `r`: 화면 수익률을 소수로 정규화한 값 (`5%`는 `0.05`, `-5%`는 `-0.05`)
- `avg_price`: `기준가 / (1 + r)`
- `ClientCash.value`: 현금성 자산 적립금의 원 단위 정수
- `ClientAccount.value`: 요약 화면의 총 적립금 또는 최종 적립금

`avg_price`는 누적 가중평균을 유지하지 말고 잔고를 반영할 때마다 위 공식으로 다시 계산한다.

각 종목에서 `qty × 기준가`와 표시된 적립금이 화면 반올림 범위에서 맞는지 확인한다. 전체 `종목 평가액 합계 + 현금`이 계좌 평가액과 맞는지도 확인한다. 부호·단위·수익률 표기가 모호하거나 합계가 설명되지 않으면 중단하고 사용자에게 원자료 확인을 요청한다.

## 모델과 종목 매칭

| 모델 | 역할 | 갱신 필드 |
|---|---|---|
| `myaccount.models.ClientAccount` | 수동계좌 | `value` |
| `myfriends.models.ClientCash` | 계좌 현금 | `value`, 국내 원화 자료이면 `currency='krw'` |
| `myfriends.models.ClientTicker` | 보유 종목 | `ticker`, `qty`, `avg_price` |
| `simulation.models.Asset` | 종목 정본 | 조회만 수행 |

6자리 종목 코드가 있으면 `Asset.objects.get(ticker=...)`로 일치시킨다. 코드가 없으면 `description__icontains`로 후보만 찾는다. 후보가 없거나 둘 이상이면 임의로 선택하거나 새 `Asset`을 만들지 말고 사용자에게 확인을 요청한다.

## 승인 비교표

운영 DB의 대상 `ClientAccount`, 관련 `ClientCash`, 전체 `ClientTicker`를 읽기 전용으로 조회한다. 다음 항목을 현재값과 승인 후보로 나눠 제시한다.

- 계좌 PK와 식별 정보
- 계좌 평가액과 현금
- 유지·변경·신규·삭제 종목
- 각 종목의 코드, 수량, 평균단가
- 자료 합계 검증 결과

삭제 종목도 승인 대상에 명시한다. 사용자가 승인하기 전에는 Django shell의 저장·수정·삭제 코드를 실행하지 않는다.

## 원자적 동기화

승인 후 원격 FundKeeper 가상환경의 Django shell에서 다음 작업을 하나의 `transaction.atomic()` 블록으로 실행한다.

1. 승인된 각 종목을 계좌와 `Asset` 기준으로 `update_or_create`하여 `qty`와 `avg_price`를 맞춘다.
2. 기존 종목 중 승인된 전체 종목 코드 집합에 없는 항목을 삭제한다.
3. `ClientCash`가 없으면 생성하고 하나이면 `value`와 국내 원화 자료의 `currency`를 갱신한다.
4. `ClientAccount.value`를 갱신한다.

자료가 전체 세트가 아니면 2단계를 포함한 어떤 DB 변경도 실행하지 않는다. 실행 중 한 항목이라도 실패하면 전체 변경을 롤백하고 성공으로 보고하지 않는다.

## 재조회 검증

같은 계좌를 다시 조회해 다음 값이 승인표와 모두 같은지 확인한다.

- 종목 코드 집합
- 각 종목의 `qty`와 `avg_price`
- 현금과 통화
- 계좌 평가액

불일치가 있으면 완료로 보고하지 않는다. 승인값, 실제 저장값, 실패 원인을 구분해 보고한다.
