# 리밸런싱 주문·체결 확인 분리 구현 계획

## 결론

- 공식 실행 경로는 `xmodules/order/order.py` 하나만 유지한다.
- `--order_flow inline`은 현재 종목별 주문·체결 방식을 그대로 사용한다.
- `--order_flow split`은 신규 래퍼 클래스를 선택한다.
- 기존 `OrderHelper`, `OrderKR`, `OrderUS` 메서드 본문과 주문 API는 변경하지 않는다.
- 국내와 미국의 `a`, `o`, `sellall` 주문에 모두 적용한다.

## 명령 계약

```bash
python xmodules/order/order.py \
  --mode real \
  --ex kr \
  --action a \
  --run_type p \
  --order_flow split
```

| 옵션 | 값 | 의미 |
|---|---|---|
| `--order_flow` | `inline` | 기존 방식. 종목별 주문 뒤 해당 종목 체결을 확인한다. |
| `--order_flow` | `split` | 계좌 안의 모든 종목을 순차 접수한 뒤 체결을 일괄 확인한다. |
| `--run_type` | `p` | 계좌를 병렬 처리한다. |
| `--run_type` | `s` | 계좌를 순차 처리한다. |

- `split`이 기본값이며, 기존 종목별 방식을 쓰려면 `--order_flow inline`을 명시한다.
- `split`은 국내·미국 `action=a`, `action=o`, `action=sellall`에 적용한다.
- `action=m`, `action=v`, `action=verify`는 주문이 없으므로 기존 클래스를 사용한다.

## 현재 최종 경로

1. `parse_cli_args()`
2. `get_accounts()`
3. `order()`
4. `MakePortfolio.force()`
5. `OrderKR` 또는 `OrderUS`
6. `get_adj_order_df()`
7. `계좌별일괄주문()`
8. 종목별 `건별주문()`
9. 같은 종목의 `건별체결확인()`
10. 완전 체결 후 다음 종목 주문

- `run_type=p`는 계좌만 병렬 처리한다.
- 한 계좌 안에서는 종목별 주문과 체결 확인이 묶여 있다.

## 변경 후 단일 최종 경로

1. 기존 `parse_cli_args()`가 `--order_flow`를 읽는다.
2. 기존 `order()`가 같은 파일의 주문 클래스 선택 함수만 호출한다.
3. `inline`이면 기존 `OrderKR` 또는 `OrderUS`를 그대로 선택한다.
4. `split`이면 신규 `SplitOrderKR` 또는 `SplitOrderUS`를 선택한다.
5. 신규 클래스는 기존 클래스를 상속하고 기존 메서드를 조합한다.
6. 별도 runner나 별도 실행 파일은 만들지 않는다.

## split 계좌별 실행 순서

1. 기존 `get_adj_order_df()`로 실제 잔고와 목표 수량 차이를 계산한다.
2. 기존 `계좌별일괄주문()`으로 해당 방향의 모든 종목을 순차 접수한다.
3. 래퍼가 주문 직후 호출되는 체결 확인만 일시적으로 가로채 주문번호를 수집한다.
4. 모든 주문 접수가 끝나면 기존 `건별체결확인()`을 종목별로 호출한다.
5. 미체결 종목이 있으면 1초 후 다시 확인한다.
6. 30초 안에 미체결이 0건이면 실제 잔고를 다시 읽는다.
7. 30초가 지나면 미체결 종목만 기존 `건별취소()`로 취소한다.
8. 취소 직전에 체결되어 취소 대상이 없으면 성공으로 처리한다.
9. 전 종목의 미체결 주문이 사라진 것을 확인한다.
10. 기존 `get_adj_order_df()`로 주문 수량을 갱신한다.
11. 남은 수량이 있으면 2번부터 재주문한다.
12. 남은 수량이 없으면 해당 계좌의 해당 매매 방향을 종료한다.

## 계좌와 매매 방향

- 계좌는 기존 `병렬처리()`를 사용한다.
- 한 계좌 안의 종목은 기존 `계좌별일괄주문()` 순서대로 접수한다.
- 주문번호 수집 상태는 `threading.local()`로 계좌 스레드마다 분리한다.
- `action=a`는 모든 계좌의 매도 완료 후 기존과 같이 3분 기다리고 매수를 시작한다.
- `action=o`는 지정한 한 방향에 같은 흐름을 적용한다.
- `action=sellall`은 전량 매도에 같은 흐름을 적용한다.

## 기존 메서드 재사용

| 업무 | 기존 메서드 | 신규 래퍼 역할 |
|---|---|---|
| 실제 잔고 기준 수량 계산 | `get_adj_order_df()` | 반복마다 다시 호출 |
| 주문 목록과 순서 | `계좌별일괄주문()` | 그대로 호출 |
| 가격·매수 가능 수량·주문 접수 | `건별주문()` | 체결 대기만 일시 가로채기 |
| 체결 확인 | `건별체결확인()` | 전체 접수 후 반복 호출 |
| 주문 취소 | `건별취소()` | 반환 형태와 취소 경쟁만 정규화 |
| 계좌 병렬 | `병렬처리()` | 계좌 단위 작업만 전달 |

## 최소 코드 원칙

- 국내·미국 공통 흐름은 mixin 하나에만 둔다.
- 기존 주문 목록 생성, 가격 계산, 주문 접수, 체결 확인, 취소 코드를 복제하지 않는다.
- 시장별 신규 코드는 기존 미체결 조회의 서로 다른 인자를 연결하는 두 메서드만 둔다.
- 기존 실행 흐름과 연결하는 변경은 CLI 옵션과 주문 클래스 선택 함수로 제한한다.
- 같은 기능을 수행하는 별도 runner, API, 보정 경로를 만들지 않는다.

## 미국 시장

- NASDAQ·NYSE·AMEX 주문에 모두 적용한다.
- 체결 확인은 기존 `OrderUS.건별체결확인()`을 호출한다.
- 기존 미국 미체결 조회의 `NASD` 값은 미국 전체 시장 조회이므로 그대로 사용한다.
- 미체결 확인과 취소는 기존 `targetOrderToCancel()`과 `건별취소()`를 그대로 호출한다.
- 신규 미국 API 구현은 추가하지 않는다.

## 실패 조건

- 취소 후 미체결 0건을 확인하지 못하면 재주문하지 않는다.
- 기존 `max_retry=30`을 계좌·매매 방향별 반복 상한으로 사용한다.
- 반복 상한 뒤에도 남은 수량이 있으면 해당 계좌를 실패 처리한다.
- 취소 요청이 실패해도 다시 조회했을 때 대상 주문이 없으면 체결 경쟁으로 보고 무시한다.

## 수정 범위

### `xmodules/order/order.py`

- 신규 mixin과 `SplitOrderKR`, `SplitOrderUS`를 추가한다.
- `parse_cli_args()`의 `--order_flow` 기본값은 `split`이다.
- 주문 클래스 선택 함수를 추가한다.
- 기존 클래스 직접 생성 지점만 선택 함수 호출로 바꾼다.
- 기존 주문 메서드 본문은 수정하지 않는다.

### `order/test_order_split.py`

- 신규 래퍼 전용 테스트만 추가한다.
- 기존 `order/tests.py`는 작업 전 상태로 유지한다.

### 변경하지 않는 파일

- `simulation/api.py`
- `simulation/tools.py`
- 기존 주문·체결·취소 API 구현

## 자동 테스트

1. `inline`이 기존 주문 클래스를 선택하는지 검사한다.
2. 10개 주문이 체결 확인보다 먼저 모두 순차 접수되는지 검사한다.
3. 계좌는 병렬이고 계좌 내부 종목은 순차인지 검사한다.
4. 1초 간격 확인과 30초 타임아웃을 검사한다.
5. 미체결 종목만 취소하는지 검사한다.
6. 취소 대상 없음 오류를 무시하는지 검사한다.
7. 미체결 0건 전에는 수량 갱신·재주문하지 않는지 검사한다.
8. 실제 잔고로 수량을 갱신한 뒤 남은 종목만 재주문하는지 검사한다.
9. 국내·미국이 같은 실행 순서를 지키는지 검사한다.
10. 미국 NASDAQ·NYSE·AMEX를 실제 거래소별로 확인하는지 검사한다.
11. `a`, `o`, `sellall`이 split 클래스를 사용하는지 검사한다.
