## 데이터 생산과 비식별화 계약

공식 경로: Exdigm 서버의 SELECT 전용 연결 → 관계를 보존한 대상 선정 → 같은 내부 환경에서 비식별 산출물 생성 → 검사 → main의 ZiiN 전용 DB/파일에 반입. 원문 개인정보를 main이나 조정실로 옮기지 않는다.

기존 `scripts/debug_workspace.sh`는 반복읽기 읽기전용 연결, 프로젝트 참조 후보자 우선 선정, 테이블 분류 누락 거부, 후보자/이력서/파일 관계 검사를 제공한다. 그러나 `COPY SELECT *`는 실제 값을 복사하므로 기존 refresh는 실행하지 않고 선정/관계 원칙을 재사용한다.

- schema/migrations와 FK 관계는 유지하되 실제 인물·직원·채용고객사 식별값은 일관된 시연값으로 바꾼다.
- 허용하지 않은 자유 본문, JSON, 원문/문서, 사진, URL, Drive ID, 전화/메일, 메모, 계약 상세가 그대로 나가면 실패한다.
- 정제한 구조화 정보로 시연용 이력서 원문/파일을 만들고, 같은 공식 문서 생성 진입점의 ZiiN 파일 resolver로 읽는다. 원본 Drive 접근을 필요로 하지 않게 한다.
- 실제 비밀번호/세션/외부 계정/토큰/통지 대기열은 복사하지 않는다. 시연 사용자 로그인은 새로 발급한다.
- 파생 검색 데이터와 생성 파일은 정제한 데이터에 맞춰 생성한다. 원래 임베딩/검색 캐시를 그대로 공개하지 않는다.
- 데이터 개수만 맞춘 성공은 인정하지 않는다. 관계 무결성, 화면 조회, 검색, 실제 문서 생성·다운로드에서 정제값만 사용되는지 확인한다.
- 시연 초기 데이터는 신규 도입사 생성 기본값과 분리한다. 시연 데이터를 다른 회사에 자동 복제하지 않는다.

## 최소 구현·공식 경로

최소 구현 게이트: 2단계에서 멈춤 — 기존 Django 업무 앱·서비스·모델·마이그레이션·화면·FileSystemStorage·Gemini 호출을 재사용한다. 필요한 추가는 tenant 설정/표시, 정제 데이터 export/import, 로컬 이력서 원문 resolver, ZiiN 배포/검증이다. 기존 source 검색에서 tenant runtime/비식별 export는 없고 개발용 raw COPY만 확인했다. 새 의존성을 우선 추가하지 않는다.

요청은 기존 Django URL/view → 업무 서비스 → ZiiN DB/로컬 파일/선택 Gemini로 흐른다. 회사 설정은 배포 단위에서 주입한다. 이력서 생성은 기존 `prepare_resume_source_text`의 파일 읽기 책임에서 선택된 저장소를 사용하고 이후 공식 파이프라인을 유지한다.

### 중간 확인

- 전용 PG 컨테이너와 비공개 업무 web을 생성했다. 기존 공개 연결은 아직 변경하지 않았다. 모든 Exdigm migrations가 전용 DB에 성공했다. `manage.py check` 통과, 내부 `/health/`·로그인·favicon·manifest 200, web healthy.
- 실제 컨테이너 경로 `/app`에서 source `uv.lock`을 고정 적용했다. main의 기본 `docker0` 장치가 없어 첫 빌드가 네트워크 초기화에서 실패했으며, Docker/공유망을 고치지 않고 빌드에만 `--network=host`를 사용해 성공했다. 앱은 전용망을 사용한다.
- 기존 랜딩 28개 테스트를 네트워크 없는 임시 컨테이너·메모리 SQLite·기존 개발용 DEBUG 설정으로 검증했다. 처음 운영 설정 그대로 실행한 테스트는 HTTPS 리다이렉트 때문에 실패했으며, 기존 테스트의 요구와 코드 기대값은 변경하지 않았다.
- ZiiN tenant 설정에서 기존 후보자/이력서/지원 진행/JD/대시보드 54개 테스트 통과. 신규 원문 backend 등의 에이전트 테스트는 통합 재검증 예정이다.
- 기존 ZiiN 키와 `gemini-3.7-flash`의 실제 짧은 응답을 확인했다(79 tokens). Exdigm 키·외부 회사 계정은 미사용.
- 후보자 신규 이력서 업로드가 Drive 의존인 직접 소비자를 발견했다. 실제 업로드→정보 추출→DB 반영도 동작하게 원문 backend에 저장 책임을 연결하고 기존 `resume_uploader` 작업자를 별도 ZiiN 서비스로 추가한다. 이는 별도 신규 업무 기능이 아니라 기존 업로드 경로의 저장소 연결이다.
- Nginx 후보 설정은 기존 www 블록을 보존하고 bare HTTPS 블록만 업무 upstream으로 바꾸며, 별도 임시 컨테이너의 `nginx -t`에서 통과했다. 실제 Nginx 설정은 아직 미반영이다.
