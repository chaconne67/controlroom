## 1. 히어로 — 확정

```
[헤드라인]  당신이 퇴근한 후에도
            지니는 당신을 위해 일합니다.

[서브]      지니는 단순한 챗봇이 아닙니다.
            헤드헌팅 업무를 처리하는 AI 동료입니다.
```

**왜 이 문장인가.** 사장이 읽는 문장이다.

- **퇴근한 후에도** — 직원은 퇴근하면 회사가 멈춘다. 사장만 아는 답답함이다
- **일합니다** — 검색해준다·정리해준다가 아니라 일한다. 차별점이 동사 하나에 들어 있다
- **당신을 위해** — 사장 귀에는 "내 회사를 위해"로 들린다

검색기는 밤에 일할 게 없다. 경쟁 프로그램이 못 쓰는 문장이다.

서브가 "네가 아는 그 프로그램이 아니다"를 못 박는다.

---

## 2. 개요 — 사장 머릿속 질문 세 개

히어로를 읽은 사장이 던지는 질문 순서가 이 순서다.

1. 일한다고? **무슨 일을?**
2. 그래서 **우리 회사가 뭐가 달라지는데?**
3. 근데 **우리 직원들이 쓰겠어?**

한 섹션이 한 질문에 답한다. 개요 구역은 라벨을 붙이지 않는다. 큰 문장만 간다.

### 개요 ① — 무슨 일을 하는데 · 검토 필요

```
[헤드]  업무가 2배 빨라집니다.
        지루한 일은 지니에게 맡기고
        더 중요한 일에 집중하세요.

[서브]  이력서 만들고, 공고 쓰고, 사이트마다 올리고.
        그거 하느라 하루가 갑니다.
```

**화면.** 헤드헌터의 업무 목록에서 네 줄에 선이 그어지고 하나만 남는다. 남는 것은 사람을 만나고 판단하는 일이다.

목록은 화면이 보여주고 글은 다른 말을 한다. 그림이 한 말을 글이 또 하면 둘 다 죽는다.

### 개요 ② — 먼저 연락하면 이긴다 · 검토 필요

```
[헤드]  경쟁사가 공고문을 작성하고
        게시물을 하나씩 올리고 있을 때
        당신은 먼저 후보자에게 연락하세요.

[서브]  속도가 경쟁력입니다.
        JD를 받고 공고문 작성에서 사이트 게시까지 5분이면 충분합니다.
```

**화면.** 같은 시간축 위에 두 줄. 위는 경쟁사가 사이트를 하나씩 올리는 중, 아래는 이미 통화 중.

사장 언어로 번역하면 속도 = 성사율 = 매출이다. 세 섹션 중 지갑에 가장 가깝다.

### 개요 ③ — 배울 게 없다 · 확정

```
[헤드]  새로 배울 것도, 복잡하게 설정할 것도 없습니다.
        동료에게 말하듯 시키세요.

[서브]  안 쓰는 기능은 없는 기능입니다.
        기능에 업무를 맞추지 않고 업무에 기능을 맞췄습니다.
        헤드헌터 20년의 전문성으로 인공지능을 훈련시켰습니다.
```

**화면.** 왼쪽에 탭 열두 개짜리 설정 화면(전부 흐릿하게), 오른쪽에 말풍선 한 줄.

사장이 프로그램 도입을 접는 이유 1위는 성능이 아니라 "사놨는데 아무도 안 쓴다"다. 이걸 기능 설명 앞에서 끄지 않으면 아래 내용이 소용없다.

## 3. 페인 → 지니가 해결

기능 설명으로 바로 넘어가지 않는다. 아픈 데를 먼저 짚고 그 자리에 지니를 놓는다. 그래서 별도의 기능 섹션이 없다. **페인 섹션이 곧 기능 섹션이다.**

**페인 구역에는 라벨을 붙인다.** 라벨이 없으면 무슨 업무 얘기인지 알 수 없다. 개요 구역과 눈으로도 갈린다.

순서는 **짜증 → 공포 → 미래**다.

| 순서 | 섹션 | 사장이 느끼는 것 |
|---|---|---|
| 페인 ① | 제출용 이력서 | 매일 겪는 짜증 |
| 페인 ② | 채용공고 게시 | 등골 서늘한 사고 |
| 페인 ③ | 이력서 데이터 | 회사의 앞날 |

이력서 데이터가 기초공사라 제일 중요하지만 후킹이 약하다. 앞에 두면 지루하고, 맨 뒤에 두면 "그래서 이게 다 쌓여서 회사 자산이 된다"는 마무리가 된다.

### 페인 ① — 제출용 이력서 · 확정

```
[라벨]  제출용 이력서

[헤드]  이력서 고치다가 하루가 갑니다.

[페인]  시켰더니 이상하게 만들어 옵니다. 고치고, 또 고치고.
        후보자한테 양식 주면서 부탁해도 다들 제멋대로 보내옵니다.
        빠진 항목 있어 전화하면 안 받고, 톡 남기면 몇 시간.

[지니]  후보자가 보낸 이력서도 제각각, 문서 작업하는 사람도 제각각. 결과도 제각각.
        이제 이런 건 지니에게 시키고 사람만 할 수 있는 더 중요한 일을 하세요.
```

"제각각" 세 번이 리듬을 만든다.

### 페인 ② — 채용공고 게시 · 확정

```
[라벨]  채용공고 게시

[헤드]  공고에 고객사 이름이 그대로 올라갔습니다.

[페인]  연봉도, 고객사 이름도 나가면 안 됩니다.
        경력 있는 컨설턴트는 알지만 신입은 모릅니다.

        사이트마다 넣는 자리가 다르고, 항목도 다르고, 포맷도 다릅니다.
        여섯 곳을 하나씩 손으로 올립니다.

        사람이 하면, 한 번은 실수합니다.

[지니]  JD 하나 넣으면 사이트별 양식에 맞춰 지니가 만듭니다.
        나가면 안 되는 건 애초에 들어가지 않습니다.
        사람은 확인만 하시면 됩니다.
```

속도는 개요 ②에서 이미 했다. 여기는 사고 쪽이다. 사장이 더 무서워하는 게 그쪽이다.

핵심은 "애초에 들어가지 않습니다"다. 실수를 잡아내는 게 아니라 실수할 자리를 없앤다.

"사람이 하면 실수합니다" → "사람은 확인만 하시면 됩니다"로 대구가 생긴다.

### 페인 ③ — 이력서 데이터 · 확정

```
[라벨]  이력서 데이터

[헤드]  고객사가 찾는 딱 맞는 후보,
        당신이 쌓아놓은 이력서 더미에 숨겨져 있지는 않나요.

[페인]  사이트에서 후보자 한 명 열어보는 데도 돈이 나갑니다.
        그렇게 돈 주고 모은 이력서, 지금 어디 있나요?

        후보자는 헤드헌팅 회사의 유일한 자산입니다.

[지니]  쌓아놓기만 한 이력서, 당장 써먹을 데이터로 만드세요.
        이제부터 이력서는 지니가 받습니다. 놓치지 않고 모읍니다.

        원본은 클라우드에, 내용은 항목별로 쪼개 데이터로.
        같은 사람이 또 보내면 최신 걸로 갱신하고 이전 것도 남깁니다.

        데이터가 쌓인 만큼 회사도 성장합니다.
```

**존량과 유입 둘 다 답해야 한다.** 헤드라인이 "쌓아놓은 더미"를 묻는데 들어오는 메일 얘기만 하면 답이 안 된다.

| | 사장이 듣는 것 |
|---|---|
| 쌓인 것 디비화 | 도입한 다음 날부터 쓸 게 생긴다 |
| 앞으로 자동 수집 | 앞으로 관리 안 해도 된다 |

앞엣것이 구매 결정을 앞당긴다. 유입만 말하면 "우리 것부터 다 넣어야 되는 거 아니야, 그거 언제 다 해"가 남는다.

**화면.** 화살표 두 개가 같은 곳으로 들어간다.

- 굵고 짧은 화살표 — 쌓인 더미. 한 번에, 도입할 때
- 가늘고 계속되는 화살표 — 메일. 매일, 자동으로

## 4. 실화 — 검토 필요

**위치: 페인 섹션이 끝난 뒤, CTA 바로 앞.**

```
[라벨]  지인은 여기서 시작했습니다

        이력서가 10만 장 쌓였는데 찾을 수가 없었습니다.
        윈도우 탐색기가 너무 느려서 애플 노트북을 따로 샀습니다.
        맥은 파일 안 글자까지 찾아주니까요.

        그래도 "반도체 공정 10년, 영어 되는 팀장급"은 못 찾았습니다.

        어느 헤드헌팅 회사 대표 이야기입니다.
        지인은 그 자리에서 시작했습니다.
```

**왜 여기인가.** 개요 ③이 "헤드헌터 20년의 전문성으로 훈련시켰습니다"라고 주장만 하고 끝난다. 증거가 없다. 이 스토리가 그 증거인데, 페인을 다 읽고 "맞아 맞아" 한 다음에 나와야 힘이 실린다. 그리고 버튼 바로 앞이 신뢰가 제일 높은 자리다.

**"어느 헤드헌팅 회사 대표 이야기입니다."** 이 줄이 장치다. 여기까지 읽고 나서야 "어, 나잖아"가 된다. 앞에서 밝히면 남 얘기로 읽힌다.

스토리는 짧아야 한다. 길어지면 페이지가 늘어진다.

## 5. CTA — 확정

```
오늘부터 지니와 함께 일해 보세요

     [ 도입 문의 ]
```

버튼 문구는 **도입 문의** 하나로 통일한다. 상단 바·히어로·마지막 세 곳이 같아야 한다. 경쟁하는 버튼을 옆에 두지 않는다.

헤드라인은 히어로의 "당신이 퇴근한 후에도"를 **오늘**로 받는다. 부탁하지 않고 사실처럼 말한다.

## 6. 아직 안 정한 것

- **보이스 지시를 어디에 넣을지.** 개요 ③에서 이미 말했으니 아래에서는 페인 없이 화면 녹화 영상 한 편으로 보여주는 쪽이 낫다
- **기타 기능 8개 처리.** 카드 여덟 장이 아니라 목록 한 판
  - 대시보드 캘린더 / 후보자 관리 워크스페이스 / 통화 녹음 업로드·자동 정리 / 일정 관리 / 업무 프로세스 / 고객사 등록·관리 / 뉴스피드 / 레퍼런스(대학 티어표·대기업 리스트)
- **개요 ①②** 최종 확인

## 7. 디자인 방침

**그래픽적 아름다움이나 예술적 감각이 목표가 아니다. 메시지가 잘 보이는 것이 목표다.**

### 가독성 — 제일 중요

- 본문 **18~19px**. 보통 웹은 16px인데 읽는 사람이 40~50대 사장이다. 키운다
- 행간 **1.8**. 한글은 라틴보다 빽빽해 보인다
- 한 줄 **30~40자**에서 끊는다. 화면 폭을 다 쓰면 눈이 줄을 놓친다
- `word-break: keep-all`. 없으면 단어 중간에서 줄이 끊긴다

### 깔끔함

- 폰트 **2종만**. 본문은 하나로
- 한 화면에 메시지 **1개**. 두 개면 둘 다 안 남는다
- 색은 배경·글자·강조 **3개**. 강조색은 화면의 5% 미만
- 카드·박스·테두리를 남발하지 않는다. 여백으로 나눈다

### 이미지

- 장식용 이미지를 넣지 않는다. **그 섹션 메시지를 보여주는 것만** 넣는다
- 없으면 비운다. 채우려고 넣은 그림이 제일 촌스럽다

## 8. 문구 쓸 때 지킬 것

AI가 쓴 티가 나면 거부감이 든다. 아래 세 가지가 특히 걸린다.

- **개수를 세지 않는다.** "네 가지를", "세 가지 방법" — 사람은 말할 때 개수를 안 센다. 목차 쓰는 버릇이다
- **번역투를 쓰지 않는다.** "~을 가져갑니다", "~을 제공합니다"
- **명사만 늘어놓지 않는다.** 장면이 없으면 읽고 나서 남는 게 없다

그리고 없는 경쟁자를 만들지 않는다. 사장들 머릿속에 없는 칸을 부정하면 없던 의심이 생긴다.
