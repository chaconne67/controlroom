# Agent Client 프로토타입 기본기획 — Windows 설치형

작성일: 2026-09-23 · 근거: [통합 에이전트 서비스 구상 v0.2](통합-에이전트-서비스-구상-2026-09-23.md) 13절 1~2단계

## 1. 목적

Windows PC에 설치해 쓰는 데스크톱 앱으로 다음 두 가지를 확인한다.

1. **디자인**: 실제 대화에서도 "예쁘고 오래 읽어도 편하다"가 느껴지는가
2. **메모리**: 다음 작업에서 "그 얘기를 다시 안 해도 되네"를 경험하는가

요금제·커뮤니티·일반 사용자용 관리형 서비스·모바일은 이번 범위가 아니다.

## 2. 기술 선택

| 부분 | 선택 | 이유 |
|---|---|---|
| 화면 | 기존 시제품(메인서버 `rndlog/telegram_miniapp/frontend`)의 Vite + JavaScript 코드 재사용 | Markdown 정제·코드 강조·말풍선 구조·스트리밍 수신이 이미 있음 |
| 앱 포장 | Tauri 2, Windows 설치 파일(NSIS `.exe`·`.msi`) | Windows 내장 WebView2 사용으로 가벼움. 이후 macOS·모바일로 같은 방식 확장 |
| 에이전트 | 메인서버 기본 Hermes API (`/v1/chat/completions`, SSE 스트리밍) | 미니앱이 이미 같은 API로 동작 중 |
| 메모리 | Hermes에 이미 연결된 GBrain(스킬·CLI 경유)을 그대로 사용 | 새 메모리 시스템을 만들지 않음 |
| 접속 | SSH 터널 `localhost:8642 → main 172.30.31.128:8642` | 공개 주소를 열지 않음 |
| API 키 | 앱의 Rust 쪽이 Windows 자격 증명 관리자에 보관·사용 | 화면 코드와 설정 파일에 키가 남지 않음 |

Electron은 추가 설치가 필요 없지만 설치 크기가 커서 "가벼움" 기준에 맞지 않아 제외했다.

## 3. 개발 환경 (2026-09-23 확인)

- 있음: Node 24, npm 11, WebView2
- 설치 필요: Rust(rustup), Visual Studio 2022 Build Tools의 C++ 데스크톱 작업 항목

## 4. 만드는 순서

1. 개발 도구 설치
2. 빈 앱 설치 확인: 기존 시제품 화면을 Tauri로 감싸 설치 파일을 만들고, 이 PC에 설치해 실행
3. 대화 화면: 답변 전체 너비, 요청 약 3분의 2 폭 말풍선, `#FDFDFD / #202020 / #339CFF`, 읽기·코딩·야간 프리셋과 자간·행간 조절
4. Hermes 연결: 앱 내부에서 대화 전송·실시간 수신, 이전 대화 이어쓰기
5. 메모리 표시: 답변에 쓰인 기억을 펼쳐 보기. **Hermes API가 GBrain 조회 과정을 화면에 넘겨주는지 미검증**이므로 이 단계 첫 작업으로 확인
6. 실사용: 며칠간 실제 업무에 사용하고 불편한 점 기록

## 5. 만들지 않는 것

- 가입·로그인·결제·요금제, QR 초대·기기 해제
- 모바일·macOS 빌드, 앱스토어 제출
- 적응형 표현 AI
- 기존 Telegram 미니앱·RNDLOG·Hermes·GBrain 설정 변경

## 6. 코드 위치와 공유

- 코드: 조정실 `agent-client/app` (Windows PC 로컬)
- controlroom `.gitignore`가 `agent-client/docs`만 공유하므로 app 코드는 현재 Git 공유 대상이 아니다. 공유가 필요해지면 `.gitignore` 변경을 별도로 결정한다.
- 원본 미니앱 코드는 복사만 하며 원본은 수정하지 않는다.

  - 화면
    - 상단 줄: 연결 상태, 새 대화, 설정
    - 사용자 말풍선 최대 66.7%
    - 입력창 포커스: 둥근 테두리 강조로 통일
    - 전송 버튼: 대비를 맞춘 진한 파랑 `#0B6FD6`
  - 설정 패널: 오른쪽에 열리고, 대화가 옆에 그대로 보여 변경 즉시 미리보기
    - 프리셋 3가지
      - 읽기: 17px / 1.70 / -0.012em / 820px
      - 코딩: 15px / 1.60 / 0 / 1040px
      - 야간: 어둡게, 나눔고딕코딩, 17px / 1.75 / -0.004em
    - 본문 글꼴: 함초롬돋움·맑은 고딕·나눔바른고딕·나눔고딕코딩
    - 글자 크기·행간·자간·본문 폭·테마 조절, 기본값 복원
  - 연결
    - 앱이 `ssh -L 127.0.0.1:8642:172.30.31.128:8642`를 창 없이 실행하고, 앱 종료 시 닫는다.
    - API 키는 Windows 자격 증명 관리자(`agent-client`)에만 저장한다. 화면 코드로는 SSE 본문만 전달한다.
    - 키가 없으면 "연결 전 · 예시 응답", 키가 있으면 실패를 실제 오류로 표시한다.
    - 매 전송 전에 터널을 확인해, 끊겼으면 다시 연다.
  - Telegram 전용 코드와 그 테스트 4개를 삭제했다. 전송 경로·새 대화·화면 설정 테스트 6개를 추가해 15/15 통과.
  - 실제 화면 확인
    - 예시 대화와 세 프리셋의 즉시 반영
    - 가짜 키로 터널 개통 → "API 키가 맞지 않습니다" 표시, 전송 시 같은 오류(예시 응답으로 대체하지 않음)
    - 키 삭제 후 "연결 전" 복귀
    - 앱 종료 시 ssh 종료
  - 코드 리뷰: 터널이 끊긴 뒤 재연결하지 않는 결함 1건을 수정했다. 재리뷰에서 finding 없음.
  - **미검증**: 실제 키로 Hermes 답변 스트리밍. 사용자가 설정 화면에서 키를 직접 입력한 뒤 확인한다.
  - 다음: 실제 대화 확인 → 5단계 메모리 표시(Hermes가 GBrain 조회 과정을 스트림으로 주는지 먼저 확인).
