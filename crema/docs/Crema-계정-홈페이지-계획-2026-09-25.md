# Crema 계정·홈페이지 계획 — 구글 로그인과 crema-agent.site

작성: 2026-09-25 · 상태: **검토안(승인 전)** · 순서: 이 계획 → [엔진 통합 마스터플랜](Crema-엔진-통합-마스터플랜-2026-09-25.md)

## 1. 의도와 성공

**요청(2026-09-25).**
- 메인서버에 Crema DB를 만들고 구글 로그인을 붙인다.
- Crema를 설치하면 구글 로그인을 먼저 하고 나머지 설치 과정으로 넘어간다.
- `crema-agent.site`에 아주 간단한 홈페이지를 만든다. 구성은 Django + nginx + PostgreSQL이며 다른 프로젝트 방식을 따른다. 디자인은 Mobbin에서 참고한다.
- 로고·앱 아이콘은 기존 시안 C(크레마 말풍선)를 쓴다. 조정실에 `crema` 프로젝트를 둔다.

**결정.**
- 코드는 같은 `chaconne67/crema` 저장소의 `server/` 폴더에 둔다.
- 로그인은 "처음 한 번 계정 연결"이다. 이후 서버가 잠시 안 돼도 앱은 계속 쓴다.
- 조정실 `agent-client`를 `crema`로 이름을 바꾼다.
- 이 계획을 엔진 통합보다 먼저 한다.

**성공.**
1. `https://crema-agent.site`가 열리고, 로고·한 줄 소개·다운로드 버튼·개인정보처리방침·이용약관이 보인다.
2. 홈페이지에서 구글로 로그인하면 내 계정(이메일, 로그아웃, 계정 삭제)이 보인다.
3. Crema 첫 실행 → "구글로 시작하기" → 브라우저에서 구글 로그인 → 앱으로 돌아오며 로그인 완료 → 다음 설정 단계로 넘어간다.
4. 앱을 다시 켜면 로그인을 다시 묻지 않는다. 서버가 잠시 멈춰도 앱은 동작한다.
5. 다른 제품(ceoloan·rndlog·ziin 등)의 운영에 영향이 없다.

## 3. 설계

### 서버 (`server/`, Django)
- 화면: 홈(로고, 한 줄 소개, 다운로드 버튼), 로그인, 내 계정, 개인정보처리방침, 이용약관. 모두 한 장짜리 단순한 페이지다.
- 다운로드 버튼은 GitHub 최신 릴리스의 `Crema-setup-x64.exe`로 연결한다(릴리스는 계속 CI에서만 만든다).
- 계정: 구글 로그인만 둔다. 저장하는 것은 구글 계정 식별자, 이메일, 이름, 가입·최근 로그인 시각뿐이다. 대화 내용은 서버에 보내지 않는다.
- 앱 연결: 앱 전용 토큰을 발급하고 서버에는 해시로만 저장한다. 조회(`/api/me`)와 해지(로그아웃, 계정 삭제 시 전부 해지)를 둔다.
- 구글 로그인 구현은 먼저 다른 제품에 쓰는 방식이 있는지 확인해 재사용하고, 없으면 Django 표준 라이브러리 수준의 최소 구현 또는 널리 쓰는 패키지 하나를 쓴다(최소 구현 게이트로 판단).

### 앱 첫 실행
1. 로그인 정보가 없으면 첫 화면에 "구글로 시작하기"만 보인다.
2. 누르면 기본 브라우저가 `crema-agent.site`의 앱 로그인 주소로 열린다.
   - 앱은 이 PC 안에서만 받는 일회용 주소(루프백)를 함께 넘긴다.
3. 구글 로그인이 끝나면 서버가 앱 토큰을 일회용 주소로 돌려준다.
   - 앱은 토큰을 Windows 자격 증명 관리자에 저장한다.
   - 데스크톱 앱 로그인의 표준 방식(RFC 8252, 루프백 리디렉션 + PKCE)이다.
4. 이어서 설정 단계로 간다. 지금은 Hermes 연결을 확인하고, 엔진 통합 뒤에는 엔진 시작과 Provider 로그인을 한다.
5. 이후 실행에서는 저장된 토큰이 있으면 바로 들어간다. 서버 확인은 뒤에서 하며, 실패해도 막지 않는다. 토큰이 해지되었을 때만 다시 로그인한다.

### 디자인
- Mobbin에서 단순한 앱 다운로드 랜딩을 몇 개 골라 참고한다.
- 색은 로고 팔레트를 쓴다: 에스프레소 `#3B2418→#1A0F0A`, 크레마 `#F6D19A→#D99A55→#9A5527`, 크림 `#F5EBDD`.
- 글꼴은 Pretendard다(2026-09-25 주인님 요청으로 나눔고딕에서 변경, jsDelivr 공식 가변·동적 서브셋).

### 조정실
- `agent-client`를 `crema`로 이름을 바꾸고 기존 문서와 아이콘을 옮긴다.
- `crema/AGENTS.md`·`CLAUDE.md`를 ziin 형식으로 새로 둔다. 코드 위치(PC `~/projects/crema`, main `~/projects/crema`), GitHub, 도메인, 배포 정의, DB, 격리 밖 설치 규칙을 적는다.
- 프로젝트 목록(`windows-control-projects.tsv`)과 `.gitignore` 공유 규칙을 갱신한다.

## 5. 단계
1. 조정실 `crema` 전환(이름 변경·지침·목록) → `kitpush`
2. 서버 코드(`server/`): 화면, 구글 로그인, 앱 토큰 API, 테스트. 로컬 또는 main에서 테스트 통과
3. 메인서버 준비: DB·계정, 비밀값 파일, Compose 정의, edge 설정, 인증서 추가(기존 제품 영향 없음을 먼저 확인)
4. 배포와 확인: 실제 도메인에서 홈페이지·로그인·내 계정 확인, 기존 14개 공개 주소 정상 확인
5. 앱 첫 실행 로그인: 로그인 화면, 루프백 수신, 토큰 저장, 재실행 유지. 깨끗한 Windows CI는 로그인 없이 가능한 부분까지만 확인하고, 실제 구글 로그인은 이 PC에서 격리 밖 실행으로 확인
6. 앱 아이콘을 시안 C로 교체하고 릴리스(0.1.2) → 이어서 엔진 통합 계획

## 6. 보존과 위험
| 항목 | 대응 |
|---|---|
| 다른 제품 운영 | edge 설정은 새 `server` 블록만 추가하고, 재읽기 전에 설정 검사를 한다. 14개 공개 주소를 전후로 확인한다 |
| 공용 DB | 새 DB·계정만 만들고 기존 DB 권한은 바꾸지 않는다 |
| 비밀값 | Git·로그·출력에 넣지 않는다. 구글 값은 주인님이 직접 입력한다 |
| CI에서 구글 로그인 검증 불가 | 로그인 앞뒤 흐름(루프백 수신·토큰 저장·재실행)은 서버 쪽 테스트용 토큰으로 검증하고, 실제 구글 로그인은 이 PC에서 확인 |
| 서버 장애 시 앱 | 로그인 뒤에는 서버 없이도 동작한다(첫 로그인만 서버 필요) |

## 7. 확인하지 못한 것
- 다른 제품에 재사용할 구글 로그인 코드가 있는지
- 일일 백업이 새 DB를 자동 포함하는지(설계상 포함, 첫 백업 뒤 확인)
- 인증서 중앙 갱신에 새 도메인을 더하는 정확한 절차(`renew-certificates.sh` 확인 필요)
