# crema 제품 기획 (초안)

2026-09-25 · 상태: 방향 검토용 초안 · 숫자(가격·용량)는 모두 검증 전 가정

## 1. 한 줄 정의

**내 PC와 클라우드에서 함께 일하는, 일반 사용자용 개인 AI 에이전트.**
PC가 켜져 있으면 PC를 직접 다루고, 꺼져 있어도 클라우드에서 24시간 일을 이어 간다. 데스크톱·모바일 앱 어디서나 같은 대화와 기억으로 이어진다.

## 2. 풀려는 문제

| 문제 | 지금 겪는 모습 | crema의 답 |
|---|---|---|
| 에이전트가 무겁고 복잡함 | Hermes는 범용이라 메신저 어댑터·클라우드 샌드박스·음성·플러그인 59개 등 안 쓰는 기능이 많음. 설치·설정·관리 지점이 많음 | 쓰는 기능만 남긴 경량 코어. 설치 한 번, 설정 최소 |
| PC가 꺼지면 멈춤 | 로컬 에이전트는 PC를 24시간 켜 둘 수 없고, 외출 중엔 연결 안 됨 | 클라우드 실행 위치를 함께 둠. PC가 꺼져 있어도 예약 작업·웹 작업·대화는 계속 |
| 외부 메신저 인터페이스의 한계 | 텔레그램 등은 그 메신저 형식(버튼·길이·서식)에 맞춰야 해서 기능이 깎임 | 자체 데스크톱·모바일 앱이 기본 창구. 메신저는 선택 연결 |
| 일반 사용자에게 어려움 | 설정 파일, API 키, 터미널 로그인, 게이트웨이 재시작 | 앱 안에서 로그인·Provider 추가·권한 선택까지 끝남(현재 Agent Client에서 이미 만든 부분) |

## 3. 핵심 차별점

가장 중요한 경쟁력은 **쉬움과 읽기 좋음**이다. 다들 "누구나 쉽게"를 말하지만 실제 제품은 자기들만 아는 말, 맥락 없는 이름, 누르면 무엇이 일어날지 모르는 버튼으로 가득하다. crema는 이것을 실제로 해낸다.

0-1. **정말 쉬운 인터페이스 (UX 원칙)**
   - 이름은 하나의 대상에 하나만 쓴다. 앱 전체에서 같은 말은 같은 뜻이다(용어집으로 관리).
   - 버튼 이름만 보고 누른 뒤 일어날 일을 정확히 예상할 수 있어야 한다. 다음 동작이 그 이름대로 이어지는지, 오해할 여지가 없는지 버튼마다 점검한다.
   - 사용자가 공부해야 알아듣는 말(개발 용어, 내부 이름)을 화면에 쓰지 않는다. 기준은 "처음 보는 사람도 바로 안다".
   - 새 화면·기능마다 문구 점검을 완료 조건에 넣는다(지금 Agent Client에서 해 온 문구 점검을 제품 규칙으로).
0-2. **편집자가 다듬은 답변 (응답 인터페이스)**
   - 대부분의 에이전트는 모델이 뱉은 글을 그대로 보여 준다. crema는 잡지·출판 편집자의 눈으로 답을 편집해 내보낸다.
   - 편집 원칙(스타일 가이드): 결론 먼저, 짧은 문단, 의미 있는 줄바꿈, 핵심만 굵게(한 문단 한두 곳), 셋 이상은 목록, 비교는 표, 긴 답은 제목으로 구역, 코드·경로는 코드 서식, 아이콘·이모지는 뜻을 더할 때만(장식 금지).
   - 구현 단계
     1. 지시문: 답을 쓸 때 스타일 가이드를 따르게 한다(지금 `REPLY_FORMAT_INSTRUCTION`으로 시작함 — 지시 전후 같은 질문에서 굵게·제목·표가 0개 → 구조화됨 확인).
     2. 전용 표시 요소: 요약 카드, 주의·팁 상자, 단계 목록, 파일·명령 카드처럼 앱이 예쁘게 그리는 블록을 정하고 모델이 그 문법으로 쓰게 한다.
     3. (선택) 후편집: 긴 답을 가벼운 모델이 한 번 더 편집. 품질은 오르지만 지연·비용이 늘어 긴 답이나 사용자가 요청할 때만.
   - 편집 품질은 같은 질문 묶음으로 전후를 비교해 측정한다(굵게 과다, 문단 길이, 목록·표 사용, 읽기 시간).

1. **하이브리드 실행**: 한 에이전트가 두 곳에서 일한다.
   - 로컬 노드(PC): 파일·프로그램·브라우저 등 PC 제어. PC가 켜져 있을 때.
   - 클라우드 노드(서버): 예약 작업, 웹 조사, 알림, 모바일 대화. 24시간.
   - 일은 필요한 곳으로 간다. PC가 필요한 일은 PC가 켜질 때까지 기다리거나(대기열), 사용자에게 알린다.
2. **어디서나 하나의 대화·기억**: 데스크톱·모바일·웹이 같은 대화, 같은 기억, 같은 설정을 본다.
3. **가벼움**: 필요한 기능만. 설치 파일과 실행 자원이 작고, 고장 지점이 적다.
4. **쉬운 시작**: API 키 하나 또는 포함 크레딧으로 바로 시작. 위험한 명령은 앱 안 승인 카드로 묻는다.
5. **덜 쓰는 토큰**: 같은 일을 더 적은 비용으로. 프롬프트 캐시, 긴 대화 압축, 도구 결과 요약, 가벼운 일(제목·예상 입력 등)은 싼 모델로 보내기. 사용자가 자기 키로 쓰든 크레딧으로 쓰든 비용이 줄어드는 것이 눈에 보이게 한다(대화별 사용량·절약량 표시).

## 4. 구조

```
[데스크톱 앱]  [모바일 앱]  [웹]   (선택: 텔레그램 등)
       \           |          /
        \          |         /
      [crema 클라우드: 계정 · 동기화 · 중계 · 클라우드 노드]
              |  (PC가 바깥으로 여는 연결 — 포트 개방 불필요)
      [로컬 노드: 사용자 PC 위 crema 코어]
```

- **crema 코어**: Hermes 포크를 줄인 에이전트 엔진. 로컬 노드와 클라우드 노드가 같은 코어를 쓴다.
- **클라우드 서비스**
  - 계정·기기 관리
  - 대화·기억·설정 동기화
  - 중계: 모바일에서 PC로 명령을 전달. PC가 먼저 서버에 연결을 열어 두는 방식이라 공유기 설정이 필요 없음
  - 클라우드 노드 실행
- **보안 원칙**
  - PC 제어는 기기 등록과 로그인이 된 경우에만 합니다.
  - 위험 명령은 승인 요청을 기본으로 합니다.
  - 모든 원격 실행은 기록을 남깁니다.
  - 대화 저장은 암호화합니다. 가능하면 종단 간 암호화를 씁니다.

## 5. 경량화: 무엇을 남기고 무엇을 뺄까

원칙: **추측으로 빼지 않는다.** 기능 목록 → 실제 사용 기록 → 제거 순서. 뺀 기능은 선택 설치(확장)로 돌릴 수 있게 한다.

| 구분 | 남김(1차 후보) | 뺌 또는 확장으로(1차 후보) |
|---|---|---|
| 에이전트 | 대화 루프, 도구 호출, 승인, 세션·기억, 예약 작업 | 봇 모드, 칸반, TUI, 멀티 프로필 |
| 모델 | 구독 로그인 Provider(주요 몇 개), API 키 Provider | 드문 Provider, MoA |
| 도구 | 파일, 터미널, 웹 검색·읽기, 브라우저 제어, 이미지 생성 | 원격 샌드박스(modal·daytona·vercel), 음성 호출어(wake) |
| 연결 | 자체 앱 API(지금의 `/v1/runs` 계열) | Slack·Matrix·WeCom 어댑터(텔레그램은 선택 확장) |
| 기타 | 설정 백엔드(앱이 쓰는 부분만) | 대시보드 웹 UI, 쓰지 않는 플러그인 |

- 포크 운영: "원본 + 작은 수정 묶음"으로 시작해, 원본 업데이트를 따라가며 줄여 간다. 수정이 커지는 부분(API·승인·세션)부터 crema 고유 모듈로 분리한다.
- 라이선스: Hermes는 MIT. 저작권·라이선스 고지 포함, "Hermes" 이름·로고는 쓰지 않음("Hermes Agent 기반" 표기는 가능). 의존성 중 MPL-2.0(certifi 등)·LGPL(선택 기능)은 고지 및 조건 준수.

## 6-1. 배포·수익화 방법 (제안)

핵심 원칙: **돈은 서버에서 받는다.** 로컬(무료) 기능은 가볍게 풀고, 비용이 드는 클라우드 기능에 과금한다. 서버가 판단하는 기능이라 불법 복제로 뚫리지 않고, 원가와 요금이 같은 곳에서 생긴다.

### 배포 경로

| 플랫폼 | 권장 경로 | 이유 |
|---|---|---|
| Windows (1순위) | 자체 웹사이트 직접 다운로드 + 자동 업데이트(Tauri updater, 서명된 업데이트) | 비용·심사 없음, 업데이트 주기 자유 |

|---|---|---|

### 공개 전략: 오픈 코어

- 로컬 앱과 코어(Hermes 포크)는 소스를 공개하고, 클라우드 서비스(동기화·중계·클라우드 노드)는 유료 서비스로 운영한다.
- PC를 제어하는 앱은 "무엇을 하는지 볼 수 있다"는 신뢰가 중요하다. 소스 공개가 설치 장벽을 낮추고, 돈은 서버 쪽에서 받으므로 수익에 손해가 적다.
- 반대 선택(전부 비공개)도 가능하다. Hermes가 MIT라 포크를 비공개로 운영해도 라이선스상 문제는 없다.

| ChatGPT 구독 로그인 | "Sign in with ChatGPT"는 2026-04 기준 Codex 도구 안에서만 제공, 제3자 앱용 공식 제도는 관심 신청 단계 | 제도가 열리기 전에는 기반으로 삼지 않는다. 열리면 공식 방식으로 붙인다 |
| 게이트웨이(OpenRouter 등) | 토큰 값은 모델사 원가 그대로, 충전 시 수수료 5.5%(최소 $0.80). 사용자 키 연결(BYOK)은 월 $25,000까지 무료 | 여러 모델을 한 계정·한 청구로 공급하는 가장 빠른 길 |
| 사례: Raycast | 월 $10 Pro에 모델 포함, $20·$50 등급은 크레딧 제공, BYOK도 지원 | "포함 크레딧 + BYOK" 병행이 시장에서 통함 |
| 사례: TypingMind | 앱 한 번 구매($39~99) + 사용자 API 키 | "앱값만 받고 모델비는 사용자가 직접" 모델 |

### crema의 공급 방식 (제안)

1. **BYOK(자기 API 키)**: 모든 등급 기본. 합법·명확, 우리 원가 없음. 대신 "키 발급이 어렵다"는 장벽을 앱 안 안내로 낮춘다.
2. **포함 크레딧**: 플러스·프로에 모델 사용을 묶어 판다. 우리가 API(직접 또는 게이트웨이)로 사서 원가+마진으로 제공. 키가 없는 일반 사용자의 시작 장벽을 없앤다.
3. **공급처**: 초기에는 게이트웨이 한 곳으로 여러 모델을 공급(계약·청구 단순). 사용량이 커지면 주요 모델사와 직접 계약·볼륨 할인으로 원가를 낮춘다.
4. **개인 구독 연결(선택 기능)**: 사용자가 자기 구독(ChatGPT·Claude·Grok 등)을 직접 연결해 쓰는 기능은 제공한다. 단, 수익 구조의 기반으로 삼지 않는다.
   - 현실 판단(주인님, 2026-09-25): 공식 문서상 금지·미허용이지만, 경쟁 구도(OpenAI·Anthropic·Grok·중국 오픈 모델) 때문에 실제로는 제3자 오픈소스 에이전트의 구독 연결을 막지 않고 있다. ChatGPT는 처음부터 제재가 없었고 Grok도 묵인, Anthropic은 컴퓨팅 부족 시기에 차단했다가 자원 확보 후 사실상 풀었다고 봄(외부 게시글 기반, 문서로는 미확인).
   - 개인이 연결하는 것과 제품이 기능으로 제공하는 것은 위험 크기가 다르다. 정책이 바뀌면 제품은 유료 사용자 전체의 핵심 기능이 한 번에 멈추고, 공식 문서가 금지 대상으로 적은 "다른 제품·서비스"에 정면으로 해당한다.
   - 그래서: ① 연결 시 "모델사 약관에 따라 제한될 수 있음"을 한 번 분명히 안내하고 사용자가 선택, ② 유료 등급의 가치는 클라우드·모바일·토큰 절약·UX·편집된 답변에 둠, ③ 모델사별로 구독 연결을 서버에서 즉시 끄고 API 키·크레딧으로 옮기라고 안내하는 스위치, ④ 구독 연결의 인증 오류·차단 비율을 집계해 정책 변화를 먼저 감지.

- 차별점은 공급 방식이 아니라 **토큰 절약·쉬운 UX·편집된 답변**에 둔다. BYOK 사용자에게도 "crema로 쓰면 같은 일이 더 싸고 보기 좋다"가 이유가 되게 한다.
- 지금 개인용 프로토타입은 Claude·ChatGPT 모두 구독 로그인(OAuth)으로 연결되어 있다(2026-09-25 확인). 개인 사용은 주인님 판단으로 유지한다.
