# IROS 등기부 추출

## 역할과 경계

이 스킬은 IROS 고유 절차와 결과 계약을 제공한다. 브라우저 자동화와 사용자 화면 비간섭의
일반 원칙·구현은 `$web-automation`에 맡긴다.

이 스킬에 범용 대기, 클릭, 입력, 세션 복구, 브라우저 수명주기, 다운로드 처리법을 복사하지
않는다. 스킬이 수집을 실행하는 것도 아니다. 스킬은 하나의 공식 SSP를 만들고 검증하기 위한
도메인 지침이며, 실제 실행과 체크포인트 저장은 스크립트가 담당한다.

## 공식 SSP

- 코드 정본은 CEO Loan 저장소의 `scripts/iros_ssp.py`다.
- 실행 명령은 이 파일의 `property`, `validate`, `status`, `collect`만 사용한다.
- `scripts/iros_dom.py`와 `scripts/iros_batch.py`는 각각 IROS 화면 절차와 배치 상태 저장을 맡는
  내부 모듈이며 별도 실행점으로 사용하지 않는다.
- Windows 실행본은 같은 세 파일을 `C:\cretop-agent`에 둔다. 배치 실행기도
  `iros_ssp.py collect`만 호출한다.
- 좌표 기반 구경로, 후보별 브라우저 재기동, 사전검색 뒤 같은 부동산을 다시 검색하는 경로,
  별도 복구 CLI를 추가하지 않는다.

배치는 사람이 작업하듯 한 전용 Chrome과 한 로그인 세션을 유지한 채 후보를 순서대로
처리한다. 홈에 보이는 실제 로그아웃 링크로 로그인 상태를 확인하고, 로그아웃 상태이면 한 번
정상 로그인한 뒤 같은 기준으로 확인한다. 본문의 `로그아웃` 문자열만으로 인증을 판정하거나
추측성 새로고침·강제 로그아웃·반복 재로그인을 하지 않는다.

## IROS 도메인 경로

정상 경로는 다음 하나다.

1. 로그인된 홈을 확인한다.
2. 주소를 도로명 주소로 정규화해 검색한다.
3. 표시 주소의 건물번호 경계까지 일치하는 결과가 정확히 한 행인지 확인한다. 주어진 경우
   부동산 종류와 고유번호도 함께 일치해야 한다.
4. `열람`, `말소사항포함(전부)`, 주민등록번호 `미공개`를 선택한다. 요청받은 공동담보·매매목록·
   신탁원부 같은 첨부는 해당 부동산 고유번호와 첨부 식별번호가 확인된 행만 선택한다.
5. 결제 대상이 선택한 부동산 한 건, 열람 한 통, 700원인지 확인하고 승인된
   `선불전자지급수단`으로 결제한다.
6. 신청결과의 미열람 또는 재열람 목록에서 같은 고유번호의 행을 연다.
7. 등기 뷰어가 요청하는 PDF를 저장하고 등기 고유번호를 다시 확인한다.
8. PDF를 구조화해 `표제부`, `갑구`, `을구`가 순서대로 존재하는지 검증하고 PDF와 registry
   JSON 경로를 결과에 남긴다.

검색 결과가 없거나 여러 건이면 결제 전 후보 제외로 처리할 수 있다. 첫 행이나 비슷한 주소를
대신 선택하지 않는다. 이미 결제된 건의 `view-only`는 해당 결제 기록이 확인된 PDF 재수령에만
사용하며, 신규 결제 경로를 우회하거나 자동 복구 수단으로 사용하지 않는다.

## 결제와 재개 경계

- 배치는 고정 manifest와 그 해시를 승인한 approval을 먼저 검증한다.
- 결제 직전 `payment_started`, 승인 확인 직후 `payment_confirmed`를 원자적으로 기록한다.
- `payment_started`, `payment_confirmed`, `payment_unknown`, `paid_unresolved` 또는 결제 상태
  `unknown`이 남으면 브라우저를 열거나 추가 결제하지 않고 사람이 확인할 수 있게 멈춘다.
- 완료 수, 확정 결제 수, 불명 결제 수와 승인된 건수·총액 한도를 매 후보 전에 확인한다.
- 결제 확인 뒤 PDF나 구조 검증이 실패해도 같은 부동산을 자동 재결제하지 않는다.
- 비밀번호, 선불번호, 쿠키, 토큰, CAPTCHA 값은 로그·요약·오류 증거에 남기지 않는다.

## 스크립트와 에이전트의 역할

확정된 화면과 오류는 스크립트에 한 번만 구현해 같은 공식 경로에서 처리한다. 아직 발생하지
않은 화면을 가정한 예외 분기와 범용 복구 트리를 만들지 않는다. 알려지지 않은 실제 화면이나
비정형 오류가 발생하면 마지막 성공 단계, 실패 단계, 비밀값을 제거한 화면 증거를 남기고
멈춘다. 그때만 `$web-automation`으로 실제 화면을 조사하고 에이전트나 언어모델이 의미를
판단한다. 해결이 검증되면 우회 도구를 남기지 말고 같은 `iros_ssp.py` 경로에 최소 변경으로
통합한다.

CAPTCHA·OTP·추가 인증이 실제로 나타나면 일반 우회 코드를 만들지 않는다. 현재 작업의 실제
화면에서 필요한 사람 수준의 입력만 수행하고 값은 기록하지 않는다.

## 완료 조건

다음이 모두 확인돼야 완료다.

1. 요청 주소와 선택한 부동산 고유번호가 정확히 일치한다.
2. 결제했다면 승인 범위 안의 한 건 700원이며 결제 상태가 확정이다.
3. 결과 PDF와 registry JSON이 실제로 존재한다.
4. registry가 정상이고 고유번호와 `표제부`, `갑구`, `을구`가 PDF와 일치한다.
5. 배치라면 목표 완료 수, 확정 결제 수, 불명 결제 0건, 승인 총액 한도를 모두 만족한다.
6. 완료 또는 중단 상태와 마지막 체크포인트가 고정 state에 보존된다.
