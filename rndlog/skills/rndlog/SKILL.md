# RNDLOG 연구 설계·기록 작성 서비스

AR Shift의 RNDLOG는 현업에 바쁜 기업을 대신해 연구 주제를 구체화하고, 연구 수행과 기록 관리,
실사 및 세무 증빙 준비를 돕는 서비스다. 고객의 연구소 신고 내용·사업·특허를 출발점으로 국내외
연구를 조사해 실행할 만한 과제와 일정을 설계하고, 고객이 수행·보완·확인할 문서를 작성한다.
자료의 완전성을 심사해 제작을 거절하는 서비스가 아니다. 확인할 수 없는 이름·인정번호 같은 사실은
입력란으로 남기고, 시간·참여율·비용 같은 계산값은 합리적인 추정값으로 채워 조사·설계·작성을
계속한다. 제작 완료와 고객의 사실 확인·제출 준비 완료는 구분한다.
고객은 수치와 내용이 채워진 실제 문서 형태를 보고 최종 검토·판단한다. 이 검토 목적을 이유로
문서에 초안·확인용 표지나 반복 안내를 붙이지 않는다.

## 작업 위치와 근거

- 현재 조정실에서 자료 수집·기획·제작을 판단한다. 회사 자료·산출물 정본과 공통 자원의 실제 SSH 서버·자료 루트는 프로젝트 `AGENTS.md`의 정본 표와 `docs/WORKSPACE.md`를 따른다. 코드 저장소 루트를 고객자료 루트로 사용하지 않는다.
- 회사별 `companies/<정식 회사명>/`에서 원본은 `sources/original/`, 수신기록은 `sources/intake/`, 조사·과제 설계는 `research/`, DOCX는 `deliverables/drafts/`와 `deliverables/final/`에 둔다.
- 회사가 특정됐으나 법인명이 미확정이면 기존 회사 작업공간에서 확인 항목을 남긴다. 대상 회사 자체가 모호하면 그 연결만 확인하며 공통 조사와 양식 준비는 진행한다.
- 시작할 때 프로젝트 지침, 회사 README, 현재 스킬과 GBrain 운영 맥락을 읽는다. 자료 위치는 현재 운영 계약으로 확인한다.
- 제도와 문서 목적은 `resources/references/기업부설연구소관리.md`, `templates-and-references.md`, `기본리서치&기획.pdf`, `rndlog_service_guide.pdf`를 읽는다. 과제 전개는 `연구보고서과제스케쥴샘플.pdf`와 `poc-beauty-roadmap.md`를 참고한다.
- 풀세트의 문서 역할은 `resources/samples/README.md`와 해당 샘플 본문으로 확인한다. 과거 HTML/PDF의 색상·월간 업무일지 주기를 신규 작성 규칙으로 가져오지 않는다.
- 법령·기관 제출 요건을 적용할 때는 KOITA 및 관계 기관의 현재 공식 홈페이지·서식·안내를 확인하고 URL·문서명·확인일을 남긴다. 서비스의 주간 작성 주기를 모든 기업의 법정 의무라고 설명하지 않는다.

## 1. 자료 취합과 제작 범위

고객이 지정한 채널·기간의 첨부, 이미지, 링크, 대화 메모를 취합한다. 사업자등록증, 연구소 인정서,
신고 연구개요, 연구원·시설 현황, 특허, 제품·서비스, 기존 연구 기록, 급여·투입시간 자료를 찾아
자료 목록과 보완 목록을 만든다. 자료가 연구와 직접 관련되지 않으면 그 이유를 적고 관련 자료를 활용한다.
카카오톡은 받은 파일 폴더뿐 아니라 첨부 카드의 미다운로드 파일도 확인한다.

원본은 바이트와 파일명을 보존하고 복사 전후 크기·SHA-256을 대조한다. 같은 이름의 다른 파일은
버전을 구분한다. 회사 README에 자료 출처, 회사 식별, 요청 기간, 보완 항목, 작업 이력을 기록한다.
연구원 이름·인정번호처럼 임의로 정할 수 없는 사실을 확인할 자료가 없으면 `[연구원명 입력]`,
`[인정번호 확인]`처럼 둔다. 근무시간·연구시간·참여율·급여와 비용은 아래 추정 규칙으로 계산해 값을 채운다.

서명자를 정하기 전에 연구개발인력현황·조직도·연구소 신고자료·대표자 자료를 대조해 성명, 직위,
연구 역할, 겸직 여부와 적용 기간을 확인한다. 이미지·스캔에 있는 인력표도 직접 읽으며 텍스트 검색에
안 나온다는 이유로 인력자료가 없다고 판단하지 않는다. 근거 파일과 문서별 역할 배정은 회사 README
또는 research/에서 관리한다. 기존 과제책임자가 확인되면 유지하고, 지정이 없으면 확인된 연구인력의
업무에 맞춰 문서 작성 역할을 배정한다. 작성 역할 배정을 회사의 공식 임명·과거 작성 사실로 단정하지 않는다.

요청 기간의 시작일·종료일과 문서별 대상 과제·작성 단위·예상 파일 수·보완 항목을 제작 목록으로
정리한다. 특정 문서만 요청하지 않았다면 아래 문서 체계에서 기간에 해당하는 세트를 구성한다.
자료가 부족한 문서도 채울 수 있는 본문·표·계산 구조를 작성한다. 미작성 문서는 이유를 목록에 남기며
임의로 연구일지와 업무일지 몇 개로 전체 요청을 축소하지 않는다.

## 2. 회사·기술 리서치와 과제 선정

회사 사업, 신고 연구분야, 특허, 제품, 연구 인력·설비에서 연구의 연결점을 찾는다. 연구 주제가
포괄적이면 해결할 기술 문제로 좁히고, 없는 정보는 조사와 제안으로 보완한다.

국내외 논문·특허·경쟁 기술·해외 선진기업 사례·학술 연구의 산업화 사례를 비교한다. 검색 건수보다
과제 선정과 방법 설계를 뒷받침하는 근거의 폭과 깊이를 확보한다. 원문에서 확인한 제목·기관/저자·
발행일·DOI 또는 URL과 적용 가능한 부분·한계를 기록한다. 확인하지 않은 논문이나 수치를 만들지 않는다.

후보별로 회사와의 연관성, 기존 기술의 한계, 연구 질문, 차별화 가능성, 필요한 자원, 기간 내 수행
가능성을 비교해 적합한 과제를 선정한다. 이미 지정된 과제는 세부 주제를 구체화한다. 자원이 불명확하면
문헌분석·설계·비교 검토 등 가능한 방법을 제안하고, 장비·실험이 필요한 단계는 준비 조건을 적는다.

조사 결과는 출처 요약만 나열하지 않고 `이 회사의 어떤 문제를 어떤 방법으로 연구할 것인지`로
이어져야 한다. 리서치 보고서는 연구 기록 세트를 대신하지 않는다.

## 3. 연구 로드맵과 주간 일정

과제별 목표·기간·세부 질문·방법·평가 기준·예상 산출물을 정하고 주간 단계로 나눈다. 단계마다
앞선 조사나 결과를 다음 단계의 입력으로 연결한다. 한 달을 무조건 4주로 고정하지 않고 실제 날짜와
요청 범위를 사용한다. 월·연도 경계의 일부 주도 포함하고 ISO 주차와 실제 시작·종료일을 함께 적는다.

각 주차에는 연구 목표, 일자별 세부 작업, 참고 근거, 방법·조건, 확보할 결과/증빙, 담당 역할,
다음 단계의 연결점을 둔다. 이름이 없으면 역할과 이름 입력란으로 진행한다. 과제가 여러 개면
문서의 과제 식별자와 파일명을 구분해 같은 주차 파일을 덮어쓰지 않는다.

미래 기간은 연구 계획·기록 양식으로 작성한다. 과거 기간은 확보한 활동자료로 기록을 정리하고,
부족한 부분은 고객 확인용 작성 초안과 수행 가능한 연구 시나리오로 보완한다. 제안한 활동과 예상
결과를 실제 수행·측정된 사실로 표현하지 않는다. 문헌의 결과는 해당 문헌의 결과임을 표시한다.
고객에게는 내용과 수치를 채운 문서를 제공해 구체적으로 검토·판단할 수 있게 한다.

## 4. 시간·참여율·비용 추정과 계산

확인된 원자료가 있으면 그 값을 우선한다. 값이 없으면 같은 회사의 과거 기록, 역할과 업무가 비슷한
회사 사례, 일반 근무조건 순으로 근거를 선택한다. 투입률은 아래 연구참여율과 같은 의미로 계산한다.
수치 필드는 빈칸·입력 요청·확인 예정 문구로 대신하지 않고 계산한 값을 자연스럽게 채운다.
다른 회사의 회사명·개인정보·고유 실적은 옮기지 않고 산정 방식과 통상 범위만 참고한다.
고객이 사전 검토 단계임을 알고 있으므로 산정 근거·추정값 안내·확인 요청을 별도 문구나 부록으로
추가하지 않는다. 계산에 필요한 기준은 이 절을 적용하고, 확인된 원자료와 충돌하는 값을 만들거나
계산값을 실제 측정·검증 완료 값이라고 설명하지 않는다.

총 근무시간은 회사 근무일정과 근태자료가 있으면 그대로 쓴다. 없으면 대상 기간의 월요일부터 금요일까지
하루 8시간으로 계산하고 공휴일은 제외한다. 휴가·결근·연장근무는 자료가 없으면 0시간으로 둔다. 일부
주차나 입·퇴사 기간은 문서의 실제 시작일과 종료일만 계산한다. 월 160시간을 모든 달에 고정 적용하지 않는다.

연구참여율 자료가 없고 업무량만으로 정하기 어려우면 아래 기본값을 쓴다. 역할과 계획된 작업량이
다르면 10%포인트 단위로 조정한다.

| 역할 | 기본 연구참여율 |
|---|---:|
| 신고된 연구전담요원 | 참여 기간 근무시간의 100% |
| 대표이사·다른 직무를 겸하는 연구소장 또는 과제책임자 | 50% |
| 일반 연구과제 참여자 | 50% |
| 연구지원·기능인력 | 30% |
| 연구행정·기타지원인력 | 20% |

`R&D 투입시간 = 총 근무시간 × 연구참여율`로 계산한다. 여러 과제가 있으면 연구 목표, 일자별 작업량,
담당 역할에 따라 R&D 투입시간을 나누며 과제별 시간의 합이 전체 R&D 투입시간을 넘지 않게 한다.
주간 시간은 일자별 작업에 0.5시간 단위로 배분하고 하루 총 근무시간을 넘지 않는다. 남은 시간은
비R&D 업무로 표시한다.

시간은 0.5시간, 참여율은 소수점 첫째 자리, 금액은 1원 단위로 반올림한다. 반올림 차이는 기간의
마지막 일자나 마지막 월에 반영해 일별·주별·월별·연간 합계가 정확히 맞게 한다.

연구개발활동조사의 연간 평균 연구참여 비율은 근무시간 비율과 참여기간을 함께 반영한다. 개인별
연환산 참여율은 `기간 중 연구참여율 × 참여 개월 수 ÷ 12`로 계산하고, 직능별 평균은 해당 인원의
연환산 참여율 합계를 인원수로 나눈다. 월 미만 기간은 실제 근무일수 비율로 계산한다.

급여자료가 없으면 같은 회사의 과거 보수, 확인된 직위·고용형태의 공개된 통상 보수, 유사 사례의
범위 순으로 값을 정한다. `기간 인건비 = 연간 급여 ÷ 12 × 대상 개월 수`, `R&D 배분액 = 기간 인건비 ×
연구참여율`로 계산한다. 월 미만 근무기간은 해당 월의 근무일수 비율로 인건비를 나눈다.

과거 기간도 리서치와 과제 흐름에 맞춰 활동·시간·참여율을 채운다. 고객이 값을 수정하면 주간 연구일지,
주간 업무일지, 월간 연구노트, 인건비배분표와 연간 자료를 같은 기준으로 다시 계산한다.

## 6. DOCX 디자인과 서명란

필요하면 허용된 접근으로 공통 제작 자원에 원본 바이트를 보존해 가져오고 출처·해시를 기록한다.

견적서에서 파생된 샘플의 글꼴·표 구조·테두리·셀 여백·문단 간격·페이지 배치를 기본으로 사용하고,
표 머리글의 녹색 배경만 짙은 네이비 또는 짙은 회색으로 변경한다. 요청에서 선택한 색을 따르며,
선택이 없으면 둘 중 하나를 제작 목록에 기록해 세트 전체에 일관되게 적용한다. 글자 대비를 확인한다.
`design-report-reference.docx`의 일반 보고서 디자인과 웹 UI 스타일은 이 제작 기준이 아니다.

참조 DOCX를 실제로 열어 표·문단·섹션 스타일을 가져오거나 복제한다. 존재 여부만 검사한 뒤 빈 문서에
임의의 Table Grid를 적용하는 방식은 참조 적용으로 인정하지 않는다. 샘플의 회사명·연구내용·날짜·
서명·이미지는 신규 회사의 내용으로 넘기지 않는다. 샘플이 없는 문서도 동일한 디자인 체계를 적용한다.

| 문서 | 기본 서명 역할 |

| 연구회의록 | 서기 / 연구소장 |

이 표는 내부 문서의 기본 구성이다. 공식 제출 서식이나 회사의 확정된 결재 규정이 있으면 먼저 적용한다.
대표자 이름을 모든 칸에 복사하지 않고 작성·검토·확인 업무와 확인된 인력을 연결한다. 같은 사람이
연구소장과 대표이사를 겸하면 내부 양식의 확인·승인란을 겸직 역할로 합친다. 별도 기술 검토가 필요하면
그 업무를 맡을 연구원을 배정한다. 칸 수를 채우려고 다른 사람을 만들거나 기존 책임자를 바꾸지 않는다.
한 사람만 있는 조직은 실제 역할에 맞춰 서명란을 줄인다. 공식 서식이 역할별 서명을 요구하면 그 구조를
유지한다. 동일인의 복수 서명을 일률적으로 위법이라고 설명하지 않는다.

문서 세트 전체의 성명·직위·역할을 본문 인력표와 서명란에서 함께 대조한다. 내부 서명표의 참여자 칸에서
작성자를 중복 나열하지 않고 필요한 칸만 남기되, 본문의 전체 참여·참석 명단은 유지한다.
샘플의 서명 공간과 날짜 행은 조정한 인원에 맞춰 유지한다.
이름과 서명/날인 공간을 분리하고 서명이나 도장은 대신 생성하지 않는다. 서명 날짜는 실제 서명일이
제공되지 않으면 `년    월    일` 입력 공간으로 두며 문서의 작성일·대상 기간으로 채우지 않는다.
추가로 승인된 날인 배치가 있으면 그 기준을 적용한다.

정식 문서에는 해당 문서가 요구하는 연구·업무 내용과 서식 항목만 넣는다. 문서 작성자의 부가 의견,
제작 경위, 추정값 안내, 고객 확인 요청과 서명 방법 설명은 넣지 않는다. 제목·부제·본문·표·머리말·
꼬리말·워터마크·주석까지 점검하고 파일명에서도 제작·검토 상태 문구를 제거한다. `고객 확인용 초안`,
`수행·수치 확인 후 서명` 같은 안내와 비게 된 안내 상자·구분자·공백을 정리한다. 연구 자체의 분석·판단·
한계·출처, 업무상 검토 내용과 정식 확인란은 보존한다. 제목과 파일명은 정식 문서명·과제·대상 기간이
서로 맞게 고친다. 이 정리는 고객의 사실 확인 완료를 뜻하지 않는다.

## 7. 검증·고객 보완·전달

DOCX 작업본을 `drafts/`에 작성하고 문서 생성에 사용하는 도구의 렌더링 절차로 모든 페이지를 확인한다.
기존 생성 도구가 있으면 위 문서·디자인 계약을 충족하는지 확인한 뒤 재사용한다.

- 제작 목록과 실제 파일의 문서 종류·과제·월·주차·기간을 전수 대조한다. 일부 주 누락과 중복을 확인한다.
- 계획→주간 연구→월간 정리→업무시간→비용의 내용·인력·기간·수치가 서로 맞는지 확인한다.
- 회사 제공 사실·외부 출처와 작성 내용이 모순되지 않는지 확인하고, 고객 문서에 사전 검토 상태나 산정 안내를 추가하지 않는다.
- 근무시간·연구시간·투입률(연구참여율)·급여·비용에 빈칸이나 입력 요청 문구가 없는지 확인한다.
- 문서 전체와 파일명에서 작성자 설명·제작 상태 안내가 제거됐는지, 필요한 연구 내용과 서식 항목은 유지됐는지 확인한다.
- 모든 서명란을 인력 근거와 대조해 역할·겸직 처리·중복 인명·서명 날짜 공간을 확인한다. 대표 문서 하나만 검사하지 않는다.
- 총 근무시간, 일자별 업무시간, 과제별 R&D 시간, 참여율과 인건비 배분액을 다시 계산해 일치하는지 확인한다.
- 고객 입력란은 보완 목록의 문서·위치·필요 자료와 연결한다. 승인된 입력란은 샘플 잔존 오류가 아니다.
- 샘플 회사명·가짜 서명·원본 예시 수치·영문 placeholder 등 의도하지 않은 잔존 내용은 제거한다.
- DOCX ZIP·관계 대상·본문·머리말·꼬리말을 검사하고, 렌더된 전체 페이지에서 표 잘림·겹침·빈 페이지·서명 공간과 참조 디자인을 확인한다.

검증을 통과한 문서는 이름·인정번호 등 임의로 정할 수 없는 사실의 입력란이 남아도 전달할 수 있다.
보완 목록과 확인 상태는 회사 README에서 관리하고, 고객 문서에 같은 안내를 반복하지 않는다.
고객 사실 확인까지 끝난 문서만 `final/`에 새 버전으로
확정하고 drafts와 final의 해시를 대조한다. 미확인 자료 때문에 조사·양식·초안 제작을 중단하지 않는다.
기관 제출이나 고객을 대신한 발송은 별도 요청에 따라 실행한다.

회사 README에는 제작 목록 대비 결과, 출처, 검증 결과, 보완 항목, 고객 확인 상태를 기록한다.
기존 고객 원본·HTML/PDF·최종본은 보존하고 수정본은 새 버전으로 만든다. PDF는 요청 시 DOCX의
보조 사본으로 제공한다. 최종 보고에는 작성 문서·대상 기간·고객 보완 사항·실제 검증 범위를 알린다.

기존 문서 수정은 요청한 문구·서명·기간 등 변경 항목을 먼저 정하고 원본과 수정본을 비교한다.
대상 밖의 수치·연구 내용·디자인과 DOCX 구성요소는 보존하고, 변경된 부분은 문서 간 연결까지 확인한다.
고객 전달 ZIP에는 요청한 문서만 넣고 작성자 설명·내부 검증 보고서·파일 해시 목록은 제외한다.
내부 근거와 검증 기록은 research/와 회사 README에 보관한다.

웹에 등록된 문서를 수정하는 작업은 기존 개별 다운로드와 전체 ZIP의 갱신까지 포함한다. 로컬 파일이나
새 ZIP 생성만으로 웹 반영 완료라고 보고하지 않는다. 현재 파일 등록·저장소·다운로드 경로를 확인하고,
중앙 저장소의 새 버전을 검증한 뒤 기존 다운로드 식별자와 연결을 유지하며 파일 경로·이름·크기·해시를
갱신한다. 연결 전 상태는 회사 작업공간에 보존하고 동시 변경을 확인한다. 파일 갱신을 위해 고객 공개·사실 확인·승인 상태를
자동 변경하지 않는다. 고객 사실 확인 전 문서도 내부 다운로드로 전달할 수 있으며 저장 위치만으로
확인 완료를 판단하지 않는다. 연결 검증에 실패하면 이번 연결 변경을 복구하고 기존 파일을 유지한다.

웹 반영은 실제 회사 자료 화면의 수정본 표시와 기존 다운로드 경로에서 받은 전체 파일의 크기·SHA-256으로
확인한다. 전체 ZIP의 문서 목록과 각 파일 해시도 개별 다운로드와 대조한다. 서버 다운로드 검증과 브라우저
저장 완료는 구분해 기록하며, 브라우저에서 차단되면 차단 사실과 검증한 범위를 알린다. 검증 기록은 교체될 수
있는 웹 컨테이너의 임시 경로에만 남기지 않고 회사 작업공간에 보관한다.
