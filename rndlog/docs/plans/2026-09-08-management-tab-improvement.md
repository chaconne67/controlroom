## 화면 구성

할 일 화면 상단 우측에 ‘할 일 추가’를 둔다. 기본 화면에는 입력폼을 펼쳐 놓지 않는다.
업무는 제목과 상태, 담당자와 기한, 필요한 보조 정보 순으로 읽는다.
각 업무의 ‘수정’을 누르면 해당 업무 자리에서 폼을 펼친다.

편집 폼은 제목 / 담당자·기한 / 상태·분류·우선순위 / 막힌 이유로 묶는다.
저장·닫기를 제공한다. 상태에서 완료·취소를 선택하고 저장해 종료한다.
별도 물리 삭제와 모든 행에 나열된 다수의 빠른 상태 버튼은 만들지 않는다.

열린 업무 아래 ‘완료·취소한 일’을 접힌 영역으로 둔다.
종료된 업무도 수정할 수 있고 열린 상태로 바꾸면 다시 열린 목록에 나타난다.
고객 안내는 별도 접힌 영역으로 유지하되 값이 없어도 작성 진입점을 제공한다.
고객 안내 저장은 고객 화면 문구를 바꾸며 문자·메일을 보내지 않는다.

불필요한 외곽 상자와 중복 구분선을 줄이고 정렬·여백으로 묶는다.
본문 14px, 기존 공용 입력 스타일과 기본정보의 간격 기준을 재사용한다.
모바일 버튼·입력의 터치 영역은 44px 이상을 보존한다.
기한·담당자 누락은 업무의 해당 위치에서만 표시한다. 누락 경고 배너는 만들지 않는다.

## 수정 전 잠금

현재 단계는 분석이다. 이 문서만 신규 작성하며 제품 코드·운영 데이터는 바꾸지 않는다.
로컬 대상 문서가 존재하지 않음을 확인했다. 기존 파일은 덮어쓰지 않는다.

### 최소 구현

최소 구현 게이트: 4단계에서 멈춤 — 기존 WorkItem과 ManagementCase를 재사용하고 Django ModelForm·권한 데코레이터·POST 저장으로 필요한 조작만 연결한다.

- 필요성: 현재 제품 관리 화면에서는 할 일을 처리할 수 없다.
- 재사용 조사: research_management/models.py, forms.py, views.py, urls.py, admin.py, workspace.html에서 WorkItem과 기존 저장 URL을 확인했다. 제품용 업무 저장 폼·URL은 없다.
- 표준 라이브러리로 폼·권한·저장을 별도 구현하면 Django 책임을 중복하므로 사용하지 않는다.
- Django 기본 ModelForm과 기존 요청/메시지/리다이렉트 패턴을 사용한다. 새 모델·마이그레이션·의존성·JS 상태 저장소는 필요하지 않다.

### 최종 경로와 병합 위치

현재: workspace URL → workspace/_workspace_context → _filtered_cases의 열린 업무 조회 → _detail_context → workspace.html의 tasks/schedule 표시.

변경: 같은 관리 화면의 업무 폼 → 관리 건/업무를 함께 검증하는 POST → ModelForm 검증과 기존 모델 저장 → 기존 workspace 경로 복귀 → 같은 목록·일정 조회.
고객 안내는 별도 필드 전용 POST로 기존 next_action_summary만 저장한다.

기존 조회 목록을 조회·선택 편집 목록으로 대체한다.
기존 일정의 조회 조건을 유지하고 동일 업무 편집으로 연결한다.
추가되는 영구 요소는 업무 등록/수정 폼과 저장 URL·뷰, 고객 안내 전용 폼과 저장 URL·뷰, 종료 업무 조회, 직접 검증이다.
등록과 수정은 같은 폼·저장 규칙을 사용한다. 업무와 고객 안내는 저장 대상을 분리한다.
이 순증가는 현재 없는 업무 처리에 필요하며 이 문서의 승인 범위다.

### 범위와 보호 조건

- 수정: research_management의 form/view/URL/관리 탭 template와 직접 관련 테스트·검증 문서. 필요 시 기존 공용 partial을 재사용한다.
- 보존: 기본정보 및 다른 탭, 회사 원장·연구조직·고객사 주담당 배정 이력, 원본·파일 메타데이터·공개·다운로드·고객 승인 계약.
- 업무 저장은 그 업무만 변경한다. 회사 진행 상태·고객 안내·관리 참고사항을 자동 변경하지 않는다.
- 관리자·영업만 업무와 안내를 저장한다. 고객·비로그인 요청은 거부하며 CSRF 검사를 유지한다.
- 다른 관리 건의 업무 식별자를 끼워 넣은 요청은 거부한다.
- 기존 비활성 담당자는 단순 편집 때문에 자동 해제하지 않는다. 새 배정은 활성 관리자·영업만 허용한다.
- 완료 시각은 서버에서 처리한다. 검증 오류는 어떠한 값도 저장하지 않는다.
- 검색·큐·선택 회사·진입 탭을 보존한다. 저장 결과 회사가 현재 큐에서 빠지면 기존 방식대로 전체 큐에서 선택 회사를 표시한다.
- 오류 시 해당 편집 폼을 열린 상태로 재표시하고 입력과 오류를 보존한다. 저장 중 표시와 중복 제출 방지는 기존 공통 기능을 먼저 확인해 재사용한다.
- 운영 데이터로 추가·수정·완료 시험을 하지 않는다. 알림 발송·일정 자동 생성·청구 기능은 없다.
