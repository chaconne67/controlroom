# RNDLOG 업로드 자료 구분 계획

- 작성 기준일: 2026-09-06
- 상태: 구현·검증·운영 배포 완료
- 대상: 연구소 관리 고객사 상세의 자료 업로드
- 목표: 관리자가 업로드 묶음의 용도를 반드시 선택하고, 보고서 입력 자료와 보관용 서류가 저장·조회·후속 처리에서 섞이지 않게 한다.

## 1. 결정

AI·OCR·파일명 규칙으로 계약서를 자동판독하지 않는다. 업로드 전에 관리자가 `자료 구분`을 반드시 하나 선택한다.

| 선택값 | 의미 | 향후 보고서 생성 |
|---|---|---|
| 보고서 작성용 자료 | 연구 보고서와 R&D 증빙 문서를 작성할 때 읽어야 하는 고객 원자료 | 입력 대상 |
| 기타 서류 | 계약서·위임장·동의서 등 보관은 필요하지만 보고서 작성에는 사용하지 않는 서류 | 입력 대상에서 제외 |

한 번의 업로드에 포함된 모든 개별 파일 또는 ZIP 내부 파일은 같은 구분을 상속한다. 두 종류가 섞였으면 업로드를 두 번 나눠서 실행한다.

파일명 키워드 판정은 이름이 바뀌거나 계약서라는 단어가 없는 경우를 놓친다. 본문 추출·OCR·AI 판정은 스캔 PDF, 암호 문서, 비용과 오분류 검토가 추가된다. 현재 두 종류만 필요한 상황에서는 사용자의 필수 선택이 가장 단순하고 검증 가능한 경로다.

## 2. 저장 위치

두 종류 모두 고객이 준 원본이므로 기존 정본인 `sources/original/` 아래에 둔다.

```text
companies/<workspace_key>/sources/original/
├── report-materials/
│   └── 업로드_<시각>_<식별자>/
└── other-documents/
    └── 업로드_<시각>_<식별자>/
```

- `report-materials`: 보고서 작성용 자료
- `other-documents`: 계약서 등을 포함한 기타 서류
- ZIP은 선택한 구분 폴더의 업로드 묶음에 원본을 보존하고 `압축해제/` 아래에 푼다.
- 기존 `sources/original/` 파일과 기존 `업로드_*` 폴더는 이동하거나 자동분류하지 않는다.
- 새 구분 폴더는 첫 업로드 때 중앙 게이트웨이가 기존 권한 규칙으로 만든다.

`documents/` 같은 새 최상위 폴더를 만들지 않는다. 계약서도 고객이 제공한 원본이라는 사실은 유지하면서, 보고서 입력 여부만 하위 경로로 분리한다.

## 3. 메타데이터 계약

`FileAsset`에 nullable/blank 가능한 `source_purpose`를 추가한다.

| 코드값 | 화면명 |
|---|---|
| `report_input` | 보고서 작성용 자료 |
| `other_document` | 기타 서류 |

- 새 고객 자료 업로드에는 둘 중 하나가 필수다.
- 기존 파일과 생성 산출물은 사실을 추정하지 않고 빈 값으로 마이그레이션한다.
- `storage_area`는 두 종류 모두 기존 `source_original`을 유지한다.
- 향후 보고서 생성기는 `source_purpose=report_input`인 파일만 기본 입력으로 조회한다.
- 경로명만으로 용도를 추정하지 않고 DB 필드와 저장 경로가 일치하도록 같은 저장 결과에서 기록한다.

## 4. 화면 동작

기존 `자료 올리기` 펼침 영역에서 파일 선택 바로 위에 필수 라디오 그룹을 둔다.

```text
자료 구분  필수
( ) 보고서 작성용 자료
    연구 보고서 작성에 사용할 원자료
( ) 기타 서류
    계약서·위임장 등 보관용이며 보고서 작성에서는 제외

고객 자료 선택
[파일 선택]
```

- 어느 항목도 미리 선택하지 않는다.
- 선택하지 않고 저장하면 중앙 전송 전에 `자료 구분을 선택해 주세요.`를 표시한다.
- 선택한 값은 파일 검증 오류가 발생해도 유지한다.
- 라디오와 설명 전체를 44px 이상의 클릭 영역으로 만든다.
- 성공하면 선택한 구분 폴더와 새 업로드 묶음을 트리에서 펼친다.
- 파일 선택 규칙과 50MB 제한은 그대로 유지한다.
- 서로 다른 종류가 섞인 파일은 나눠 올리라는 안내를 표시한다.

## 5. 폴더 트리

기존 실제 경로 트리에 두 폴더를 항상 표시한다.

```text
sources
└── original  고객 원본
    ├── report-materials  보고서 작성용 자료
    └── other-documents   기타 서류
```

기존 미분류 파일은 현재 실제 위치 그대로 `original` 아래에 보인다. 가상 이동이나 숨김 처리는 하지 않는다.

## 7. 최종 실행 경로

```text
관리자가 자료 구분 선택
→ 파일 또는 ZIP 선택
→ Django가 구분값·파일 안전성·총량 검사
→ 제한 SSH 명령에 허용된 구분 코드 전달
→ 중앙 게이트웨이가 구분 코드를 고정 경로로 변환
→ 선택한 하위 폴더의 새 업로드 묶음에 원자 저장
→ manifest의 목적 경로 검증
→ FileAsset에 source_purpose와 메타데이터 기록
→ 선택한 폴더와 업로드 묶음을 펼친 트리 반환
```

사용자가 보낸 경로 문자열을 그대로 사용하지 않는다. 게이트웨이 내부의 고정 매핑만 실제 저장 경로를 결정한다.

## 8. 검증과 배포

수정 전 기준선:

- 운영 `main` 커밋 `5017809`, 변경 없음
- 연구소 관리 테스트 28개 통과
- Django 검사 통과

수정 후:

1. 미선택·알 수 없는 구분값이 중앙 전송 전에 실패하는지 확인한다.
2. 두 구분의 개별 파일과 ZIP이 각각 정확한 폴더에 저장되는지 임시 작업공간에서 확인한다.
3. ZIP 원본 보존·압축 해제·경로 탈출 차단·전체 rollback이 유지되는지 확인한다.
4. 기존 미분류 `FileAsset`이 이동·재분류되지 않는지 확인한다.
5. 보고서 작성용 필터가 기타 서류를 포함하지 않는 계약 테스트를 추가한다.
6. Tailwind 빌드, Django 검사, migration drift, 관련 테스트를 실행한다.
7. 390px·480px·1024px 이상에서 필수 라디오, 오류, 성공, 트리 열린 상태를 확인한다.
8. `code-review-loop`로 권한·경로·데이터 원자성을 재검토한다.
9. 승인 범위만 있는 clean `main`에서 커밋·배포한다.
10. 운영 고객사에 시험 파일을 올리지 않고 화면 렌더링·중앙 health·서비스 `1/1`을 확인한다.
