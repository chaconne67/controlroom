# 컴퍼니 룩업 대량 조회 실행계획

작성일: 2026-05-10

## 결론

네이버 검색과 카카오 Daum 검색을 함께 쓰면 하루 최대 **75,000번** 검색할 수 있다.

현재 `data/merged.db` 기준으로 전체 회사는 **83,724건**, 아직 조회 대기인 회사는 **76,694건**이다. 따라서 첫날에는 거의 모든 대기 회사를 한 번씩 훑고, 둘째 날부터 빈칸을 보완하는 방식이 가장 빠르다.

## 공식 한도

| 구분 | 하루 한도 | 사용 의미 |
|---|---:|---|
| 네이버 검색 | 25,000건 | 웹문서, 블로그, 뉴스 등 검색 전체 합산 |
| 카카오 Daum 검색 전체 | 50,000건 | 웹문서, 블로그, 카페 등 검색 전체 합산 |
| 카카오 웹문서 검색 | 30,000건 | Daum 검색 50,000건 안의 세부 한도 |
| 카카오 로컬 키워드 검색 | 100,000건 | 장소·업체 검색용 별도 한도 |

주의: 카카오 웹문서, 블로그, 카페가 각각 30,000건이어도 Daum 검색 전체 한도는 50,000건이다. 즉 카카오 Daum 검색은 하루 총합 50,000건 안에서 나눠 써야 한다.

출처:

- 네이버 검색 API: https://developers.naver.com/products/service-api/search/search.md
- 카카오 쿼터: https://developers.kakao.com/docs/ko/getting-started/quota

## 목표

1. 첫날은 최대한 많은 회사를 한 번씩 조사한다.
2. 둘째 날부터는 전날 못 채운 칸만 다른 조합으로 다시 조사한다.
3. 우선순위는 전화번호·이메일, 대표이름, 홈페이지 주소 순서다.
4. 이미 충분히 채워진 회사는 다시 검색하지 않는다.

## 1일차: 전체 빠른 훑기

목표는 회사별로 최소 1번 검색해 연락처 후보가 있는지 확인하는 것이다.

| 채널 | 요청 수 | 대상 | 검색 의도 |
|---|---:|---|---|
| 네이버 검색 | 25,000건 | 취소·청문 관련 회사 우선 | 회사명 전화번호 이메일 |
| 카카오 웹문서 | 30,000건 | 나머지 대기 회사 | 회사명 전화번호 이메일 |
| 카카오 블로그 | 10,000건 | 검색 결과가 약한 회사 | 회사명 대표전화 연락처 |
| 카카오 카페 | 10,000건 | 남은 대기 회사 | 회사명 연락처 이메일 |

합계: 75,000건

예상 결과:

- 대기 76,694건 중 약 75,000건을 1차 조사한다.
- 약 1,694건은 2일차 첫 순번으로 넘긴다.
- 첫날 성공 기준은 완성이 아니라 후보 확보다.

## 2일차: 빈칸 보완

목표는 1일차 결과를 보고 부족한 정보만 보완하는 것이다.

| 채널 | 요청 수 | 대상 | 검색 의도 |
|---|---:|---|---|
| 네이버 검색 | 25,000건 | 이메일이 없는 회사 | 회사명 이메일 |
| 카카오 웹문서 | 30,000건 | 전화번호가 없는 회사 | 회사명 대표전화 연락처 |
| 카카오 블로그 | 10,000건 | 대표이름이 없는 회사 | 회사명 대표이사 대표자 |
| 카카오 카페 | 10,000건 | 홈페이지가 없는 회사 | 회사명 홈페이지 |

합계: 75,000건

운영 기준:

- 아직 한 번도 조회하지 못한 약 1,694건을 먼저 처리한다.
- 전화번호와 이메일이 모두 있는 회사는 대표이름·홈페이지 보완 대상으로만 보낸다.
- 전화번호와 이메일이 없는 회사는 대표이름·홈페이지보다 연락처 보완을 먼저 한다.

## 3일차: 품질 보완

목표는 값이 있더라도 믿기 어려운 회사를 다시 보는 것이다.

| 채널 | 요청 수 | 대상 | 검색 의도 |
|---|---:|---|---|
| 네이버 검색 | 25,000건 | 같은 번호가 여러 회사에 반복된 건 | 회사명 공식 대표전화 |
| 카카오 웹문서 | 30,000건 | 검색 결과 충돌 건 | 회사명 공식 홈페이지 |
| 카카오 블로그 | 10,000건 | 대표이름 불확실 건 | 회사명 대표이사 |
| 카카오 카페 | 10,000건 | 전화번호가 휴대폰·대표번호로만 잡힌 건 | 회사명 연락처 |

합계: 75,000건

## 카카오 로컬까지 쓰는 확장안

카카오 로컬 키워드 검색까지 추가하면 하루 최대치는 더 커진다.

| 구분 | 하루 한도 | 역할 |
|---|---:|---|
| 네이버 검색 | 25,000건 | 이메일, 공식 문서, 홈페이지 후보 |
| 카카오 Daum 검색 | 50,000건 | 웹문서, 블로그, 카페 보완 |
| 카카오 로컬 키워드 검색 | 100,000건 | 전화번호, 주소, 장소 페이지 후보 |

합계: 175,000건

다만 로컬 검색은 장소·업체 검색에 강하고 이메일 확보에는 약하다. 따라서 전화번호 보완용으로 쓰고, 이메일은 네이버와 카카오 웹문서 검색으로 보완한다.

## 추천 운영 방식

### 기본안: 검색 API만 사용

첫 2일 동안은 75,000건씩 최대한 사용한다.

1일차:

- 대기 회사를 최대한 넓게 1회 조사한다.
- 같은 회사를 여러 검색어로 깊게 파지 않는다.

2일차:

- 1일차에서 빠진 회사와 빈칸이 많은 회사를 우선한다.
- 검색어를 바꿔서 전화번호, 이메일, 대표이름, 홈페이지를 나눠 보완한다.

3일차 이후:

- 실패, 충돌, 반복 번호, 불확실한 대표이름만 다시 본다.

### 확장안: 카카오 로컬 추가

첫날부터 전화번호 확보 속도를 높이고 싶으면 카카오 로컬을 추가한다.

1일차:

- 카카오 로컬로 전체 회사의 전화번호·주소 후보를 빠르게 본다.
- 네이버와 카카오 Daum 검색은 이메일·공식 홈페이지 중심으로 쓴다.

2일차:

- 로컬에서 못 찾은 회사는 웹문서 검색으로 보완한다.
- 웹문서에서 이메일만 찾은 회사는 로컬로 전화번호를 보완한다.

## 실행 순서

1. 조회 대기 회사를 우선순위대로 정렬한다.
2. 하루 요청 예산을 네이버 25,000건, 카카오 Daum 50,000건으로 나눈다.
3. 첫날은 회사당 1회 검색을 원칙으로 한다.
4. 검색 결과에서 전화번호·이메일·대표이름·홈페이지 후보를 저장한다.
5. 둘째 날은 비어 있는 칸 기준으로 검색어와 채널을 바꾼다.
6. 셋째 날부터는 실패·충돌·중복 의심 건만 재조회한다.

## 성공 기준

| 단계 | 성공 기준 |
|---|---|
| 1일차 | 대기 회사 대부분이 최소 1회 조회됨 |
| 2일차 | 전화번호 또는 이메일이 없는 회사 수가 크게 감소 |
| 3일차 | 반복 번호, 오염 출처, 충돌 후보가 줄어듦 |
| 최종 | 전화번호·이메일 확보율을 최우선으로 높이고, 대표이름과 홈페이지를 보완 |

## 주의사항

- 75,000건은 회사 수가 아니라 검색 요청 수다.
- 회사 하나에 여러 검색어를 쓰면 하루에 처리 가능한 회사 수는 줄어든다.
- 카카오 Daum 검색은 웹문서·블로그·카페를 합쳐 50,000건으로 봐야 한다.
- 카카오 로컬은 별도 한도지만, 현재 작업 흐름에 추가 구현이 필요하다.
- 검색 API 한도를 다 써도 본문 페이지 요청은 상대 사이트에서 차단될 수 있다.
- 공식 한도는 변경될 수 있으므로 대량 실행 전 당일 문서를 다시 확인한다.
