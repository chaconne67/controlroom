# CRETOP 범용 팝업 최종 복구 설계

## 목표

- 기존 정상 수집 경로와 기존 오류처리를 그대로 유지한다.
- 기존 오류처리가 모두 실패하여 배치를 중단하려는 경우에만 범용 팝업 복구를 한 번 시도한다.
- 범용 복구가 성공하면 스마트검색으로 초기화한 뒤 중단된 회사를 검색부터 다시 처리한다.

## 변경하지 않는 범위

- 회사 검색, 상세 진입, 브리핑 확인, 8개 화면 수집 순서를 변경하지 않는다.
- 기존 marker, 클릭 재시도 횟수, 회사 경계, 파일 저장, DB 저장을 변경하지 않는다.
- 페이지 만료, 유료 서비스, 정보 비공개, 로그인·세션, 검색·상세 화면 등 기존 오류 분류와 후속 조치를 변경하지 않는다.
- 기존 정보제공중지·재무정보 비공개 확인 좌표를 이번 작업에서 공통 영상처리로 교체하지 않는다.
- 기존 오류처리의 통합이나 정리는 후속 작업으로 남긴다.
- LLM을 호출하지 않는다.

## 현재 최종 경로

1. `scripts/cretop_detail_collection.py`가 로컬 기준 SSP를 원격에 배포하고 SHA-256 일치를 확인한다.
2. 원격 `scripts/cretop_agent.py`의 `collect-batch`가 기존 Chrome 세션에서 회사를 검색한다.
3. 검색 결과가 한 건이고 사업자번호가 일치하면 상세페이지에 진입한다.
4. 브리핑을 포함한 승인된 8개 화면을 순서대로 수집한다.
5. 기대 marker가 실패하면 `_handle_company_exception()`이 기존 오류를 분류하고 기존 복구를 실행한다.
6. 회사 처리 중 기존 복구까지 실패한 경우에만 `_handle_company_exception()`의 마지막 범용 팝업 복구 단계가 실행된다.
7. 프리플라이트는 같은 에러처리기의 기존 분기만 사용하며 마지막 범용 팝업 복구 단계에는 진입하지 않는다.

## 병합 위치

- 정상 수집 경로와 별도로 예외만 전담하는 기존 `_handle_company_exception()`에 범용 팝업 복구 기능을 추가한다.
- 별도의 에러 처리 흐름이나 두 번째 에러처리기를 만들지 않는다.
- 영상에서 팝업과 버튼을 판정하는 기계적 계산은 작은 보조 함수로 분리할 수 있지만, 처리 순서와 결과 결정은 기존 `_handle_company_exception()`이 계속 소유한다.
- 범용 단계는 기존 분류와 복구를 모두 거친 뒤 중단 결과를 만들기 직전의 마지막 단계에 병합한다.
- 다음 두 회사 처리 종료 경계만 범용 단계의 대상이다.
  - 기존 분류로 처리할 수 없는 화면
  - 기존 분류는 됐지만 해당 복구가 실패한 화면
- 유료 서비스나 반복된 페이지 만료처럼 기존 정책이 의도적으로 중단한 결과에는 범용 단계로 진입하지 않는다.
- 호출 문맥을 `preflight`와 `company`로 명시적으로 구분한다.
- `preflight` 문맥에서는 기존 분기만 실행하고 범용 단계는 실행하지 않는다.
- `company` 문맥에서 기존 오류처리가 실패한 경우에만 범용 단계를 실행한다.
- 정상 회사 처리 함수와 기존 오류 분류·복구 분기는 변경하지 않는다.

## 범용 팝업 판정

범용 복구는 다음 조건을 모두 만족해야 시작한다.

- 기존 예외 화면 캡처가 성공했다.
- 기존 본문 복사와 오류 분류가 정상적으로 수행됐다.
- 기존 오류처리가 해결하지 못한 상태다.
- 이번 회사에서 범용 복구를 아직 사용하지 않았거나, 범용 복구 후 같은
  형태의 팝업이 재발해 닫기만 필요한 상태다.
- 화면 중앙 영역에서 어두운 배경 위의 밝은 팝업 패널이 검출된다.
- 밝은 패널 아래쪽 내부에서 단일 검은색 버튼이 검출된다.
- 후보 패널과 버튼이 각각 하나로 확정된다.

후보가 없거나 여러 개이면 클릭하지 않고 기존 중단 결과를 유지한다.

본문이 없거나 본문 복사 자체가 실패한 경우에는 범용 단계로 진입하지 않는다. 빈 본문은 기존 정책대로 중단하며, 복사 로직 오류는 별도 원인 분석과 수정 대상으로 남긴다.

## 버튼 탐지와 클릭

1. 실패 캡처를 고정 해상도 `1920x1080` 기준으로 분석한다.
2. 중앙 영역에서 밝은 직사각형 팝업 후보를 찾는다.
3. 팝업 내부 아래쪽에서 어두운 직사각형 버튼 후보를 찾는다.
4. 면적, 가로세로 비율, 팝업 내부 포함 여부로 후보를 제한한다.
5. 단일 후보의 경계 상자 중심점을 클릭 좌표로 사용한다.
6. 클릭은 한 번만 수행한다.
7. 클릭 전 캡처, 검출된 팝업·버튼 경계, 계산 좌표를 실패 증거에 남긴다.

OCR이나 문구 의미 판단은 성공 조건으로 사용하지 않는다. 영상 구조가 명확하지 않으면 범용 복구를 실행하지 않는다.

## 클릭 후 검증과 복귀

1. 클릭 후 화면을 다시 캡처한다.
2. 클릭 전 검출한 팝업·버튼 구조가 사라졌는지 확인한다.
3. 화면 텍스트를 다시 복사한다.
4. 기존 화면 marker 판정기로 현재 위치를 분류한다.
5. 기존 경로만 사용해 스마트검색으로 복귀한다.
6. `스마트 검색`, `키워드`, `기업상태`, `정상`, `조회하기` marker를 모두 확인한다.
7. 첫 범용 복구에서 스마트검색 확인에 성공하면 같은 회사를 검색부터 다시
   시작한다.
8. 재시도에서 팝업이 재발하면 같은 판정과 클릭으로 팝업만 닫고 스마트검색
   복귀를 확인한다.

팝업 소멸, 화면 복사, 현재 위치 판정, 스마트검색 복귀 중 하나라도 실패하면 범용 복구 실패로 기록하고 배치를 중단한다.

## 재시도 제한

- 범용 팝업 복구 후 같은 회사 재추출은 한 번만 허용한다.
- 복구 후에는 중단 지점에서 이어가지 않고 같은 회사를 검색부터 다시 처리한다.
- 재시도에서 팝업이 재발하면 추가 재추출은 하지 않는다.
- 재발 팝업의 확인 버튼만 클릭하고 팝업 소멸과 스마트검색 복귀를 확인한다.
- 스마트검색 복귀가 가능하면 해당 회사를 `CRETOP 상세정보 없음` 오류로 기록하고 다음 회사로 진행한다.
- 스마트검색 복귀까지 실패하면 배치를 중단한다.

## 기록 계약

범용 복구 결과에는 다음을 남긴다.

- 원래 예외 단계와 원인
- 기존 오류 분류와 기존 복구 실패
- 클릭 전·후 캡처
- 검출한 팝업과 버튼 경계 상자
- 계산한 버튼 중심 좌표
- 팝업 소멸 판정
- 클릭 후 화면 marker 판정
- 스마트검색 복귀 결과
- 같은 회사 재시도 여부와 최종 결과

원래 오류와 범용 복구 오류는 서로 덮어쓰지 않는다.

## 검증

### 로컬 검증

- 정상 화면 이미지에서는 팝업을 검출하지 않는 단위 테스트
- 중앙의 밝은 팝업과 단일 검은 버튼에서는 버튼 중심 좌표를 반환하는 단위 테스트
- 버튼 후보가 없거나 여러 개이면 클릭 좌표를 반환하지 않는 단위 테스트
- 기존 오류처리가 성공하면 범용 단계에 진입하지 않는 테스트
- 회사 처리에서 기존 오류처리가 실패한 경우에만 범용 단계에 진입하는 테스트
- 프리플라이트 문맥에서는 범용 단계에 진입하지 않는 테스트
- 본문이 없거나 본문 복사가 실패하면 범용 단계에 진입하지 않는 테스트
- 회사당 한 번의 복구 제한 테스트
- 범용 복구 후 같은 회사를 검색부터 다시 시작하는 테스트
- 재시도에서 팝업이 재발하면 팝업을 닫고 회사 오류로 기록한 뒤 다음 회사로 진행하는 테스트
- 기존 CRETOP 테스트 전체와 `uv run pytest -q` 실행

### 최종 경로 검증

- 이번 실패 회사를 case-first로 실행한다.
- 기존 오류처리가 실패한 뒤 범용 영상 복구가 한 번만 실행되어야 한다.
- 팝업 버튼 중심 클릭, 팝업 소멸, 스마트검색 marker 확인이 순서대로 남아야 한다.
- 같은 회사가 검색부터 다시 실행되어야 한다.
- 이전에 정상 수집된 회사 한 곳을 같은 SSP로 실행해 기존 정상 경로가 그대로 통과해야 한다.

원격 배포와 실브라우저 검증은 주인님의 명시적인 실행 지시가 있는 경우에만 수행한다.

## 실패 시 처리

- 실브라우저 최종 경로 검증이 실패하면 이번에 병합한 범용 복구 변경만 되돌린다.
- 기존 정상 경로와 기존 오류처리는 되돌리거나 수정하지 않는다.
- 실패 캡처와 판정 근거만 보존하고 분석 단계로 돌아간다.
