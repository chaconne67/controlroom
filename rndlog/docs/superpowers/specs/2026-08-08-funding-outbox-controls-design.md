# 문자 발송 필터 컨트롤 디자인 복구

## 목표

문자 발송 목록의 검색·필터·예약 컨트롤을 프로젝트 디자인 시스템과 같은 형태로 표시한다. 사용자는 회사를 검색하고 조건을 좁힌 뒤 하나의 주 행동인 `문자 예약하기`로 이어간다.

## 원인

`funding/templates/funding/admin_list.html`이 `select`, `btn`, `btn-primary` 클래스를 사용하지만 공통 CSS와 Tailwind 출력에는 해당 컴포넌트 정의가 없다. 검색창만 유틸리티 클래스로 꾸며져 있고 필터와 예약 버튼은 브라우저 기본 모양으로 렌더링된다.

## 범위

- 수정: `funding/templates/funding/admin_list.html`의 필터 select와 `pick-open` 버튼
- 검증: 같은 템플릿을 공유하는 문자 발송과 TM 진행 내역 화면
- 보존: 검색·필터 field 이름, HTMX URL·target·swap·trigger, 선택 수 갱신, 예약·전달 모달, 서버 처리와 데이터 모델

공통 CSS 컴포넌트, 다른 화면, 업무 규칙은 변경하지 않는다.

## 선택한 설계

기존 Tailwind 유틸리티와 WDS 토큰을 대상 템플릿에 직접 적용한다.

- 필터: 최소 44px 높이, `rounded-lg`, 흰 배경, WDS line·label 토큰, WDS primary focus 상태
- 주 버튼: 최소 44px 높이, WDS primary normal 배경, 흰 글자, strong hover, disabled 상태
- 배치: 기존 flex-wrap과 8px 간격을 유지해 좁은 화면에서 자연스럽게 다음 줄로 이동
- 접근성: 검색과 각 select에 보이는 의미와 같은 `aria-label` 추가
- 행동 위계: 필터는 중립 표면으로 유지하고 `문자 예약하기` 또는 `영업자에게 전달`만 유일한 강조 행동으로 표시

## 제외한 대안

### 공통 컴포넌트 클래스 추가

`select`와 `btn`을 공통 CSS에 정의하면 여러 funding 화면이 동시에 바뀐다. 이번 화면의 누락 복구보다 영향 범위가 크므로 제외한다.

### 화면 전용 CSS 추가

이미 Tailwind와 WDS 토큰으로 표현할 수 있다. 중복 규칙과 별도 유지 지점을 만들기 때문에 제외한다.

## 인터랙션 계약

- Given: 사용자가 문자 발송 또는 TM 진행 내역 목록을 열었다.
- When: 검색어를 입력하거나 필터를 바꾼다.
- Then: 기존 `GET rows_url` 요청이 `#admin-rows`만 `outerHTML`로 교체한다.
- When: 예약 또는 전달 버튼을 누른다.
- Then: 기존 JavaScript가 선택값과 `list_query`를 전달해 `#modal-slot`에 모달을 연다.
- 불변조건: URL, 검색·필터 값, 페이지 스크롤 소유자, 목록 선택 로직, 서버 데이터는 시각 변경 전후 동일하다.
- 실패 처리: 기존 HTMX와 전역 오류 처리 계약을 유지한다.

## 검증

1. 템플릿 회귀 테스트로 필터 field, 단일 주 버튼, HTMX 계약을 확인한다.
2. Tailwind를 다시 빌드해 사용한 클래스가 출력 CSS에 생성되는지 확인한다.
3. Django 검사와 funding 관리자 테스트를 실행한다.
4. 실제 개발 URL에서 관리자 문자 발송, TM 문자 발송, TM 진행 내역을 확인한다.
5. 데스크톱과 좁은 폭에서 높이·간격·줄바꿈·focus·disabled 상태를 확인한다.
6. 필터 변경과 버튼 클릭 전후 DOM, 네트워크, 콘솔 오류를 확인한다.

## 완료 조건

- 브라우저 기본 모양의 select와 텍스트형 예약 버튼이 남지 않는다.
- 모든 필터와 주 버튼이 디자인 시스템 토큰으로 일관되게 보인다.
- 필터 갱신과 모달 열기가 기존과 동일하게 동작한다.
- 공통 CSS나 범위 밖 화면에 변경이 없다.
