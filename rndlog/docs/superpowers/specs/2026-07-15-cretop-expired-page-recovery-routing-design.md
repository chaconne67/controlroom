# CRETOP 페이지 만료 복구 분기 설계

## 목적

CRETOP 화면에서 페이지 만료가 확인되면 강력 새로고침 후 화면 상태를 다시 판정하고, 필요한 복구 단계만 실행한 뒤 중단된 회사의 검색부터 수집을 재개한다.

## 관측된 실패

- 실행: `cretop_pending12_20260715_01`
- 화면 문구: `페이지가 만료되었습니다`
- 결과 코드: `-1405`
- 결과: 회사 수집 전 종료, 생성 항목 0건, DB 저장 0건
- 원인: 기존 분류가 `[8004]` 또는 붙어 있는 `페이지 만료`만 인식해 조사 `가`가 포함된 문구를 만료 상태로 분류하지 못했다.

## 만료 신호

화면 복사 텍스트가 다음 중 하나를 만족하면 `ExpiredPageError`로 분류한다.

- `[8004]` 포함
- 정규화된 복사 텍스트에 `페이지`와 `만료`가 함께 포함

`-1405`는 보조 기록이며 분기 조건으로 사용하지 않는다.

## 최종 복구 경로

1. 페이지 만료 신호를 감지한다.
2. `Ctrl+Shift+R`을 한 번 실행한다.
3. 30초 동안 추가 조작 없이 기다린다.
4. 화면 글자를 한 번 복사해 현재 상태를 판정한다.
5. 정상 로그인 marker `WA260642`와 기존 CRETOP 레이아웃이 확인되면 기존 홈 초기화를 실행한다.
6. 정상 로그인 레이아웃이 확인되지 않으면 기존 프리플라이트를 실행한다.
7. 프리플라이트가 정상 로그인 상태를 만들면 기존 홈 초기화를 실행한다.
8. 홈 marker `검색어를 입력해주세요.`와 `My Board`가 확인되면 중단된 회사를 검색부터 다시 시작한다.
9. 같은 배치에서 두 번째 페이지 만료가 발생하면 기존 계약대로 즉시 중단한다.

## 기존 경로 대체

기존 순서:

```text
30초 대기 → Ctrl+Shift+R → 항상 프리플라이트 → 홈 초기화 → 30초 대기
```

변경 순서:

```text
Ctrl+Shift+R → 30초 대기 → 화면 판정
→ 정상 로그인 화면: 홈 초기화
→ 로그인 복구 필요: 프리플라이트 → 홈 초기화
```

사전 30초 대기와 홈 초기화 뒤의 추가 30초 대기는 제거한다. 만료 복구 1회당 고정 대기는 새로고침 뒤 30초 한 번만 둔다.

## 상태 판정

- 홈 초기화 직행:
  - `WA260642`가 있음
  - 기존 상세 레이아웃 또는 전역 CRETOP 레이아웃 marker가 있음
- 프리플라이트:
  - 위 정상 로그인 레이아웃 조건을 만족하지 않음
  - 재로그인, 자동로그아웃, 시간연장, 동시접속 복구는 기존 프리플라이트가 담당
- 중단:
  - 프리플라이트가 정상 로그인 marker를 만들지 못함
  - 홈 초기화가 홈 marker를 만들지 못함
  - 같은 배치에서 두 번째 만료 발생

알 수 없는 화면에서 홈 좌표를 먼저 클릭한 뒤 실패하면 프리플라이트하는 예외 기반 폴백은 사용하지 않는다.

## 병합 위치와 범위

- 기준 파일: `scripts/cretop_agent.py`
- 만료 분류: 기존 `_raise_if_expired_page()` 조건 교체
- 복구 순서: 기존 `_recover_expired_page_to_home()` 내부 순서와 상태 분기 교체
- 재사용:
  - `_ensure_ready_fast()`
  - `_go_home_fast()`
  - `_wait_without_action()`
  - 기존 배치의 1회 복구 제한
- 금지:
  - 별도 runner
  - `-1405` 전용 분기
  - 수동 새로고침
  - 실패 회사 건너뛰기
  - 회사별 예외 규칙

## 안정 계약 검사

확인된 중대 회귀이며 외부 데이터 수집 전체를 막으므로 안정적인 상태 계약 검사를 추가한다.

1. `페이지가 만료되었습니다`가 `ExpiredPageError`로 분류된다.
2. 만료 복구가 `Ctrl+Shift+R → 30초 대기 → 화면 복사` 순서를 지킨다.
3. 정상 로그인 레이아웃이면 프리플라이트 없이 홈 초기화한다.
4. 정상 로그인 레이아웃이 아니면 프리플라이트 후 홈 초기화한다.
5. 사전 대기와 홈 초기화 뒤 추가 대기가 남지 않는다.
6. 기존 `[8004]`와 `페이지 만료` 판정은 유지된다.

- 전체 CRETOP 단위 검사와 정적 검사 통과
- 코드리뷰 후 커밋

원격 단계:

- 로컬 리뷰·커밋과 분리

- 공식 12건 배치 경로 실행
- 원격 결과 12건 생성과 `ceo_loan` DB 종결 상태 확인

로컬 검사만으로 실브라우저 복구 성공을 선언하지 않는다.
