# CRETOP 정보제공중지 확인 복구 설계

## 문제

- `정보제공중지 안내` 팝업의 확인 버튼 중앙은 1920×1080 기준 `(960, 694)`이다.
- 기존 공용 좌표 `(967, 620)`은 버튼 위 빈 공간을 눌러 팝업을 닫지 못한다.
- 기존 검증은 팝업 뒤 검색 결과의 공통 상세 마커를 성공으로 오인한다.

## 목표

- 정보제공중지 팝업은 실제 확인 버튼을 누른다.
- 팝업 문구가 사라진 뒤에만 스마트검색으로 복귀한다.
- 재무정보 비공개 팝업과 정상 수집 경로는 그대로 유지한다.

## 설계

1. 정보제공중지 전용 확인 좌표를 둔다.
2. 예외 본문에서 정보제공중지와 재무정보 비공개를 구분한다.
3. 팝업별 좌표와 소멸 확인 문구를 기존 공용 복구 함수에 전달한다.
4. 확인 클릭 뒤 상세 마커가 아니라 팝업 문구의 소멸을 확인한다.
5. 기존 상단 스마트검색 복귀 함수로 다음 기업 준비 상태를 만든다.

## SSP 병합

`collect_batch_fast → _handle_company_exception → company_data_unavailable → _recover_company_failure_to_smart_search → _return_to_smart_search_from_top`

- 새 실행 경로나 별도 예외 처리기를 만들지 않는다.
- 기존 복구 단계 내부의 좌표 선택과 성공 판정만 교체한다.

## 검증 계약

- 정보제공중지: `(960, 694)` 클릭 후 `정보제공중지` 문구가 사라져야 한다.
- 재무정보 비공개: 기존 `(967, 620)` 클릭 후 `공개되지 않습니다` 문구가 사라져야 한다.
- 두 경우 모두 팝업 소멸 뒤 상단 스마트검색 복귀가 실행되어야 한다.
