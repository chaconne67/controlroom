# CRETOP 기업자금 참조자료 정리 문서 설계

## 목적

- 원본 PDF의 회의 요청사항을 업무 담당자와 개발자가 함께 이해할 수 있게 정리한다.
- 원문에 적힌 사실, 문맥상 해석, 구현 규칙, 확인이 필요한 쟁점을 구분한다.
- 원문에 없는 정책이나 계산 규칙을 새로 만들지 않는다.

## 입력과 산출물

- 입력: `cretop/cretop_기업자금_참조자료.pdf`
- 입력: `cretop/경영진단.xlsx`
- 산출물: `cretop/cretop_기업자금_참조자료_정리.md`
- 산출물 언어: 쉬운 한국어
- 주 독자: 기업자금 업무 담당자와 구현 개발자

## 원문 범위

PDF는 다음 세 요청으로 구성된다.

1. 업종과 매출액을 기준으로 대출가능금액 범위를 표시하는 폼
2. 약 14,000개 업체를 추리는 CRETOP 조건
3. 업체 보고서 MMS 이미지에 `자본총계`를 추가하는 매핑

## 문서 구조

### 1. 문서 목적과 출처

- 원본 파일명과 문서 성격을 밝힌다.
- 확정된 정책 문서가 아니라 회의 요청사항을 재구성한 자료임을 표시한다.

### 2. 전체 핵심 요약

- 세 요청을 업무 목표 중심으로 짧게 요약한다.
- 독자가 먼저 결론을 보고 세부 내용으로 내려갈 수 있게 한다.

### 3. 항목별 통합 해설

각 항목은 같은 순서로 구성한다.

1. 원문 요지
2. 쉬운 해석
3. 구현 가능한 규칙
4. 예시
5. 주의사항과 확인 필요 사항

### 4. 개발 요구사항 요약

- 입력값, 계산 규칙, 필터 조건, 출력 문구, 데이터 매핑을 표로 정리한다.
- 구현 전에 업무 담당자에게 확인해야 할 사항을 별도 목록으로 모은다.

### 5. Excel 자동작성 계약

- `경영진단.xlsx`의 핵심 입력 시트는 `Sheet1`로 고정한다.
- 33개 입력 위치마다 셀 주소, 필드 키, 데이터 원천, 단위, 누락 정책을 기록한다.
- 기존 `scripts/cretop_report_pipeline.py`의 `export-report`를 단일 최종 경로로 사용한다.
- `.xlsx` 읽기와 쓰기는 `openpyxl`로 통합한다.
- `K11` 제목은 보존하고 주거래은행 값을 `L11`에 쓴다.
- `D7` 업태에 영업상태를 넣지 않는다.

### 6. 계산과 문구의 책임 분리

- 스크립트는 KSIC 코드 기반 업종군, 자격 조건, 대출가능금액, `D36` 문구를 결정한다.
- LLM은 구조화 사실을 해석해 `D32` 검토의견과 `D35` 최종결과 앞 2줄만 만든다.
- LLM은 스크립트가 전달한 `eligibility.status`를 다시 분류하거나 변경하지 않는다.
- 스크립트는 `D35` 마지막에 변동 가능성 고정 안내를 추가한다.
- LLM은 금액을 계산·수정하거나 기관 승인 결과를 생성하지 않는다.

### 7. 대출가능금액 산식

- 기준 매출은 가장 최근 확정 재무연도 값이다.
- 업종별 비율은 제조업 `1/2`, 도소매업 `1/6`, 그 외 비제조업 `1/4`다.
- 이론 최대 한도는 `1억원 단위 내림`한다.
- 추정 상한은 `max(이론 최대 한도 - 1억원, 1억원)`이다.
- 표시 하한은 `max(추정 상한 - 1억원, 1억원)`이다.
- 제조업 연매출 10억원은 `3억원~4억원`으로 표시한다.

## 해석 원칙

### 사실과 해석 구분

- PDF에 직접 적힌 요구사항은 `원문 기준`으로 표시한다.
- 문맥을 풀어 설명한 내용은 `해석`으로 표시한다.
- 원문끼리 충돌하거나 의미가 불명확하면 하나를 임의 선택하지 않는다.

### 계산 규칙 처리

- 이론 최대 한도는 제조업 `연매출의 1/2`, 도소매업 `1/6`, 그 외 비제조업 `1/4`로 계산한다.
- 추정 상한은 이론 최대 한도에서 `1억원`을 차감하며 최솟값은 `1억원`이다.
- 표시 하한은 추정 상한에서 다시 `1억원`을 차감하며 최솟값은 `1억원`이다.
- 제조업 연매출 10억원은 이론 최대 5억원, 추정 상한 4억원, 표시 하한 3억원으로 계산한다.
- 원문 뒤쪽의 제조업 `매출액의 1/4` 표기는 확정 계산 규칙과 충돌하는 원문상 불일치로 남긴다.
- 부채, 자본금, 기존 대출, 대출 시기, 전년 대비 매출 성장에 따른 조정은 계산식이 없는 보정 요인으로 분류한다.

### 업체 필터 처리

- 휴업·폐업·회생 여부는 포함 조건인지 제외 조건인지 원문상 명확하지 않다고 표시한다.
- 신용등급은 `B+ 이상`을 통과 기준으로 정리한다.
- 제조업·비제조업은 연매출 5억원 이상, 도소매업은 10억원 이상으로 정리한다.
- 부채비율은 업종과 무관하게 350% 이하로 정리한다.
- 원문의 `B°`는 표기 의도를 확정하지 않고 원문 표기를 병기한다.

### MMS 보고서 처리

- 업체 보고서 이미지에 `자본총계` 항목을 추가하는 요청으로 정리한다.
- 첨부이미지가 현재 PDF에 포함되지 않아 위치와 표시 형식은 확인이 필요하다고 밝힌다.

## 오류와 누락 처리

- 읽을 수 없는 문구는 추측해 보완하지 않는다.
- 원문에 없는 수치, 등급, 필터 조합은 추가하지 않는다.
- 구현 전에 결정이 필요한 내용은 문서 마지막의 `확인 필요 사항`에 모은다.
- 주업종 코드·최근 매출·신용등급·부채비율·활성 신용사건 상태가 없으면 Excel을 만들지 않는다.
- LLM 출력 계약 위반은 오류를 포함해 한 번만 재요청하고, 다시 실패하면 Excel을 만들지 않는다.
- 원본 `경영진단.xlsx`를 덮어쓰지 않는다.

## 검증 기준

- PDF의 세 요청이 모두 Markdown 문서에 반영되어야 한다.
- `경영진단.xlsx`의 33개 입력 위치가 모두 문서에 반영되어야 한다.
- 모든 수치와 예시는 원문과 대조되어야 한다.
- 사실, 해석, 불명확한 내용이 섞이지 않아야 한다.
- 원본 PDF의 텍스트와 최종 Markdown을 항목별로 다시 대조한다.
- 제조업 10억원, 도소매업 12억원, 최소 1억원 경계 계산을 직접 확인한다.
- 프롬프트의 LLM 책임과 스크립트 책임이 섞이지 않았는지 확인한다.
- 결과 파일은 Markdown 문법 검사와 Git diff 확인을 거친다.

## 범위 제외

- 대출가능금액 계산 코드 작성
- CRETOP 데이터 조회 또는 필터 실행
- 실제 Excel 생성 스크립트 작성
- `경영진단.xlsx` 원본 수정
- MMS 이미지 제작이나 발송
