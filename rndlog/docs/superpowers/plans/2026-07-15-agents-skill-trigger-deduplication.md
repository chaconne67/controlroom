# AGENTS 스킬 발동 조건 중복 제거 계획

## 목표

`AGENTS.md`에는 RndLog 프로젝트에서만 추가로 필요한 행동 기준만 남기고, 각 스킬의 `description`과 같은 일반 발동 조건은 제거한다.

## 현재 상태와 판단

- `$web-automation`, `$rndnote-design`, `$agent-script-role` 발동 문장은 각 스킬의 `description`과 의미가 같다.
- `$problem-solving` 문장도 기본 발동 조건과 구현만 요청된 경우의 제외 조건은 스킬 `description`과 겹친다.
- 다만 “문제·원인·해결 중 하나라도 확실하지 않으면 사용”은 RndLog가 요구하는 강제 기준이므로 프로젝트 규칙으로 남길 가치가 있다.
- 같은 조건을 두 문서에 유지하면 한쪽만 바뀌어 발동 범위가 어긋날 수 있다.

## 변경 내용

`AGENTS.md` 상단의 스킬 발동 조건 네 문장을 다음 한 문장으로 교체한다.

> 오류·오작동·실패 대응에서 문제·원인·해결 방법 중 하나라도 불확실하면 `$problem-solving` 스킬을 반드시 사용한다.

- 스킬 카탈로그가 제공하는 일반 발동 조건은 각 `SKILL.md`의 `description`을 단일 원천으로 사용한다.
- 각 스킬 본문과 다른 AGENTS 규칙은 변경하지 않는다.

## 변경 범위

- 수정: `/home/work/rndnote/AGENTS.md`
- 추가: 이 계획 문서
- 제외: `/home/chaconne/.codex/skills/*/SKILL.md`, 애플리케이션 코드, 기존 사용자 미커밋 변경

## SSP 병합 위치와 정리 대상

- 이 작업은 애플리케이션 실행 경로를 바꾸지 않아 SSP 하드 게이트 적용 대상이 아니다.
- 에이전트의 작업 진입 시 읽는 `AGENTS.md` 상단 규칙에서 중복된 네 문장을 한 문장으로 통합한다.
- 새 발동 경로나 예외를 추가하지 않으며, 규칙 수를 줄여 지침 엔트로피를 낮춘다.

## 검증 방법

1. `rg`로 AGENTS에 남은 네 스킬 이름과 문장을 확인한다.
2. `git diff --check -- AGENTS.md`로 문서 형식을 확인한다.
3. 커밋 전 staged diff에 이번 변경만 포함됐는지 확인한다.
4. 기존 사용자 미커밋 변경이 unstaged 상태로 그대로 남았는지 확인한다.

## 승인 후 실행

이 문서 승인 즉시 `AGENTS.md`를 수정하고 검증한 뒤, 이번 변경만 별도 커밋한다. 추가 구현 승인이나 문서 승인은 요청하지 않는다.
